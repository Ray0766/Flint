## 决策日志
- **GenerationRecord 字段映射（owner #4「MUST 走 GenerationRecord」）**：实测 `generation_records` 表**无任何外键**（deliverable_id/job_id/retrieval_snapshot_id = 纯 text NOT NULL）→ 构造 Topic 生成记录不违反约束，**未命中 S9-1**（类型够用）。映射：`deliverable_id:=topic_id`（本记录生成的产物即该 Topic）、`retrieval_snapshot_id:=seed_id`（种子/上下文快照）、`job_id:=生成作业 id`（调用方传）、`prompt_version:="topic_gen@1#<hash>"`、`model:=provider 模型 id`、`user_evidence_verdict_optin:=False`、`ledger_version/pricebook_version:=None`、`ts/cost:=调用方传`（无隐藏时钟，第三铁律可复现）。**语义借用已登记 owner 复核**（问题单同名条，deliverable_id 承 topic_id 属预期孤行，owner 若不认可局部改）。
- **接地铁律（S2-2）落为 `_ground_evidences`**：why_now.evidences 逐条只保留 `citation_id ∈ 可引用集合(allowed)` 且 `event_date` 可 `date.fromisoformat` 解析的证据；集合外/坏日期一律丢弃——LLM NEVER 编造出处，无据留白。测试 `cit-FAKE`（集合外）与 `not-a-date`（坏日期）均被丢弃。
- **speculative 由系统据 evidences 判，非 LLM 给**（[C2]）：接地后 evidences 为空 → `speculative=True`。三路验证：LLM 直接给空 / 全部集合外 / 坏日期全丢 → 都归 speculative。NEVER 让 LLM 自报 speculative 充数。
- **embedding 走 `EmbeddingService.embed([one_liner])[0]`（确定性、非 LLM）**：`DeterministicHashBackend(dim=1024)` 同尺 bge-m3；同 one_liner → 同 embedding（content_hash 缓存），测试断言 t1.embedding==t2.embedding。真机走 `SentenceTransformerBackend`（bge-m3）注入。
- **prompt 版本化 topic_gen@1**：`prompts/topic_gen@1.md`（含 {allowed_citations}/{keywords}/{hypothesis}/{context} 占位 + schema 示例花括号）经 `load_prompt(enforce_lock=True)` 装载，`_fill_prompt` 用 `.replace` 逐占位替换（避 `.format` 花括号 KeyError）。`update_lock` 登记 hash `398ab408c41c`（diff 仅一增，verify_lock 空）。
- **本卡范围 = 单个接地 Topic + 记录**；差异约束 [C1]（两维 tag + embedding δ、重生成 ≤3）、5~8 计数、诚实降级归 TS-005。
