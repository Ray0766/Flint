## 3. 这一屏最要紧的一条：「没查过」不是「空图」

`docs/前端功能说明-v2.md#2.16` 写着端点是 `GET/POST /workbenches`【**未建·接口预留**】。
仓里与工作台有关的后端只有 `POST /workbenches/{id}/edges`（GRAPH-07 落盘连线），
**没有任何一条能把一张图读出来**。

同一节还写着「空图 → 引导『从广场拖入第一个热点』」。这两句话合在一起有个陷阱：
**端点没建就把空图引导画出来，等于告诉用户「你的工作台是空的」——而我们不知道。**

所以本屏分三态，源码里就是三条路：

| `graph` | 意思 | 屏上 |
|---|---|---|
| `null` | **没查过**（端点未建） | 「接口未提供」+ 一句说明 |
| `{nodes: []}` | 查过了、确实是空的 | 引导拖入第一个热点 |
| 有节点 | 有图 | 画布 + 生成闸门 |

判据把两种「没有节点」钉成**不同的 `data-workbench-state`**——
不然取证时分不出屏上到底是哪一种。

这是本轮反复出现的同一条（`not_checked` ≠ `checked-empty`）在前端的形态：
后端那边是 BE-03~11 的 `status: not_checked`，这里是 `NotProvided`。

**空图 NEVER 预置示例节点**（v2 原话）：预置的节点与用户自己拖进来的长得一样。

## 5. 只装配，不重写

GRAPH 组 16 卡把节点、连线、角色、多选、生成闸门、拖拽、撤销都做好了，
缺的只是一块把它们摆在一起的画布。所以 `GraphWorkbench` 只做装配：

- 节点用既有 `GraphNode`，生成闸门用既有 `GenerateGate`；
- **不自己算布局**（判据断言没有 `forceLayout`——布局归 `lib/graph-layout`）；
- **不自己排序**（零计算）；
- **不自己挑 primary**（I12-1 恒 ≤1，由后端给；判据断言没有从 `nodes[...]` 里取 primary 的写法）。

**移动端只读（E10）**：只读时增删改控件**不渲染**（`readOnly ? null :`），不是置灰——
与保护块那条纪律同源：置灰的控件仍然告诉用户「这里本来能点」，而在只读端它永远不能点。
判据断言只读时 `button` 数为 0，且节点仍然全在（可看可缩放）。

## 6. 改既有文件：三处

### 6.1 `tools/check_design_constraints.mjs`（AUDIT-02 的尺子，本轮刚 verified）

- **改前**：A6「每屏三态齐全」对 `app/**/page.tsx` **一律**要求 loading/empty/error。
- **改后**：只对**取数屏**要求（源码里有 `fetch(` / `useEffect` / `await` / `Client`）。
- **为什么非改不可**：本屏一个请求都不发（§4），却被这条规则报「缺加载态」。
  硬给它写一个加载态，写出来的是**一段永远进不去的死分支**，
  而死分支会让下一个人以为这屏在取数。
- **强度对比**：改完之后**四条既有真缺口一条不少**
  （`deliverables/[id]`、`deliverables/[id]/export`、`demo`、`jobs/[id]` 全都在取数，
  照旧报红）。规则是**收窄到正确的对象**，不是放过违规。
  A6 的阴性对照同步改成一屏**取数屏**——样例必须落在规则的对象上，否则那条对照是空的。

### 6.2 `harness/fe_smoke.py`（EYE-03 的产物）

- **改前**：`SAMPLE_IDS` 四条动态路由。
- **改后**：**追加**一条 `/workbenches/[id]: "wb-placeholder"`，逻辑一行没动。
- **为什么非改不可**：这份文件自己的注释原话——「新增动态路由却不在这里登记 →
  `discover_screens` 会把它报成 problem，NEVER 跳过」。
- **一处与前四条不同、写在注释里**：这个 id **不是从库里查出来的**
  （`GET /workbenches` 未建、库里也没有 workbenches 表，这一屏不拿 id 去问任何东西）。
  等端点建好、这一屏真去取数那天，**MUST 换成从库里查出来的真 id**，
  否则又会变成「探针给错地址」那种假红。
