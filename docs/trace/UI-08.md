## 2. 三种「没有」互不冒充（本卡的全部重量）

蓝本把 R2 记成 `billing_enabled: false`。这句话有个陷阱：
**它是「查过了、计费没启用」，而本屏此刻是「没查过」**。三者在屏上说三句话：

| 状态 | 屏上 | 为什么不能合并 |
|---|---|---|
| 没查过（端点未装配） | 计费接口未提供 | 说成「未启用」是替后端下结论 |
| 查过了、未启用 | 计费未启用 + 后端给的理由 | —— |
| 未启用时的用量 | 只报已用次数，**不显示任何上限** | `limit: 0` 会被读成「免费额度 0 次」，而真相是还没定价 |

账户屏同一条：档案三态（`not_checked` / `no_record` / `known`）逐字转出。
**在账户屏上这一条格外要紧**——用户会据此去「补全资料」，
而他的资料其实好好地在那儿。

## 3. 金额与余量：前端一处运算都没有

- **金额恒是字符串**，原样渲染。判据用 `"1.250"` 做样例：转成数字会变成 `1.25`，
  而那是钱，一位都不许动。
- **合计用后端算好的那个**。判据用 `0.1 + 0.2` 做样例：前端自己加会得到
  `0.30000000000000004`。
- **余量是后端给的数**。判据故意给一个「不自洽」的组合
  （used 3 / limit 10 / remaining **4**）：若前端自己减会显示 7，
  显示 4 才说明它取的是后端那一个。
- 结构判据：`BillingPanel` 里**没有任何算术运算符**，也没有
  `Number(` / `parseFloat` / `toFixed` / `.reduce(`。
