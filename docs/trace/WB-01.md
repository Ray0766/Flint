## 刻意没照蓝本做的三处（`SHIP-14` 首节要逐条列）

1. **外链字体**：蓝本 `<head>` 引 Google Fonts（IBM Plex Sans）。**NEVER 引**——CI 恒不联网（`S2-7`），且那是一次第三方请求。字体走 `_ds` 已有的 `--font-*`。
2. **颜色**：蓝本自带 `--bg/--panel/--panel2/--ink/--accent` 十几个十六进制。全部落到 `_ds` token（`--bg-page/--surface/--surface-card/--rule/--text-body/--text-meta/--accent-highlight`）。判据扫本段裸色值 = **0**。
3. **窄屏**：蓝本**没有任何响应式**（三栏永远横排）。390 上照抄的话 250+240+文档挤在 390 里，每栏都窄到读不了而**屏上不报错**。改成 <900 纵向排开、整页正常滚动（`100vh + overflow:hidden` 只在宽屏成立）。

## 高度不靠算术，靠 flex 链

蓝本是整页 `height:100vh`。本仓这一屏上面还有固定药丸条与 `__body` 内边距，
照抄会正好高出那一截，而**高出来的那一截在屏上看不见**（表现为「能往下滚一点点」）。
改成 `外壳 100vh → __body → .screen--workbench → .workbench` 逐层 `flex:1; min-block-size:0`，
**一处算术都没有**。

## 三处判据自己是缺陷（当场改的）

1. `chatAtLimit >= 240` 实测 **233**，红。**照蓝本做出来就是 233**：蓝本夹的是 `cardsW ≤ sideW-240`，而那 7px 拖条住在同一个 `sideW` 里。钉**契约的事实**（蓝本夹的是哪个量），不是钉一个看起来一样的数——第 12 批 `GATE1-DEDUP` 栽的正是这一处。
2. CSS 判据先去注释再按 `WB-01` 切段 → `IndexError`：**锚点本身写在注释里**，去完就没了。两步顺序反了，判据把自己要找的路标先擦掉了。
3. 三栏 `overflow-y:auto` 判在**栏上**——蓝本三处 `overflow-y:auto` 全在**栏内**（第 54/116/170 行），栏本身是 flex 列，顶上页签与底下输入框要钉住不滚。改判栏内那一层 + 栏的 `min-height:0`。

## steward 2026-08-12 的两条教训（原话逐字，往后所有视觉判据照办）

### 一 · 「零横向溢出」这条正向判据对 `fixed` / `absolute` 元素**无效**

> 「**『零横向溢出』这条正向判据对 position: fixed 的元素无效**——fixed 溢出不撑
> 文档 scrollWidth，所以它在药丸条身上恒绿。而我自己复核第 13 批时**也只看了
> 1920 两张截图、没看 390**。
>
> 所以这条不算你的漏，是我写的判据漏了一维。往后视觉判据里凡是 fixed / absolute
> 的元素，量法 MUST 是「最右元素右缘 ≤ 视口宽」，NEVER 用文档级的横向溢出去代替。」

**执行位**：`EYE-05` 与此后每一条视觉判据，脱离文档流的元素
（`position: fixed` / `absolute`）逐个量**自己的右缘**，
NEVER 拿 `document.documentElement.scrollWidth` 去代替。
文档级那一条继续留着——它量的是**另一件事**（正常流里的溢出），两条并存，不互相顶替。

### 二 · 读缓存的判据等于没有判据

> 「你把取证缓存改成按输入指纹失效，这一手同样重要——**读缓存的判据等于没有判据**。」

`WB-01` 已经给两处补了指纹（`test_shell_nav.py` 的顶栏取证、
`test_screen_composition.py` 的屏组成取证），且**指纹在拍完之后才盖**——
拍之前盖的话，探针失败会留下一份「指纹对得上而内容是旧的」缓存，比没有缓存更坏。

`.ui-probe/` 下其余各家仍是「文件在就不重跑」，按同一形状补是下一批的活
（记在 `docs/blocked/NAV-BAR-OVERFLOWS-AT-390.md` 末节）。
