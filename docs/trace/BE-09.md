## 2. 两条路，两种身份

| 路 | 身份 | 判据 |
|---|---|---|
| 管理：`POST /shares` · `GET /shares` · `DELETE /shares/{token}` | 要 `X-User-Id`，只看得见自己的 | 变异⑨⑲㉑ |
| 外链：`GET /public/shares/{token}` | **不要身份** | 变异⑳（加上身份要求 → 红 11 个） |

外链就是给没账号的人看的。要身份就等于把「分享」变成「登录后才能看」。
所以这条路上还有三条 NEVER，各有判据：

- **NEVER 回 owner**（变异④）——持链人不该知道这是谁分享的；
- **NEVER 回未分享的兄弟资源**（变异⑤）——判据断言内容源**只被问了这一个 target**；
- **NEVER 接受写操作**（变异⑥⑦）——用既有 `verify_write_forbidden` 回 403，
  且判据另断言写请求**什么都没改**（不然「先撤销再报 403」也能过）。

## 3. 三个状态码分得开（转调既有门禁）

`links.py` 的 docstring 把这条写死了：全报 404 看起来更安全，实际是
把三种处境糊成一句「没有」。本端点原样转出：

| 情形 | 码 | 为什么不是别的 |
|---|---|---|
| token 不存在 | **404** | 「这个 token 存不存在」是唯一真正该藏的东西 |
| 撤销 / 过期 | **410** | 告诉持链人「你没走错，它到期了」——他据此去找人续期 |
| 要口令而没给对 | **401** | 与上面两种分开：过期链接给对口令**也不放行** |
| 只读链接上的写请求 | **403** | 身份没问题，动作不允许 |

变异⑭（自己写一套状态码）红 5 个；变异⑮（把判断顺序反过来：先验口令再验有效期）
红 2 个——反过来会把「已过期」泄露成「口令错」，也让死链接还能被拿来试口令。

## 4. 撤销不是删除

冻结件原话：「过期可续期，撤销不可逆」。所以撤销是**置位 + 留着那行**：

- 删掉的话，持链人拿到 404「没这条」，他会以为自己拿错了链接（变异⑧ 红 2 个）；
- 留着才能回 410。

列表里两者**分开报**，NEVER 合并成一个 bool（变异⑫）；
没有到期日时报 `null`（= 不过期，冻结件语义），**NEVER 编一个**（变异⑬）。

## 5. token 与口令

- token 由服务端 `secrets.token_urlsafe(32)` 生成。判据三层：两次必不同、
  长度 ≥32、模块里**有 `secrets` 且没有 `random`**（变异①② 各钉一层）。
- 客户端**递不进来** token（`extra="forbid"`，变异③）——
  递得进来就等于让调用方自己挑一条别人猜得到的链接。
- 口令只以 hash 存在（变异⑩ 明文落库 → 红），创建响应里既不回明文也不回 hash
  （变异⑪㉒）。

## 6. 变异考逼出来的一条：**声明**本身就是风险

二十二个变异体里 **⑯ 活了下来**：加一个 `password: str | None = None` 查询串参数
但**不接线**。行为一个字没变，判据全绿。

它不是假变异——`or` 空转那种是行为不变且**无害**；这一个行为不变但**已经把口令
入口写进了 OpenAPI**，下一个人照着填上就把口令送进了访问日志与 Referer。

判据因此改判在**函数签名**上：`public_read` 的参数里除路径与 `Request` 外，
每一个都得是 `Header(...)`。⑯ 与 ⑯′（真接线那版）双双当场红。

**「行为没变」不等于「没变坏」**——这是本轮变异考里第一次遇到这种。

## 7. 一处判据误伤（自己抓自己）

第一版写-SQL 检测器扫的是裸动词 `\bDELETE\b`——而本模块的路由方法表里
就有 `"DELETE"` 这个字符串，它是 **HTTP 方法名**。判据当场红，红得没道理。

改成带 SQL 上下文的模式（`DELETE\s+FROM` 这类），并补一层更硬的：
**模块里没有 asyncpg / sqlalchemy / psycopg**——够不着数据库就写不进去。

一把会误伤的尺子，用不了几天就没人再看它。

## 10. 登记未做

1. **没挂进任何 ASGI 应用**。BE-01~09 九张卡同一件待办。
2. **`ShareLinkStore` 是本模块内的内存实现**。冻结件 `ShareLink` 有类型、
   但仓里**没有任何 share 存储层**（`flint/share/` 只有门禁逻辑）——
   所以座子建在本模块里，SQL 实现随 E2 接入。
   **本模块的 `ShareLink` 是 dataclass 影子**（字段逐字对齐冻结件），
   真接线时应换成冻结件那个类型本身。
3. **`load_content` 没有真实实现**。三种 target（deliverable / graph / topic）
   各有各的取法，且**取出来的内容还要过一遍导出门禁**
   （`flint/render/gatekeeper.py`：被阻断的块不该经外链流出去）——
   那是另一张卡，本卡的 loader 是注入点。**这一条最要紧**，
   因为外链是唯一不需要身份的路。
4. **口令盐是固定的**（`links.py` 自己写着「生产实现应换成 per-link 随机盐 + argon2」）。
   本卡不动那一处：改它属 K 组选型 + 全仓迁移。
5. **没有枚举防护/限流**。`links.py` 原话「枚举防护属路由层，本模块不涉及」——
   本卡也不涉及：限流要在网关或中间件上做，属部署面。已登记。
6. **`share_with_friend`（好友定向分享）post-v1**，冻结件里抛
   `NotImplementedError`，本卡不碰。
