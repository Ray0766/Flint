## 撞上的经过（可复现）

DEF-03 做变异考时，脚本按惯例「读全文 → 改一处 → 跑 → 写回原文」。
`Path.write_text()` 在 Windows 上**默认做换行翻译**：读进来的 `\n` 写回去变成 `\r\n`。
文件内容逐字未变，行尾全变了。

随后全量 `npm test` 跑出 2 failed，两条都是同一句断言：

```
FAIL components/graph-edge/GraphEdge.test.tsx > 文案 key 化：源码代码行零 CJK
AssertionError: expected '// GRAPH-07：连线草稿 + 强制假设（F7/F8，前端这一半）。…' not to match /[一-鿿]/
```

报出来的 `code` 是**未经剥离的全文**——剥注释那一步一个字都没剥掉。

## 为什么会这样（根因是 JS 正则的行终止符定义）

那些尺子的剥刀是同一份（`web/test-utils/source.ts#codeOnly`，与 `tools/i18n_scan.mjs` 对齐）：

```js
source.split("\n").map((line) => line.replace(/\/\/.*$/, "")).join("\n")
```

CRLF 之下，`split("\n")` 切出来的每行**末尾还挂着一个 `\r`**。
而在 JS 正则里 **`\r` 是行终止符**，`.` 不匹配它；`$`（无 `m` 标志）要求匹配到字符串末尾。
于是 `//.*$` 在 `\r` 前就走不下去，**整行注释一条都剥不掉**。

Python 侧同款剥刀不受影响（`.` 同样不匹配 `\r`，但 `re.sub(r"//.*$", "", line)`
配 `$` 在 Python 里可以匹配到末尾换行前的位置）——**两侧行为不一致，正是难查的地方**。

## 为什么值得单独立一条

1. **失效是全局的、静默的**：受影响的不是一条断言，而是**所有**「源码里不该出现 X」
   的尺子（`codeOnly` 是前后踩了六次同一个坑之后才抽出来的共享件，用它的地方很多）。
2. **这次的方向是幸运的**：CJK 那条要的是「剥完之后没有中文」，剥不掉 → 红。
   但同一条缝在「剥完之后**必须**出现 X」这类判据上会给出**绿**——
   注释里随便提一句就够了。本仓两类判据都有。
3. **触发条件是日常操作**：任何用 Python 文本模式写文件的脚本（变异考、批量改写、
   代码生成）都会在 Windows 上把一个文件 CRLF 化，而**内容 diff 是空的**，
   人眼复查看不出来。本仓不是 git 仓库，也没有 `.gitattributes` 兜底。

## 建议的修法（两条，成本都很低）

1. **一把换行符尺子**：扫 `flint/` `tests/` `web/`（除 `node_modules` / `.next`）
   的源码文件，出现 `\r\n` 即红并点名文件。接进全局门。
   —— 它同时挡住「内容对但行尾错」这类看不见的污染。
2. **剥刀本身对 CRLF 免疫**：`codeOnly` 里先 `replace(/\r\n?/g, "\n")` 再剥。
   建议**两条都做**：改剥刀是治标（别处还有各自写的剥法），尺子是治本。
