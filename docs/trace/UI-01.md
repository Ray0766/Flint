## 4. 三处 NEVER 照搬蓝本（acceptance②）

1. **账户位里的 `X-User-Id: self` 不上产品面**。蓝本顶栏把它印出来，
   而 FB-10 的尺子把 `X-User-Id` **逐字列进「A 类脚手架」命中组**。
   照搬会让一把已 verified 的尺子当场变红；更要紧的是用户看着一行 HTTP 头，
   会以为这产品还没做完。换成诚实态：`账户` + 「接口未提供」标
   （蓝本自己也挂着「账户端点未建 · §3.9」，说的是同一件事）。
2. **大类筛选条不做**。蓝本 S0 带一条 `GET /categories` 的筛选条。端点**是有的**，
   但本仓现在没有广场屏可筛——筛不到东西的筛选条就是 A 类脚手架。它跟广场屏一起来。
3. **wordmark 不是链接**。蓝本点 wordmark 回首页，而本仓 `/` 路由不存在（实测 404）。
   点了掉进 404 的入口比没有入口更坏：它把「还没做」伪装成「做完了」。

**导航里只列真实可达的无参路由**：`web/app/` 现有三个屏，两个要 id
（没有 id 时链不过去），所以导航只有 `/demo` 一条。判据
`test_the_shell_never_links_to_a_route_that_does_not_exist` 逐条查每个 href
在盘上有对应 `page.tsx` 且不带 `[`。

## 6. 两个坑，都是实测撞出来的

### 6.1 vitest 文件 NEVER 放进 `web/app/`

第一版把 `shell.test.tsx` / `screens.test.tsx` 直接放在 `web/app/` 下（为了让
`--run app` 这个过滤器匹配得到）。`app/` 是 Next 的**路由树**，往里塞测试文件
等于把 vitest 与 testing-library 挂进应用的模块图。改放
`web/__tests__/app/`——路径里照样有 `app` 三个字母，过滤器匹配得到，
而路由树是干净的。

### 6.2 `use(params)` 会挂起，不包 Suspense 首帧什么都没有

`/jobs/[id]` 用 `use(params)` 解 Promise。测试里直接 `render(<JobPage …/>)`
拿到的是一个空 `<div/>`：组件挂起了，断言读到 `undefined`——
**而那与「属性被删了」长得一模一样**。改成 `await act(async () => render(<Suspense>…))`
再 `waitFor`。这条写进了测试里的注释，否则下一个人会以为那层 `act` 是多余的。

### 7.1 取证过程中修好的两件事（都不是产品代码）

1. **Next 开发服务器的渲染 worker 崩了**。第一轮取证 dark 全 200，light 两屏
   HTTP 500，报 `Jest worker encountered 2 child process exceptions, exceeding retry limit`
   ——这是 Next dev 的已知失败，崩掉之后**不会自愈**，重启才好。
   实测：重启后 `/jobs/[id]` 恢复 200。**产品代码零改动**。

   `docs/blocked/FE-DEMO-ENV-FLINT-API-BASE.md`，**本批不处理**。
   带 `FLINT_API_BASE=http://localhost:8000` 重起 dev 之后 200。
   **改的是起栈方式，不是代码**——那张单一个字没动。

后端 :8000 本轮是我起的（`harness.demo_server`，DSN 指本机 55432）；
postgres 与前端 :3000 本机在跑。**全程只读页面**，沿用 ui_probe 的边界。
