| `web/lib/derefClient.test.ts` + `web/components/deref/DerefValue.test.tsx` | verify_cmd 所指（15 条） |

**唯一的产品规则**（acceptance②）：端点不可用时**如实标「接口未提供」并把原 id 留在屏上**。

- **NEVER 空白**——空白读起来是「这里本来就没东西」，而真相是「这里有东西但没取到」；
- **NEVER 编造**——编出来的内容没有出处，而第一条铁律是「结论必有引用」。
  落地形式：`unavailable` 的结果里**没有 `data` 字段**，调用方拿不到一个「看起来像内容」的东西；
- **loading 也不空白**——先显示原 id，读者至少看得到「这里引的是哪一条」。

acceptance③ 的分界落在 `data-*`：管道细节（`GET /facts/…`、HTTP 状态码）**移出产品面**，
但留在 `data-deref-*` 上供取证与调试（EYE-01 的 `--selector`、既有 BlockView 测试都靠它定位）。
**产品面移走 ≠ 全仓删掉**——`test_the_dev_facing_data_attributes_survive` 守着这一半。

## 4. 真页面抓出了单测抓不到的东西（本卡最值得记的一段）

首版把「每条通道怎么显示」做成 `render` **函数 prop**，由 `BlockView` 传进来。
**15 条 vitest 全绿**，然后真页面当场 **500**：

```
pageerror: Functions cannot be passed directly to Client Components unless you
explicitly expose it by marking it with "use server".
```

`BlockView` 由 Server Component 渲染，而 `DerefValue` 是 Client Component——
**函数不能跨这条边界传**。而 **vitest 里一切都在客户端，那条边界根本不存在**，
所以单测永远看不见这个错。

改法不是给 BlockView 加 `"use client"`（那会改掉 L0 只读渲染器的渲染模型），
而是**把 props 收窄成全部可序列化**：`kind` + `id` + `quantity`，
「怎么显示」按 kind 写在 `DerefValue` 内部的 `present()` 里。
边界问题从根上没有了，而且格式化逻辑集中到一处。

复跑：真页面 **500 → 200**，vitest 543 passed。
测试同步改掉（去掉 `render` prop），并在文件头写明这条边界与为什么单测看不见它。

## 6. 挂载（改既有文件之一）

**改前**：`harness/demo_server.py` 挂了 views/combo/analysis/deliverables/categories/interventions 六个 app。
**改后**：加挂 `create_deref_app(DerefApiDeps(dsn=DSN))`。
**为什么非改不可**：不挂的话六处全显示「接口未提供」——那是诚实的，但 acceptance①
说的是「**改为显示解引用后的内容**」，没挂就等于没做到。
端点只读（FB-04~08 各配了写库语句检测器），挂上不改任何既有端点的响应形状。

挂载生效的验证方式：`GET /facts/x` 回 `{"code":"NOT_FOUND","message":"no such fact"}`，
而未注册路由回 FastAPI 默认的 `{"detail":"Not Found"}`——**两者可区分**，
否则「挂上了但没数据」与「根本没挂」长得一模一样。

## 9.5 顺手修的既有文件：我自己在 GAUGE-04 埋的假红

全局门跑出 **2 failed**，都在 `tests/v041/test_vitest_filters.py`（GAUGE-04 的产物）：

```
assert [22, 0] == [21, 0]
过滤器 'components'：校验器数出 22，真 vitest 是 21
```

根因是**我在 GAUGE-04 里把会动的数字钉死了**：那两条断言写的是 2026-08-04 当天
对着真 vitest 量到的绝对值（`components → 21 文件`、全量 58 个文件）。
本卡加了两个测试文件（`derefClient.test.ts` / `DerefValue.test.tsx`），
`components` 从 21 变成 22 —— **语义一点没坏，坏的是那个设计**。

**这是一条假红**：它没有发现任何缺陷，只是在惩罚「有人加了测试」。
而假红比没有断言更糟——下一个人看到它红，第一反应是把数字改大，
改着改着这条断言就只剩一个仪式。

改法：断言改成「**校验器数出来的 == 按同一规则从磁盘数出来的**」（`_disk_count`），
把「与真 vitest 那次一致」作为**标定记录**留在常量上方的注释里。
标定确立的是**匹配语义**（过滤器 = 相对 web/ 路径的子串），语义不随文件增减而变；
绝对值随时会变，所以它不该出现在断言里。

| 文件 | 改前 | 改后 | 为什么非改不可 |
|---|---|---|---|
| `tests/v041/test_vitest_filters.py` | `VITEST_TRUTH` 四个绝对值 + `ALL_TEST_FILES = 58` | `FILTER_SHAPES` + `_disk_count()` 现算 | 不改则全局门对所有人恒红，而红的原因是「有人加了测试文件」 |
