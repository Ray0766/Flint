## 2. `billing_enabled` 不是写死的 false，是配置算出来的

蓝本 R2 行写的是占位屏 `billing_enabled: false`。本卡把它接成真的：
`BillingConfig.configured` 的口径原样沿用——**四项任缺其一都算未配置**
（判据 `test_a_half_configured_price_is_not_enabled`）。

未启用时本端点**连键都不给**：

| NEVER 给的键 | 给了会怎样 |
|---|---|
| `limit` / `remaining` / `exhausted` | 前端显示「免费额度 0 次」，而真相是还没定价 |
| `currency` / `pricing_version` | 等于说「已经在按这个币种收钱了」 |

acceptance② 原话「NEVER 返回 0 元或假额度冒充已启用」。变异②③ 分别钉这两头。

**但计数照报**：运行次数一直在数（它不需要定价），所以未启用时如实给 `used`、
不给上限。这是「已用量明细」在未定价阶段唯一能诚实说出的部分。

## 3. 额度转调既有闸门——判据钉的是「阈值比较本身」

`check_quota` 就是提交前那道门用的函数。端点里再写一遍阈值，就会出现
**横幅说「还有额度」而提交被拦**（BE-04 同一条纪律）。

第一版判据写的是「模块里不许出现 `<`」。这条不够硬：换个方向写成
`used >= limit` 一样是第二个真相，而且它**多半是对的**——于是更难被发现。
判据改判在 AST 上：任何拿 `used` / `limit` / `free_quota` / `remaining` /
`shortfall` 做大小比较的表达式，一处都不许有。

补的变异㉓（写一个**行为完全正确**的重复实现）当场红——
这正是行为测试抓不住、只有结构判据能抓的那一类。

余量与是否超额**都由后端给**（蓝本铁律：前端零计算），且两者同源。
`test_remaining_zero_and_exhausted_never_disagree` 跑 0~13 全区间断言
`remaining == 0` ⟺ `exhausted`，变异⑦（余量允许为负）当场红。

## 4. 钱恒是字符串，且本模块一处乘除都没有

`Decimal` 走 JSON 浮点，0.1 + 0.2 会变成 0.30000000000000004——而这是钱。
判据递归扫全响应：**一个 float 都不许有**（变异⑪⑫ 各钉一处）。

acceptance③「金额恒服务端算」在本模块的形态是**算在别处**：
`meter.price_usage` 负责算，这里只转述。判据断言模块里没有任何乘除
BinOp、且不引用 `price_usage`（变异⑲ 钉住）。

对账口径与 `BillingLedger.reconcile` 逐字同形：条数 + 合计 + 币种集合 +
版本集合 + **混用标记**。两个口径的钱加在一起那个和没有意义，所以混用 MUST 报出来（变异⑬）。

## 5. 用量明细：冻结件里没有，所以只能经注入

acceptance③ 要求「每条计费事件带作业 id、**用量明细**、口径版本」。
冻结件 `BillingEvent` 有七个字段——owner / job_id / tier / at / amount /
currency / pricing_version——**没有用量字段**。用量在 `meter.Charge` 上，
而 `Charge` 当前不落库（PAY-02 已登记）。

所以用量经注入取，三态照旧：没注入 `not_checked`、串了行 `no_record`、
查到 `known`。**NEVER 编一组 token 数**（变异⑯ 钉住）——编出来的 token 数
会让对账得出一个查不出错的错数。

这是「登记未做时留一条接线缝」的标准形态：`UsageLoader` 就是那条缝。

## 6. 两处「再滤一遍」（BE-05 那条纪律照用）

数据源若按 org 查、按 owner 查，会捞到别人的行：

- **账目按 owner 再滤一遍**（变异⑭）
- **用量按 job_id 再滤一遍**（变异⑮）——把别的作业的 token 数贴在这一笔账上，
  对账时得出的错数查不出错在哪。

多租户隔离 NEVER 只靠调用方查对了。

## 10. 登记未做

1. **没挂进任何 ASGI 应用**。BE-01~06 六张卡同一件待办。
2. **三个数据源都没有真实实现**：
   - `count_used` 要数「该 owner 已发起的计费档作业次数」——口径（按作业？按成功作业？
     按自然月？）**卡面与 SHIP-01 都没写**，属定价口径（K7/K8 未定），已在 PAY-02 登记；
   - `load_events` 要读 SQL 版账本（`BillingLedger` 当前是内存实现，`ledger.py`
     自己写着「SQL 实现随 E2 接入」）；
   - `load_usage` 要读落库的 `Charge`——**而 `Charge` 当前不落库**（§5）。
3. **免费额度的重置周期没有**。`BillingConfig.free_quota` 是一个上限数，
   没有「每月重置」这回事——真要按月，得先有口径与一张计数表。
   本端点如实转述当前计数，NEVER 自己造一个周期。
4. **不提供任何支付动作**。S2-10 红线：付费网关开通与真实商户密钥属人审节点。
   R2 屏若要「去支付」按钮，那是另一张卡 + owner 批准。
5. **`fx` 汇率不显示**。`Charge` 有结算价/显示价/汇率三样，但 `BillingEvent`
   只落了一个金额与币种——账本里没有汇率，这里就不报汇率。
   跨币种对账要先扩账本字段（冻结件改动，走 owner 变更通道）。
