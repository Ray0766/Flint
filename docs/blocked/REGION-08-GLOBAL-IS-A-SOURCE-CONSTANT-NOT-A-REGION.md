# `global` 不是一个区，它是 `ghtrend` 写死的常量——而它现在与 `CN` 同住一列

**状态** closed（owner 2026-08-08 裁决 `DEC-040`，由 `REGION-11` 执行）

## owner 的答复：归入显式的「未归区」

本单问的是一句话——**`global` 算不算一个区**。答复是**都不算，也不让它消失**：

> `global` 与 `NULL` **一起归入一个显式的「未归区」选项**。

两条错法各自的样子（`DEC-040` 原文）：

- 把 `global` 当第九区 → 用户在**地理列表**里选到一个不存在的地方；
- 让它从筛选面消失 → 那 104 条只在「不筛」时出现，**一旦开始筛就蒸发**。

**「未归区」是唯一诚实的说法**：它承认这些簇存在、也承认我们不知道它们的产地。

### 合并只发生在呈现层——库里两者恒可分辨

**NEVER 把 `NULL` 回填成 `global`**。那会抹掉「这条簇从来没归过区」这个事实，
**而抹掉之后，抹掉本身也看不见了**：回填过的行与本来就是 `global` 的行长得一模一样。

`REGION-11` 交付：

| 产出 | 是什么 |
|---|---|
| `flint/api/views.py#UNASSIGNED_REGION` | 筛选记号 `unassigned`（九个地区码全是两位大写字母，撞不上） |
| `flint/api/views.py#SOURCE_CONSTANT_REGIONS` | 落在 region 列里、但不是地理事实的那些值（今天只有 `global`） |
| `web/lib/regions.ts` | 前端同一个记号 + `withUnassigned` + `regionOptionLabel` |
| `tests/v041/test_unassigned_region.py` | 15 条判据，含**闭合**判据：九区之和加未归区 == 全量，且选项之间互不重叠 |

**`global` 本身仍然选不了**（选它照旧 400）——这不是遗漏，是本单的立场：
`global` 不是一个地方。用户选的是「未归区」，一个承认「我们不知道产地」的选项。

## 一、那一条撞车的簇，逐行摆出来

`c-20260629-108`（`canonical_name` = `brain-computer interface`）的成员：

```
day 2026-06-29 … 07-05   gtrends   脑机接口   region=CN
day 2026-06-30 … 07-05   ghtrend   bci        region=global
```

两条原始词经 `assets/term-map.yaml` 归到**同一个规范词** `brain-computer interface`。
**那是词表在正常工作**——跨源跨语言对上同一个概念，正是 `cross_count` /
`multi_boost` 在奖励的事。

所以这不是「US 与 JP 的报道被 embedding 合成一簇」那种破法。

## 二、真正的问题：一列里装着两种意思

四个源给 region 的方式**不是一回事**（实查代码）：

| 源 | region 从哪来 | 它是什么意思 |
|---|---|---|
| `weibo` | `flint/sources/weibo.py:54` **写死 `"CN"`** | 这个源只看中国区 |
| `gtrends` | `gtrends.py:120` `self._region`（**按区取**） | 这条真的来自那个区 |
| `arxiv` | `arxiv.py:57` 由调用方给 | 视配置而定 |
| `ghtrend` | `ghtrend.py:130` **写死 `"global"`** | **这个源不分区** |

也就是说 `region` 这一列今天同时装着两种断言：

- `CN` = **这条来自中国区**（一个地理事实）；
- `global` = **这个源没有区可言**（一个「不适用」标记）。

**两者不是同一类东西，却在同一列里按同一种规则参与比较。** 于是：

1. 那一条撞车，撞的其实是「有区」与「不适用」，不是「CN」与「US」；
2. 回填出来的 103 条 `global` 簇，说的是「这些簇只来自不分区的源」——
   而广场上 `region=global` 会被读成「全球热点」，**那是另一句话**；
3. 反过来，一个真正的全球热点如果同时被 weibo 和 ghtrend 抓到，
   它会因为「跨区」而**判不出区**——正是这一条的下场。

## 三、这件事为什么必须 owner 裁

`REGION-09` 要让 `GET /plaza/hot?region=` 真筛。**现在就能筛**——
库里 89 条 `CN`、103 条 `global`、1 条 `NULL`，切换是有效果的。

但「有效果」不等于「说的是实话」。用户在广场上选「全球」，
拿到的会是**只来自 GitHub Trending 的那 103 条**，而不是全球热点。
`DEC-035` 那句话在这里换了个形状：**一个筛得出东西但筛的不是那件事的筛选器，
比不筛更坏**——它有结果，所以没人会怀疑它。
