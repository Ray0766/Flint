# TITLE-01 · trace

**卡**：②标题做大——屏头标题与品牌字号分级。
**结果**：verified · 1 cycle · 判据 8 条全绿。

## 实况

改前实测：`h1.screen__title` = `--fs-31`（**31px**）、
`.app-shell__wordmark` = `--fs-20`（**20px**），
**而且 1920 与 390 上一样大**——大屏上小得像个小标签，小屏上又挤。

owner 那句「标题做大」说的是大屏上那一眼；而「到处都塞一个 48px」
会在 390 上把标题挤成三行——所以要的是**分级**，不是单纯放大。

## 改法

两档写进 `_ds` 的排版 token（acceptance③ 逐字），用 `clamp` 随视口缩放：

```css
--text-screen-title: clamp(24px, 2.6vw, 48px);
--text-wordmark:     clamp(20px, 1.6vw, 30px);
```

下界照卡面（24 / 20），上界照蓝本主标那一档（蓝本 h1 是 56px；
本仓屏头上方还压着一条浮动药丸条，48 更稳）。

**NEVER 在组件里写死 px**——写死之后下一次调档没人找得到它。
判据剥掉块注释后扫那两条规则：MUST 用新档、NEVER 有 `font-size: NNpx`。

## 实测

```
1920: 标题 48px    · 品牌 30px
1440: 标题 37.44px · 品牌 23.04px
 390: 标题 24px    · 品牌 20px
```

四条阈值（40 / 28 / 24 / 20）全过，且**分级是真的**：1920 > 1440 > 390。

> 那一条「逐级变小」的判据值得单列：改前三个视口是同一个数，
> 而一条「≥40px」的判据在**恒 48px** 的实现上也会绿——
> 那个实现在手机上会挤爆。

## 两条守着没退的

- 标题仍是 `h1`（换成一个大 div 的话字号判据照样绿，而读屏失去这一屏的标题）；
- 标题仍走显示体 `--font-display`（字号变大，不换字）。
