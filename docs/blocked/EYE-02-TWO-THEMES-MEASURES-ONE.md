## 实测到的事

K6-01 用 `tools/visual_assert.py#check_fragment` 量入口按钮，两个主题量出**同一组数**：

```
dark : color rgb(27,42,46)  background rgb(247,248,243)  96×29
light: color rgb(27,42,46)  background rgb(247,248,243)  96×29
```

一位都不差。查了 `web/public/_ds/*/styles.css` 与 `tokens/*.css`：
**没有 `prefers-color-scheme`，也没有 `data-theme`**——这套设计系统只有一块调色板。

而 `_playwright_measurer` 切主题的方式是 `new_context(color_scheme=theme)`，
也就是设 `prefers-color-scheme`。没有任何规则响应它，于是两次测量必然相同。

## 为什么这值得立一张卡

EYE-02 的判据写的是「明暗两主题下均满足」。对**任何由 `_ds` 上色的元素**，
这句话现在的实际含义是「同一组颜色被判了两遍」。它**不会误判**（两次都对），
但也**证不到**它字面上声称的那件事：换主题之后仍然看得见。

危险在于读的人会以为这条已经验过了。等 `_ds` 哪天真出了暗色板，
第一次暗色回归失败才会有人发现这条判据此前一直在空转。

## 三条路（要 owner 选）

1. **`_ds` 出暗色板**：由设计系统那边加 `prefers-color-scheme: dark` 的一组 token。
   这条最正，但属供应商资产的改动面（终检 C6 的口径：`_ds` 是导出物）。
2. **EYE-02 明说射程**：在 `visual_assert.py` 与 EYE-02 的 trace 里写清
   「本判据只在被测元素自身响应主题时才有区分力」，并加一条自检——
   两个主题量出完全相同的观测值时**报告里标一句**（不判红，因为那不是错）。
3. **单主题验收 + 一张欠条**：现在只声称「在现行调色板下可见」，
   把暗色板留成上线前待办。

**本卡（K6-01）选的是照实记录**：判据照跑（两个主题都过），
但**不在 trace 里宣称「暗色下也验过了」**——因为没验过。

## 顺带记一条对照的形状

K6-01 的阴性对照**不能照抄 FB-02**：FB-02 守的是空 span（没规则就 0×0，直接红），
本卡守的是带文字的 button（浏览器给默认样式，抽掉规则照样可见，实测
`unstyled.ok=True`）。照抄会得到一条**永远绿的阴性对照**——那比没有对照更糟，
它看起来像验过了。本卡改钉在「可点区域高度 ≥ 24px」上（抽掉规则实测 23px）。
