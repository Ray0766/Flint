# ONE-UNNAMED-FRONTEND-RED-NOT-CAPTURED · 一次前端红，名字没抓到

**状态** open

**发现者** worker / `FIX-05` 收卡前跑全局门 · **发现时间** 2026-08-06
**危害** 未知 —— **因为不知道红的是哪一条**
**为什么登记**：`FIX-04` 刚把一处间歇红定位并修掉，同一天又观测到一次红。
不登记的话，它就变成一次「重跑一遍就好」——而那正是 `FIX-04` 要治的病。

## 我知道的

```
 Test Files  1 failed | 73 passed (74)
      Tests  （这一行没抓到）
⎯⎯⎯⎯⎯⎯⎯ Failed Tests 1 ⎯⎯⎯⎯⎯⎯⎯
```

一次 `npm test -- --run`，1 个文件失败。**当时的命令只 grep 了汇总行，
把用例名过滤掉了**——这是我的操作失误，不是工具的问题。

## 我不知道的

- **哪个文件、哪条用例**；
- 它与 `FIX-04` 修掉的那处（`ui07` 的两拍竞态）是不是同一处；
- 它与当时的环境有没有关系：那一跑之前刚做完 `FIX-05` 的变异考，
  期间 `web/app/globals.css` 被反复改写、Next dev server 一直在监听那个文件。
  vitest 配了 `css: false`，理论上不读它——**但「理论上」不是证据**。

## 之后的观测

同一份代码连跑 **6 次全绿**（`754 passed` × 6）；
`FIX-04` 收卡时另有修前 10 次、修后 10 次全绿。

**这些绿不能证明它不存在**——`FIX-04` 那处也是 5 次里才红 1 次，
而它是真的（40 次循环里第 29 次复现）。

## 给下一个人：怎么抓住它

跑连跑时**把失败用例名留下来**，别只留汇总行：

```bash
for i in $(seq 1 30); do
  npm test -- --run --reporter=verbose > "/tmp/run-$i.log" 2>&1 || \
    echo "第 $i 次红：$(grep -E '^ +× ' "/tmp/run-$i.log" | head -3)"
done
```

抓到名字之后，照 `FIX-04` 的路子走：**先把它逼成稳定红，再动手改**
（`docs/trace/FIX-04.md` §6：造不出稳定红时诚实的说法是「没定位到」，
NEVER 是「修好了」）。

## 本卡怎么处置的

`FIX-05` 的验收面是 390px 横向溢出，与前端单测无关，所以**没有停下**；
但也 NEVER 把这次观测吞掉——它记在这里，并写进 `docs/trace/FIX-05.md` §未做
与 `docs/trace/FIX-04.md` §未做。

## `FIX-08` 的观测（2026-08-08）· **单据保留开着**

按本单「给下一个人：怎么抓住它」那一节的办法，连跑 **30 次**，
并把失败用例名留下来（工具已固化为 `web/scripts/repeat-tests.mjs`）。

```

每跑 Tests 802 passed (802)     ← 逐跑记下的汇总行，与用例名互为佐证
产物 .ui-probe/frontend-red.json（逐跑一条：退出码 / 失败用例名 / 汇总行 / 耗时）
```

**30 次未复现。** 本单 **NEVER 关单**，理由逐条：

1. `FIX-04` 那处间歇红是 **40 次里第 29 次**才复现的（`docs/trace/FIX-04.md` 逐字记着）
   ——30 次全绿**不能证明它不存在**，只能证明它不常见；
2. 那一次红发生在 `FIX-05` 的变异考期间：`web/app/globals.css` 被反复改写、
   Next dev server 一直在监听那个文件。**这一轮没有复现那个环境**，
   所以这 30 次绿甚至没有覆盖当时的条件；
3. 本批把 `globals.css` 又改了七次（DS-02 / PLAZA-01 / PLAZA-03 / PLAZA-04 /
   DESIGN-02 / CHAIN-03 / CHAIN-04 / CHAIN-05），期间跑过十几轮 `npm test -- --run`，
   **一次红都没有**——这是新的旁证，但同样不是证明。

## 现场从此不会再丢

`web/scripts/repeat-tests.mjs`：连跑 N 次，**每一次红都记下用例名**
（行内 `× 用例名` 与汇总段 `FAIL 文件 > 用例` 两种形状都抓）。
判据 `tests/v041/test_frontend_red_capture.py` 里有一条**阴性对照**：
喂一段真实形状的 vitest 输出，它必须抽得出用例名——
没有那一条，「30 次全绿」可能只是因为脚本根本不会抓名字，
**而那正是这张单子的由来**。

脚本**恒退出 0**：它是取证工具，不是判据。取证工具自己判红的话，
「没复现」与「工具挂了」会长得一样。
