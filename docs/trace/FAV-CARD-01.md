# FAV-CARD-01 · trace

**卡**：收藏图书馆用与广场同样的卡片呈现。
**结果**：verified · 1 cycle · 判据 42 条全绿 · 六张截图全过。

## 一处要先说清的实况差

owner 说「`FAV-SNAPSHOT` 已经让 `evidence_snapshot` 存了真内容——数据早就有了」。
**一半对**，实查：

| 快照里有的 | 快照里**没有**的 |
|---|---|
| 证据卡：`card_id` / `keyword_ids` / `flags` / `top_links`（含真微博链接） | **卡面**：标题 / 首见日 / 地区 / 热度 |

也就是说**证据在，而「这条热点长什么样」不在**——
所以光改这一屏是渲染不出卡的，标题那一格没有来源。

## 改了三处

1. **后端**（`flint/fav/snapshot_source.py#_cluster_face`）：
   取证时把卡面与证据**一起存下**。
   NEVER 让收藏屏实时查簇——那样一条被清掉的热点会让收藏变成空壳，
   而内嵌基线（`DEC-055`）的全部意义就是不让它变成壳。
2. **「更新到最新」也走自取路**（`fresh_snapshot` 改成可选）：
   必填的话，那个按钮就要前端自己拼一份快照，
   而那正是 `DEC-055` 明禁的事。三条旧收藏按这条路刷了一遍，
   全部拿到真卡面（蔡磊… / 贾冰… / 钟楚曦…）。
3. **前端**：收藏项渲染广场那个 `HotspotCard`，
   **`HotspotCard.tsx` 一个字没改**——它的文件头早写好了这一天的恢复条件：
   「或 `favorites` 落库后在收藏屏上说『你收藏的那份快照旧了』——
   让那一处的产出方开始传 `stale`……**改那一处即可，本文件不用动**」。
   本卡就是那一处。

## 我碰坏了别人的东西，八条判据当场抓住

第一版把 `favorites__stale` 那一格**换成了**卡上的 `stale` 槽——
`UI-05` 那一族八条红。

它判的是三件事：三种陈旧文案 · 三种机器可读记号（`data-favorite-stale`）·
按 `targetId` 认得出是哪一条（那一族判「顺序照后端给的来，不排序」）。

> **它们守的口径一个字没变，是我把承载它们的那一格拿走了。**

处置不是改判据，是把三样放回来：

- 陈旧那一格留在卡旁边——它与卡上那一槽说的是同一件事而**受众不同**：
  槽给看屏的人，这一格给判据与读屏软件；
- `.favorites__target` 那个钩子放回，退成 `sr-only`（1×1 + `clip-path`）——
  屏上看不见，读屏与判据仍读得到。

### 还红了两条，各是一处真事

- **同一句话印了两遍**：我给「没有卡面」那一支也写了「内容不在了」，
  而既有的 `no-content` 那一支也说同一句——
  `UI-05` 红在「Found multiple elements with the text」，**屏上也真的印了两遍**。
  改成那一支不自己说话，那句话**一处**说。
- `sr-only` 这个类**本仓原本没有**。不补的话那个钩子会把裸 id 印回屏上。

## 判据自己错两次

1. **探针读 `innerText`**，把 `sr-only` 那格也算进去了——
   「屏上有没有裸簇 id」于是永远说「有」，而屏上其实没有。
   改成只量**看得见的**叶子节点（宽高 > 2px 且未被 `display/visibility` 藏）。
2. **没分清「印出来」与「挂上去」**：断言 `{item.targetId}` 不出现在那一支里，
   而 `data-favorite-target={item.targetId}` 是**给读屏的属性**，不是标题。
   拦掉它等于让不看屏的人失去「这是哪一条」。
