## 一、acceptance③ 那条比对：**对得上，所以没有开单**

工单说「两处对不上时停下开单」。逐字比过：五套 × 每章的
`id / 占比 / 字数区间 / 检查问句` 与蓝本 `const TPLS` **逐字相同**
（蓝本自己那行注释也写着「章节表来自附件 assets/templates/*.yaml」）。
判据不是我抄一份表来比，是**从蓝本 HTML 里解析出那张表**再与 yaml 比——
在测试里手抄一份的话，判的是我抄得对不对。

**只有显示名不在 yaml 里**：那五个 yaml 没有中文名/英文名这两格。

## 二、「NEVER 在前端另建一份章节清单」怎么落地

前端**没有运行时的路**去读那五个 yaml：全仓没有任何端点回报告模板
（`/design/templates` 是设计台那一族）。手抄一份又被工单明禁。
第三条路：**派生**——`tools/gen_section_tables.py` 从 yaml 生成
`web/lib/sectionTables.generated.ts`，判据每次跑都用 `--check` 核一遍是不是最新的，
且扫导航源码确认它**不含任何章节 id 字面量**。

显示名走 `messages/{zh,en}.json` 的 `wb.section.<模板>.<章节>`——
它是界面文案，写进 yaml 的话两份词典的对称判据管不到它。

## 三、差点压掉的一格：`timeline` 有两个名字

`grant/timeline` 蓝本写「时间表」，`thesis/timeline` 写「时间线」。
第一版把显示名按 `section_id` 平铺成一个键，**后写的那个覆盖了前一个**——
屏上一套会显示另一套的名字，而没有任何判据会响。
改成按模板分键（`wb.section.<模板>.<章节>`），并**单列一条判据**钉住这两个名字不同。

同一个坑我在**判据里又踩了一次**：`test_each_template_shows_exactly_its_own_sections`
第一版拿整块 `TPLS` 扫成一个扁平字典去取名字，于是 grant 那一套当场判红——
**屏上是对的，红的是判据自己**。

宽度那一格改了一行 CSS：`.workbench__nav` 原本 `inline-size:138px` 而内边距与边框
把它撑到 **148**；加 `box-sizing: border-box` 之后量到的就是 138。
判据量的是 `getBoundingClientRect`，所以钉的是**量得到的宽度**。

## 五、「是否满足」只能从后端来

`GET /deliverables/{id}/quality` 今天是 **503**（`quality` 那一族没配后端，
与 `combo` 同一种形态）。于是每一章都显示「还没有判定」——那是实话。
判据两个方向各钉一次：屏上那句话在 + **请求真的发出去过**
（只判前者的话，一个从不去问的实现也会绿）。
前端 NEVER 自己看一眼有没有块就说「通过」：「这一章有字」与「这一章过了检查」是两件事。
