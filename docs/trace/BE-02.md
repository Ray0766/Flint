## 2. 读内容与导出是两条路，不能合并

蓝本 P12 写着「内容端点未接（pack 装配仅离线）」——查看器拿不到内容。本卡补那个口。

| | `/render?fmt=pack`（既有） | `/pack`（本卡） |
|---|---|---|
| 干什么 | 出件 | 看内容 |
| 过导出门禁 | **是**（审11：预览与出件同门） | **否**——看内容不是导出 |
| 现场装配 | 由注入的 builder 出 bundle | **只读已有产物** |
| 没有产物 | 走 builder | 回「尚未生成」态 |

**读的那条路 NEVER 调装配器**（判据打在 AST 的调用名上）：
装配要跑门禁、算副本哈希、过 S2-8 自检。放进一个 GET 里的话，
**一次刷新页面就跑一遍**，而且装出来的与导出那份可能不是同一份
（两次装配之间源变了）。

## 3. 四条不肯含糊的地方

1. **章节从 markdown 里数出来**，不是写死九个字符串。写死的话，
   装配少了一章这里照样报九章，而读的人以为拿到的是全本。
   切不出章时返回**空表**——把整篇当成一章会显示一个叫「S1」、内容是整本的章节，
   **看起来像装配成功了**。
2. **产物不存在回「尚未生成」而不是 404**。404 说的是「没这个交付物」，
   而这里交付物是在的，只是 pack 还没装。反向也说：装好了要说 `generated`，
   只在没有时说话的话，读的人得靠推断。
3. **冻结件副本只给清单与哈希，不给内容**。副本是二进制、动辄几十 KB，
   塞进 JSON 里既没人看也拖慢每次打开。要看内容走导出那条路（zip 里有）。
4. **Human Digest 带 `for_ai_context: false`**。它是监工视图
   （`pack_assemble` 原话「NEVER 并入 markdown」），不带这个标记的话，
   前端会把它和九章一起喂进上下文。

**NEVER 合成分值**：章节数是**计数**不是分值。把它除以 9 变成「完整度 89%」是前端的事，
而本端点连那个分母都不给——少一章是内容问题，不是一个百分比。

## 4. 改既有文件：一处

### `flint/api/pack.py`（卡上 outputs 第一项）

- **改前**：只有 `/render` 一条路（导出面），`PackApiDeps` 三个字段。
- **改后**：**追加** `split_chapters` / `pack_content_json` 两个纯函数与
  `/pack` 一条只读路由；`PackApiDeps` 加两个**默认 `None`** 的注入点
  （`pack_owner` / `pack_ready`）。`/render` 那条路与它的门禁**一行没动**
  （判据 `test_the_existing_render_endpoint_still_exists` 与 M4-028 的既有用例都钉着）。
- **为什么非改不可**：卡上 outputs 第一项就是它。

**两个新字段默认 `None` 的后果，判据专门守了一条**：既有装配点（M4-028）
构造 `PackApiDeps` 时只给三项。如果那种 app 照样交出内容，
**等于本卡在所有既有部署上开了一个无鉴权的读口**。所以未注入时读内容直接 404。

**② 与 ⑧ 是同一类**：判据没有构造那种输入。② 我从没喂过一份没有章头的 markdown；
⑧ 我的 `_client()` 永远注入那两个依赖，而**既有装配点恰恰不注入**——
⑧ 因此不只是判据的洞，它指向一个真实部署面的风险。两条都补了。

**⑯ 为什么杀不掉，以及为什么这不是洞**：那个变异把「不存在」与「不该看到」的错误码
一起改了——因为我的实现让这两种情况走**同一行** `_error(404, "NOT_FOUND", ...)`。
逐条比状态码与错误码的判据看不出差别（两边一起变）。

这**不是判据不够，是设计让它们由构造保证相同**——比「两行必须写成一样」更强。
但那条性质仍然值得钉，所以补了一条**打在源码上**的：
读内容那条路上出现的每一个 `_error(404, ...)`，其 code 实参必须是 `NOT_FOUND`。

十七次变异后 `pack.py` 与变异前逐字相同（baseline 28 passed，含 M4-028 的既有用例）。

## 7. 登记未做

1. **`pack_owner` / `pack_ready` 没有真实实现**。本卡定的是**注入点**，
   真接线要去查 `deliverables` 的 owner 与 pack 产物是否落盘——
   那要动装配点（`harness/demo_server.py` 或生产入口），超出本卡 outputs。
   **未注入时读内容恒 404**，所以现在接上去也不会漏内容。
2. **前端没改**。vibe_pack 查看器（蓝本 P12）属 UI-03~11。
3. **章节切分只认 `## S\d+ ` 这种头**。装配器本来就这么验的（`pack_assemble`
   逐章验头），但如果哪天章头格式变了，这里会静默切不出章（返回空表，不报错）。
   空表至少不会骗人，但也不会说「格式变了」——登记在此。
4. **`tasks_json` 解不动时给空表**且 `status` 仍是 `generated`：
   硬把整个响应变成 404 会把能看的章节也一起藏掉。这是我定的取舍，卡面没写。
