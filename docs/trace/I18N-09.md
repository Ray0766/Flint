## 2 三项收尾各自做了什么

**① 扫描器**：`cjkLines` 改用共享 `_scan_lib.mjs#codeOnly`（跨行块注释 + 行尾 `//` +
CRLF 归一，一次做对三件事），并加**自证**：先证明这把尺子认得出该报的、
也不误报不该报的，再去量别人。自证不过直接退出 2——先修尺子，再量东西。

**② `app/` 三页**：`layout.tsx` 的站点标题与描述、交付物页的「未找到」、
作业页的「（连接中）」全部 key 化。站点标题也是界面文案：写死的话，
切英文时浏览器标签页仍是中文，而那是用户第一眼看到的东西。

**③ 旧词条表**：`web/lib/i18n.ts` 的 36 条并进 `messages/{zh,en}.json`（英文补齐、
键集一致），文件本身改成**薄转发**——十个 v0.3 组件的 import 一行没改，
而它们取到的与新组件取到的是同一份。两张表并存的后果不是多占几行：
同一个 key 在两处可以有不同的话，而用户看到哪一句取决于组件当初 import 了谁。

## 3 修尺子的过程里，尺子又错了两次（都记下来）

**第一次（行号偏移）**：`codeOnly` 把块注释**删掉**，于是行号整体前移——
`t.ts` 的 JSDoc 后面那一行被报成第 29 行的未 key 化文案，而那一行其实是注释的下一句。
改法：块注释换成**等量的换行**（保行数）。这个 bug 影响的不只是本工具——
`_scan_lib` 是三把扫描器共用的，所以一处修好，三把的行号都对了。

**第二次（自证漏了那条）**：修完之后我把 `codeOnly` 故意改回「删掉块注释」跑负控，
**自证居然放行**——因为原有四条用例里没有「块注释后面跟着中文代码行」这一种。
补上第五条（并断**行号**必须是第 4 行）之后，负控如实拦下：`exit 2`，
输出「期望报在第 4 行，实际第 2 行」。

这两次合起来是同一个教训：**自证只覆盖到你想到的错法**。第五条用例来自
一次真实发生的错，而不是想象。

## 4 一处口径统一
