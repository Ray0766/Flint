## E2 存储设计（增 7 张表 + 1 列 + 1 处冲突处置）

新增七张表，逐张对应 §4 的类型：

| 新表 | 承载类型（§4） | 要点 |
|---|---|---|
| `source_registry` | `SourceEntry` / `SourceRegistry` | 九区源注册表；`AuthorityTier` 与 `FetchLegalStatus` 两列，后者默认 `unknown` |
| `workbench_graphs` | `WorkbenchGraph` | 一个工作台一张图，按 owner_scope 隔离 |
| `graph_nodes` | `GraphNode` | 节点带 `NodeRole`；`source` 引用既有实体 id 体系（§6-H8） |
| `graph_edges` | `GraphEdge` | 边假设复用 combo 的 hypothesis 校验通道（§6-H8） |
| `favorites` | `Favorite` | 收藏；stale 判定复用 `Revalidator` 通道（§6-H1） |
| `template_registry` | `TemplateRecord` | 模板固化注册表（G5） |
| `share_links` | `ShareLink` / `ShareTarget` | 外链只读；token 查表，viewer 匿名走既有 JWT 中间件（§6-H2） |

- `price_entries` 加 `currency` 列，默认 `"CNY"`——字段侧真件已含币种（见 `docs/pricebook_currency_v04.md`），本节只补表列。
- **冲突处置（§9-P1）**：`snapshots` 表的 180 天周删任务与收藏冻结语义相冲——被收藏对象引用的 snapshot NEVER 被周删任务清理；周删按「无收藏引用」为前置条件筛选，冻结引用计数落在 `favorites` 侧。

## E3 API 契约（增四组端点 + 一个 query + 一个错误码）

- 新端点组：`/favorites`、`/share-links` 与 `/share/{token}`（viewer 匿名）、`/workbenches`、`/design`。
- 既有 `/plaza/hot` 增 `region` query——**增量不破坏**：不传 `region` 时行为与 v1.1 逐字相同。
- 错误码增 `EMPTY_HYPOTHESIS`（F8/F9 的服务端判据）。
- **鉴权不新建**：全部走 E3 既有 JWT 中间件的 `Principal` → owner_scope 解析（§6-H2）。外链 viewer 是匿名 `Principal` 子类型，挂同一 auth dependency，NEVER 新写中间件。

## E4 作业编排（分批锁 + 三种新 JobKind）

- `daily_ingest` 按 region 分批加锁，锁键 `lock:daily_ingest:{day}:{region}:{batch}`。单区失败只阻断该区当日更新，其余区照常（E6 部分成功语义，与 `PRINCIPLES#B5`「违反时」一致）。
- 新 JobKind 三种：`translate` / `design_generate` / `template_solidify`，**注册进既有 runner**（§6-H7），NEVER 新写 runner 类。

## E5 LLM 调用层（翻译缓存 + 流式 + 硬约束）

- 翻译调用归入「幂等判别类」缓存，内容 hash = 原文字节 + 目标语言 + translator 版本三者。translator 版本变更即缓存失效——译文带版本标记（`TranslatedText`），NEVER 让旧译文冒充新 translator 的产物。
- `design_generate` 走流式（§9-P3），复用既有 SSE 通道（§6-H4），NEVER 新开第二条事件流。
- **硬约束**：本轮 NEVER 动用真实 API key、真实网络或付费调用；`LLMProvider` 与 Translator 一律 fixture/mock 注入。

## E6 故障降级矩阵（增 3 行）

| 触发条件 | 是否阻断 | 降级行为 |
|---|---|---|
| 翻译服务不可用 | 不阻断 | 退回 `name_native` 单行显示（A7）；译文槽留空并标注，NEVER 用原文冒充译文 |
