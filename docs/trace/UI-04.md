## 4. 本卡最要紧的一条：「没查过注册表」不是「注册表不可用」

v2 2.17 写着：「模板注册表不可用 → 固化与生产渲染阻断，探索期不阻断（E6）——
**按钮置灰并说明原因**」。

这句话有个陷阱：**没查过就把按钮置灰并说「注册表不可用」，是在替后端下结论**——
而真相是我们没问过。两者的修法完全不同：

| `registryAvailable` | 屏上说什么 | 用户该做什么 |
|---|---|---|
| `null`（没查过） | 「还没查过模板注册表……这不是『注册表不可用』」 | 等接线 |
| `false`（查过、确实不可用） | 「模板注册表不可用：固化与生产渲染已阻断」 | 等注册表恢复 |
| `true` | 按钮可点 | 固化 |

两种阻断**都置灰按钮**（照 v2 原话），但说的是两句不同的话，
且带**不同的 `data-design-blocked`**——取证时分得出屏上是哪一种。

E6 的另一半也照做：**说清还能做什么**（「探索不受影响」），
否则用户以为整个设计台挂了。

这是本轮反复出现的同一条（`not_checked` ≠ `checked-false`）的第 N 个形态；
UI-03 是「没查过 ≠ 空图」，这里是「没查过 ≠ 坏了」。

## 5. 预览：零构建、脚本关掉、失败不顶替

- **零构建**：`iframe srcdoc`（v2 原话），产物是什么就渲染什么，不引任何构建链；
- **`sandbox=""`**：脚本关掉——预览的是**设计**，不是让它在我们的页面里执行；
- **失败 NEVER 用上一次成功的顶替**（v2 原话）：顶替之后用户看到的是上一版，
  而他以为那是刚生成的这一版——**他会照着那张图去固化**。
  失败时显示的是**原始产物 + 错误本身**。

判据除了行为（rerender 成失败态后旧 iframe 必须消失、旧内容不许还在），
还钉了**结构**：源码里连一个「上一版」的存放处都不该有
（`test_the_component_keeps_no_last_good_preview`：无 `lastGood*`、无 `useState`）。
有了那个变量，就迟早有人在失败分支里把它渲染出来。
