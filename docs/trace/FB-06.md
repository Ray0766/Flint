## 4. 失锚：照实标记，仍然可见（acceptance②）

`quote_span IS NULL` = 失锚：这条引用还指着一篇文献，但没钉住具体段落。
端点回 `anchored: false` + `anchor_note`，**同时照常给出文献链接与 `locator`**。

理由写进了代码与测试：**藏起来之后，正文里那句结论看上去就是没有出处的——
而它其实有出处，只是段落丢了。这两件事对读者的意义完全不同。**
断言里特意钉住「`locator` 还在」（读者仍能去翻那一页）与「文献链接仍在」。
配正例（有短段的不带失锚标记），否则前一条等于恒真。

## 5. 私有材料：规则取自冻结件，不是我写的

冻结件 `Doc` 的 docstring 原话：

> `access="private"`(用户材料): 产品内可点开原文段落; 导出/分享强制标注
> 「引自用户提供材料, 外部不可核验」, 链接不外链 [审5]

本端点是**产品内的读取面**，所以段落照给；但响应把 `access` / `external_link_allowed` /
`share_note` 一并交出去，**让下游的导出与分享有东西可依据**——下游猜不出来的规则等于没有规则。

`share_note` **在运行时从 `Doc.__doc__` 里取那对方引号之间的字**，不在代码里写死：
自己写一句的那天，导出里的说法与契约里的说法就不再是同一句，而两处都「看起来对」。
取不到时直接抛（「口径变了，本处要跟着改」），NEVER 静默回退成一句自己编的。

### 5.1 这条纪律当场抓了我一次

测试首版把期望值写死成 `"引自用户提供材料，外部不可核验"`（**全角**逗号），
而契约用的是**半角**逗号，当场红。

**写死期望值就是把契约抄了一遍**，抄本与正本迟早不一致——而这条断言存在的理由恰恰是防这件事。
改成测试与实现**各自从同一个源头取**（都读 `Doc.__doc__`），两边就不可能对不上。
