## 2. 四种处境四句话（本卡的全部重量）

v2 2.18 原话：「token 失效/过期 → 明确区分『链接已过期』与『无此链接』，
**NEVER 一律报 404 含糊过去**」。后端那侧把理由写死在
`flint/share/links.py` 的 docstring 里：

> 全报 404 看起来「更安全」，实际是把三种完全不同的处境糊成一句「没有」，
> 让持链人无从判断下一步。

对**持链人**来说，这决定他下一步做什么：

| 后端 | 屏上 | 他该做什么 |
|---|---|---|
| （未接通） | 接口未提供 | 等接线——**不是**「没有这个链接」 |
| 404 | 没有这个链接 | 检查是不是拿错了地址 |
| 410 | 曾经有效、现在不是 | 去找分享的人要一条新的 |
| 401 | 需要口令 | 输口令 |

五种各带各的 `data-share-state`，判据断言两两不同。

## 3. 410 里的理由拿不到时 NEVER 猜

后端「已过期」与「已被撤销」**都回 410**（`resolve_share`），只有错误文案不同。
所以前端拿到 410 时**未必知道是哪一种**。

拿不到理由就说中性那句（「这个链接已失效：它曾经有效，现在不是了」）——
说成「已过期」而其实是被撤销的，持链人会去等一个**永远不会来的续期**。

`reason` 有值时照它说；没有时 `data-share-gone-reason="unspecified"`。
判据钉了三种理由三个标记互不相同。

## 4. 只读：控件不渲染，token 不显示

- **不渲染任何干预控件**（v2 原话）。判据不只数按钮，还扫源码：
  `<button` / `<input` / `<textarea` / `<select` / `<form` **一个标签都不许有**——
  与保护块同一条纪律：置灰仍然告诉用户「这里本来能点」，而在外链上它永远不能点。
- **token 不上屏**：外链页面上不该出现内部 id（FB-10 A 类）。
  页面把 token 取出来是为了将来取数（`void token`），此刻一个字都不渲染。
  判据实测 `document.body.textContent` 里找不到 token。

## 8. 登记未做

1. **BE-09 的 `/public/shares/{token}` 未挂进 `app.py`**（AUDIT-01 头条）。
   挂上后本屏把 `outcome` 按状态码译出来即可：404→unknown · 410→gone ·
   401→password_required · 200→ready，四条路都已备好。
2. **口令输入没做**：`password_required` 这条路现在只说「需要口令」，
   没有输入框。口令要走 `X-Share-Password` 头（BE-09 定的，**不走查询串**），
   而输入框属交互卡；本卡先把五种处境的呈现立起来。
3. **正文渲染是纯文本**：`ready` 那条路现在直出 `body` 字符串。
   真接线时它应当走既有 `BlockTree`（交付物的块树渲染），
   且**要过导出门禁**（v2 2.18：blocking 块存在时拦截）——那是另一张卡。
4. **403（只读链接上的写请求）没有屏形态**：本屏根本不发写请求，
   所以这条路走不到。BE-09 那侧已经钉住（写方法一律 403 且无副作用）。
