## 3. 四条边界怎么落的

### ① 内容 + 数值 + 出处，字段名与冻结件逐字对齐

响应含 `Fact` 的**全部 10 个字段**（`fact_id/statement/value/unit/citation_ids/status/origin/
created_in_version/source_claim_id/promoted_from`），断言用 `dataclasses.fields(Fact)` **解析**
而不是手抄一份期望清单——手抄的那份和冻结件迟早不是同一个。
另加四个上下文字段（`project_id` / `ledger_version` / `channel` / `disputed`），
**不改冻结件的任何名字**。

### ② 三通道 NEVER 混用（S2-2）

断言方式是**集合运算**：`(PriceCell 字段 ∪ ProfileRef 字段) − Fact 字段` 与响应键交集必须为空，
所以将来任一通道加字段，这条会自动跟着变严，而不是停在我今天写死的那几个名字上。
响应另带 `channel: "fact"`——让下游**读得到**自己拿的是哪条通道，而不是靠字段名去猜。

### ③ disputed 照实返回

`status=="disputed"` → 200 + `disputed: true` + 内容照原样。
**悄悄滤掉一条有争议的事实，界面上留下的是一句没有异议的结论**——那比显示争议本身危险。
配正例（frozen 的事实 `disputed: false`），否则上一条等于恒真。

口径澄清写进模块 docstring：S2-4 说的是「disputed 的 fact NEVER 被**新生成**引用」，
那管的是生成面；**读取面把它藏起来是另一回事，且方向相反**。

### ④ 越权 404 而不是 403 + 只读

- **404**：403 等于告诉对方「这个 id 存在，只是不给你看」——**状态码本身泄露了存在性**，
  还能被用来枚举 id。`test_an_unknown_fact_looks_exactly_like_someone_elses` 断言
  「查不到」与「不该看到」**同码同错误体**；再配一条正例（本人取自己的 fact 是 200），
  否则「一律 404」也能满足前两条。
- **owner 过滤放在 SQL 里**（`p.owner ->> 'id' = $2`）而不是取回来再判：
  取回来再判的写法，哪天有人删掉那两行 Python 判断，**数据已经出库了**。
- **只读**：模块里只有 SELECT。检测器扫写库语句，且配阴性对照
  （对 `INSERT INTO` / `DELETE FROM` / `UPDATE … SET` 必须报得出来，对 `SELECT` 不报）——
  没有对照的话，「零命中」可能只是因为这把尺子什么都认不出。

## 4. 回哪一个版本

账本不可变，`facts` 按版本成行，同一个 `fact_id` 在 v1 与 v2 里可以是不同内容。
端点回**该项目最新版本**那一份并给出 `ledger_version`。夹具就照这个形态造：
`fb04-fact-1` 在 v1 是「旧版陈述 / 11.0」、v2 是「向量库托管月成本 / 12.5」，
断言必须拿到 v2 那份。**不说版本的话，两个人拿着同一个 fact_id 看到不同数字，谁都不知道差在哪。**
