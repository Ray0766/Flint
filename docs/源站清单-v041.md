### 三条不达标项，照实记（acceptance②）

1. **`google_trends_api` 的可得性与结构稳定性判 weak**：官方 API **仍在 alpha**——
   配额受限、端点集有限、需 Google Cloud 认证。**仍列**是因为它是唯一能按地区参数
   取数的官方趋势源，九区里多数区要靠它兜底。
2. **`yahoo_jp_realtime` 的结构稳定性判 weak**：官方页面写明提供排行信息 API
   （面向合作方），但**公开文档没有自助申请入口与端点契约**——接入路径要 owner 侧
   联系，属 K2 面。
3. **`reddit_data_api` 的可得性判 fail**：自助注册**已关闭**，新 OAuth 令牌需人工审批
   （公开资料称 2–4 周）；免费档**仅限非商业**用途，而 Flint 是**商用 MVP**（S1）——
   商用要另签合作协议。**仍列**是因为这条「拿不到」本身就是 owner 要看的结论
   （要不要走商务流程）。

## 未找到公开端点的区

以下各区**本轮调研未找到可直接接入的官方公开端点**——这是一条**结论**，
不是「还没查」：

- **`CN`**：**未找到公开端点**。微博热搜与百度热搜**没有官方公开 API**；
  搜到的全部是第三方转售平台（天聚数行 / 极速数据 / 幂简集成之类），
  它们既不是源站官方，也无法满足「可定位 + 结构稳定」的准入
  （[天聚数行 微博热搜榜 API](https://www.tianapi.com/apiview/100) ·
  [极速数据 热搜榜](https://m.jisuapi.com/api/hotsearch/)）。
  仓里既有的 `weibo` 源走的是另一条路（`flint/sources/weibo.py`），
  其合规态同样待 K2。
- **`AU` · `SG` · `GB` · `IT` · `FR`**：**未找到公开端点**（本轮未搜到各区**本土**的
  官方趋势/热点端点）。这五区目前只能靠 `google_trends_api` 按地区参数取数——
  而那条本身是 alpha。

**「未找到公开端点」与「该区没有源」不是一回事**：前者是本轮调研的边界，
后者是一个结论。要把它变成后者，得再查一轮（下一轮 K1-01 或 owner 指路）。

## 未决问题（不自决，写给 owner）

1. **多区源怎么落表**：`SourceEntry.region` 是**单值**。Google Trends 这类按参数分区
   的源，是按区各落一条（`google_trends_us` / `google_trends_jp`…，条目膨胀但字段
   口径不破），还是给契约加一个「多区」标记（**要动冻结件，走 PDD**）？
   本轮先按**注册地**落 `US` 一条，并在此登记。
2. **Reddit 走不走商务流程**：非商业免费档对 Flint（商用 MVP）不适用；
   要用就得申请商用合作（人工审批、按调用计费）。**这属付费/商务触点，NEVER 自决。**
3. **五区靠 alpha 兜底可不可接受**：`AU` `SG` `GB` `IT` `FR` 目前只有 Google Trends
   一条路，而它是 alpha。要么接受这个风险，要么这五区先按 E6 缺数据行走空表。
4. **权威度是初判**：`official` / `mainstream` / `community` 按「是不是该平台自己的
   官方端点」判。**K3 会给一套权威度方法论**——那之前这些值会被 K3 覆盖。
