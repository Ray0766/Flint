## 2. 本卡最大的一个决定：**没有新增源模块**

acceptance① 要「新源按既有四源的形态实现」。逐条核 K1-01 的四条候选，
**没有一条今天写得出解析器**：

| 候选 | 请求契约 | **响应契约** | 结论 |
|---|---|---|---|
| `naver_datalab` | 有官方示例（`POST https://openapi.naver.com/v1/datalab/search`，`X-Naver-Client-Id`/`Secret` 头 + `keywordGroups` 请求体） | **拿不到**：文档站本机取不到，官方示例代码只 echo 响应、不写结构 | 写解析器就得**编**响应结构 |
| `yahoo_jp_realtime` | **没有**公开端点契约（K1-01 结论） | 没有 | 连请求怎么发都不确定 |
| `reddit_data_api` | 有（OAuth） | 有 | **拿不到令牌**：自助注册已关闭、免费档仅限非商业，而本产品是商用 MVP |
| `google_trends_api` | — | — | **早就有实现**（`flint/sources/gtrends.py`） |

**编一个响应结构的后果很具体**：解析器与它的测试会**自洽**——两边都按编出来的形状写，
跑起来全绿；等哪天真连上，它一行也解析不出来。而那时它已经被当作「已实现」写进
清单与出口报告。本仓一路在防的就是这种自洽（BL-01 的「自洽不等于正确」同源）。

还有一道更硬的门：四条的 `fetch_legal_status` 全是 `unknown`（K2 未决），
REGION-07 对 `unknown` **不放行抓取**——今天连抓都不该抓。

→ 立卡 `docs/blocked/K1-02-SOURCE-CONTRACTS-MISSING.md`，把三条各自卡在什么上、
要 owner 定什么写清楚。

## 3. 所以本卡交的是「接入路径」

`flint/sources/candidates.py`（新增，**未改任何既有文件**）：

- `load_candidate_registry(payload=None)`：种子表 → `SourceRegistry`。
  **两道条件都满足才进表**：① `fetch_legal_status == "allowed"`（`unknown` 与
  `restricted` 都不进——准入标准原话「默认不当作可抓」）② `enabled is True`。
  今天一条都不满足 → **返回空表**，与 `load_seed_registry()` 的既有行为一致。
- `register_ingest_sources(store, day, regions, payload=None)`：按区取选集；
  **没有源的区落一条 `DegradationNote(reason="no_region_sources")`**（acceptance②）。
  返回值只含**真有源**的区——空区不放一个空列表进去：调用方拿到 `{"KR": []}`
  会以为「取过了、是空的」，而真相是「这区压根没源」。
- `NOT_IMPLEMENTED_REASONS`：三条没实现的**逐条给理由**。不写理由的话，下一个人
  只会看到「清单里有、代码里没有」，然后要么以为漏了，要么随手补一个编出来的解析器。

`payload` 这个注入口是**为了让阴性对照可测**：不注入的话，今天种子表里一条都不放行，
「空表」与「这条路根本不通」长得一模一样。

K2 给出合规结论那天，改的只是种子表里那两个字段。

## 5. 变异考：七个（③⑥ 各重做一次）

| 变异 | 抽掉什么 | 结果 |
|---|---|---|
| ① 合规态不检查 | 放行门 | **2 failed** ✓ |
| ② `enabled` 不检查 | 放行门 | **1 failed** ✓ |
| ③ 空区不落降级行（`store.add(...)` 整段换 `pass`） | acceptance② | **3 failed** ✓ |
| ④ 空区放一个空列表进去 | 「没源」与「空结果」的区分 | **1 failed** ✓ |
| ⑤ 降级行不说「其余区照常」 | 故障/无数据的区分 | **1 failed** ✓ |
| ⑥ 三条理由都写成「待补」 | acceptance 之外、本卡纪律 | **1 failed** ✓ |
| ⑦ 放行值改成 `unknown` | K2 未决的边界 | **3 failed** ✓ |

**③⑥ 第一次都不算数，原因不同，都记下来**：

- **③ 首版把 `store.add(DegradationNote(` 换成 `_ = DegradationNote(`**，后面几行参数
  的缩进与 `))` 对不上 → **语法坏了**，跑出来是 `1 error`。语法错误当然会红，
  但那证明的是「文件能不能编译」，**不是「测试盯不盯这件事」**。重做：按行号把整段
  调用换成 `pass`，语法完好 → 3 failed，这才是判据在起作用。
- **⑥ 首版写成 `NOT_IMPLEMENTED_REASONS = {} or {...原内容}`**，而 `{}` 在 Python 里
  是假值 → 整个表达式求值回原字典，**变异是惰性的（inert），什么也没改**。
  16 passed 因此**不是测试有洞**。重做：把三条理由的值都换成「待补」→ 1 failed。

**「惰性变异」与「测试有洞」长得一模一样，都是全绿**。区别只有一个办法能看出来：
问「我这次到底改没改行为」。本批第二次撞上（BL-04 的 `value is None` 那次同型）。

七次变异后 `flint/sources/candidates.py` 的 sha256 与变异前逐位相同。
