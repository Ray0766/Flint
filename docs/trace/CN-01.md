## 1 为什么这张卡的交付物是「停得住」

`DEC-022`（2026-08-04）授权的是 B 档抓取的**纪律形态**——抓完必录 `fixtures/`。
**欠的是首次实跑需 owner 在场**（`docs/blocked/E2E-REALSOURCE.md` 原话）。

两者是两件事。把「已授权纪律」读成「可以跑了」，正是这条红线要防的误读——
而**下一个连跑会话读到「抓取脚本可一条命令跑」就会去跑它**。

所以本卡最值钱的判据不是前面那几条「准备到位」，是
`test_the_recorder_refuses_to_run_without_the_owner_present`：
不带开关时**退出码非 0、一个请求都不发、而且拒得很吵**。

## 2 落在哪：`fixtures/_record_cn_real.py`

**住在 `fixtures/` 而不是 `scripts/`**，两个理由都成立：

1. 本仓既有惯例就是这样——`_generate_4src.py` 等一批录制/生成脚本都在 `fixtures/`；
2. 它正好落在本卡 outputs（`fixtures/` · `docs/` · 判据文件）之内。
   放进 `scripts/` 会**超出 outputs**，而本批 rules 写死那要停下走 `docs/blocked/`。

（对照：同一轮里 `SHELL-02` 就是因为够不着 outputs 之外的那一列而停下开单的。
这里不需要停——换个符合惯例的位置就行，**而不是把 outputs 悄悄扩了**。）

## 3 准备到位的四条，逐条对上

| 卡面要求 | 怎么做的 | 为什么这么做 |
|---|---|---|
| 一条命令可跑 | `python fixtures/_record_cn_real.py [--owner-is-here]` | 不需要先配环境；干跑与实跑是同一条命令的两种形态 |
| 录制路径与命名已定 | 沿用 `E12`：`fixtures/{source}/{yyyy-mm-dd}.json` | **不新发明**——自己拼一套的话，既有回放路径 `build_replay_deps` 读不到它，抓回来的真数据会躺在盘上而广场照旧显示合成词面 |
| 限速与三类错误处置已接 | 复用 `SourceThrottle`；`RateLimitedError` / `SourceFetchError` / `ParseDrift` **各接一条 `except`**，各成一条结果 | 合并之后，一次限频与一次页面改版在日志里长得一样，而两者要做的事完全不同：前者等一会儿再来，后者要去改解析器 |
| 合规状态照实记录 | 原样打印 `legal_policy.OWNER_DECISION`（`RECORD_ONLY` / `non_commercial` @ 2026-08-04） | **NEVER 在脚本里重判一次**——重判就是第二个真相，两份裁决迟早各说各的。判据连 `admits(` / `enforce_fetch_policy(` 都禁了 |

### 3.1 开关刻意不做成环境变量

`--owner-is-here` 是命令行上看得见的那一个。环境变量会被 `.env`、被 CI 配置、
被上一条命令留在 shell 里的值**悄悄打开**，而这一次点头必须是当场、显式、看得见的。
判据 `test_the_switch_is_an_explicit_flag_not_an_environment_variable`
连 `getenv` / `environ` 出现在脚本里都判红。

### 3.2 限速桶容量为什么是 1

**这一次跑总共只该发几个请求。** 桶开大了等于给一次误操作留出重试的空间——
而这条路上的每一次重试都是一次真实外网抓取。

### 3.3 录制与灌库刻意分成两步

脚本**不碰库**。录完之后另跑一条既有回放命令把当天数据灌进 demo 库。

理由：**录制是不可逆的一次外网动作，灌库是可以重来的**。
合在一起的话，灌库那一步失败会让人想「再跑一次」——而再跑一次就是再抓一次。

## 4 两条判据「按设计跳过」，而且跳得很吵

```
SKIPPED [2] CN-01 还在等 owner 在场点一次——脚本准备到位、默认拒跑，
            跑过之后会写 docs/cn-01-real-ingest-receipt.json，那时下面几条自动开始判。
            **这不是失败，是红线内的刻意不做。**
```

**「还没点头」与「点了但没抓到」NEVER 合并**：两者在「库里没有真实热点」
这个结果上长得一模一样。所以脚本跑成之后写一张回执，
那两条判据**按回执在不在**决定是断言还是跳过——
其中一条就是卡面要求的「全库扫描 `热搜话题NN`，命中即红」。

**NEVER 让它们静静地绿**：写成 `assert True` 或者干脆不写的话，
owner 点完头之后没有任何东西会告诉他「这次真的换成真数据了」。
