## 2 「既有 undo 链」是文档里的既有，不是代码里的既有

卡片 inputs 写「既有 undo 链」，H5 指向《前端功能说明 2.x》。**仓库里没有对应实现**
（`web/` 下零 undo 代码），文档那一行定的是纪律不是模块。故本卡建立这条链本身，
并把「唯一性」做成结构性保证而不是约定：**模块不导出类、也不导出工厂**——
没有第二条栈可造。这与 H5「store 断言全局 undo 栈实例唯一」是同一件事的两种说法。

## 3 关键设计判断

**一条时间线**：用户按 ⌘Z 时想撤的是「我刚才做的那件事」，不管它发生在图谱上、
编辑器里还是图书馆里。每个视图各留一条栈的话，同一个 ⌘Z 在不同视图下撤掉的是
不同时刻的操作，而用户并不知道自己此刻在哪条栈上。

**先执行后出栈**：撤销动作失败时那一条留在栈上。出栈再执行的话，失败之后这一步
就永远消失了——用户既没撤成、也再撤不了，而界面上什么都看不出来。

**满了丢最旧的**：上限 200 是写死的手写值（不是估出来的「合适值」）；丢最新的
等于让用户刚做的那步撤不回来，而那正是他最可能想撤的一步。

**读栈回副本**：外部拿到栈以后 `pop()` 一下就改了真身，那种耦合在多视图下必然出事。

**范围外但已留缝**：三个图谱操作（GRAPH-04 拖动、GRAPH-07 连线、GRAPH-09 批量角色）
的组件**尚未**调 `pushUndo`——本卡 outputs 只有 `web/lib/undo/`，改那三个已验收组件
需要各自补测试（test-first 顺序不能倒）。缝已留好：`pushUndo({view, label, undo})`
就是接线点，接线归各自视图的后续卡；本卡在测试里用 graph/editor/library 三个视图的
条目交替入栈，验的是**机制**（一条链、跨视图倒序、无法造第二条），也正是 H5 那句
「store 断言全局 undo 栈实例唯一」要的东西。

## 4 自审报告（§4.6，本卡 self_review=true）

**① 测试真实覆盖 acceptance**

acceptance①「共用一条链（全局栈实例唯一断言，H5）」：

| 测试名 | 覆盖点 |
|---|---|
| `全局实例唯一：另一次 import 操作的是同一条栈（双向可见）` | 这边推那边看得见、那边撤这边看得见、那边推这边也看得见 |
| `没有第二条栈可造：模块不导出工厂或类` | 源码断言（走共享 `codeOnly`），结构性保证而非约定 |
| `读到的栈是副本` | 外部 `pop()` 不影响真身 |

acceptance②「跨视图交替操作后连续 undo 顺序正确」：

| 测试名 | 覆盖点 |
|---|---|
| `跨视图交替操作后，连续 undo 按时间倒序撤` | graph/editor/graph/library 四条交替入栈 → 撤销顺序 d,c,b,a（一条时间线，不是各撤各的） |
| `异步撤销被等到底` | 慢的那条被 await 到底，下一次 undo 不插队（否则界面上会出现「后撤的先生效」） |
| `undo 回报撤掉的是哪一条` | 调用方据此提示用户 |

边界三条：空栈返回 null 不抛错（新开一页按 ⌘Z 不该炸）、撤销失败留在栈上、
`view`/`label` 必填（一条说不出自己是什么的撤销项没法提示用户）。
上限一条：满了丢最旧、栈顶仍是最新。

**② 无冻结件偏离**：纯前端模块，零触碰 `contracts/` 与 `contracts_v04/`。

**③ 无禁用词**：本卡两份产出扫描 `BANNED_HITS= 0`。上限那处写死具体数值并说明理由，
未使用任何模糊表述。

**④ 复用断言在位**：H5 的唯一性以「不导出类/工厂」的源码断言 + 跨 import 状态共享

## 5 一次返工（改判据不改语义）

`全局实例唯一` 初版写成 `expect(again.getUndoStack()).toBe(getUndoStack())` ——
而 `getUndoStack()` 按设计回**副本**（另有一条测试就在验这件事），两次副本永远不等。
那条红是**判据错了不是实现错了**：单例要验的是**状态共享**，不是返回值同一。
改为跨 import 的双向可见断言（推/撤/再推三段），语义比原来更强。
