## 一、单子说的是什么

一次 `npm test -- --run` 红了，而当时的命令**只 grep 了汇总行**，把用例名过滤掉了。
那次红只剩下「1 failed」四个字——不知道是哪个文件、哪条用例，
也无从判断它与 `FIX-04` 刚修掉的那处是不是同一个。**现场丢了就再也找不回来。**

## 二、三件都做了

### 2.1 连跑 30 次并保留用例名

```
连跑 30 次：绿 30 · 红 0
每跑 Tests 802 passed (802)     ← 逐跑记下的汇总行
每跑耗时 中位数 6.6s · 最长 6.8s
产物 .ui-probe/frontend-red.json（逐跑一条：退出码 / 失败用例名 / 汇总行 / 耗时）
```

### 2.2 **30 次未复现 → 写进单子，NEVER 关单**

卡面 acceptance② 逐字要求这一条。理由不是「谨慎」，是**证据不足**：

1. `FIX-04` 那处是 **40 次里第 29 次**才复现的——30 次全绿只能证明它不常见；
2. 那一次红发生在 `FIX-05` 的变异考期间（`globals.css` 被反复改写、
   dev server 一直在监听）。**这一轮没有复现那个环境**，
   所以这 30 次绿甚至没有覆盖当时的条件；
3. 本批把 `globals.css` 改了七八次、期间跑过十几轮 `npm test`，一次红都没有——
   **新的旁证，但同样不是证明**。

### 2.3 固化成脚本：`web/scripts/repeat-tests.mjs`

连跑 N 次，**每一次红都记下用例名**（行内 `× 用例名` 与汇总段
`FAIL 文件 > 用例` 两种形状都抓——两种都出现过）。

**它恒退出 0**：取证工具自己判红的话，「没复现」与「工具挂了」会长得一样。
判红那件事在 `tests/v041/test_frontend_red_capture.py` 里。

## 三、判据里最要紧的那一条是阴性对照

`test_the_script_captures_names_not_just_the_summary_line`：
喂一段**真实形状**的 vitest 输出，脚本必须抽得出用例名。

没有它，「30 次全绿」可能只是因为脚本根本不会抓名字——
**而那正是这张单子的由来**。

另外三条：每一次红都要带名字（**名字为空 = 工具没抓住现场，那本身是缺陷**）、
每跑都要记下汇总行（给人核对的那一条）、单子里的结论与产物**逐字对得上**
（红了就要有名字，全绿就要说「未复现」）。
