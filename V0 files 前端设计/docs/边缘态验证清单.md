# 边缘态渲染验证清单

**口径**：不做截图，做**可重复跑的断言**——断言写死在脚本里，谁跑都一样，回归就报错。
三支脚本各管一段：后端是否真回了诚实态 → 前端是否真渲染出来 → 坏链路是否也说人话。

**本次实测日期**：2026-08-01。**结果**：连通性 94/94、屏渲染 51/51、坏链路 33/33（5xx 15 +
不可达 18），`tsc --noEmit` exit 0，`next build`（已开启类型门）通过。

## 5 · 样本从哪来（诚实交代）

- **判定样本**（`job-gate1-live-qwen`）：跑 `harness/gate1_live.py replay-qwen`，即**产品自己的
  `run_gate1` 全流水线**，LLM 与 github/arxiv 都走既有录制回放（零联网）。产出的 verdict 是
  引擎真算的，不是我写的。
- **报告样本**（`del-demo-fixture-report`）：`harness/demo_seed_report.py`。它**不跑生成**，
  只用冻结件域对象经生产 store（`PgDeliverableStore` / `PgBlockStore`）把一棵 Block 树写进库，
  再交给**真端点**服务、**真门禁**（`guarded_render`）判导出——所以 409/保护/争议/阻断都是
  后端真算的。但**正文文本是脚本写死的夹具**，不是模型产出；`del-demo-fixture-` 前缀即为标记。
  不跑它，报告屏就如实显 404，那也是正确行为。详见文件头的「边界」段与移交说明的「待你定夺 ①」。
- **另有**：`python -m flint.jobs.compose --sources none` 能用真组稿流水线产出一份
  `del-demo-report-1`，但空 ledger 只出 7 个 heading（无正文/无诚实态），故未用作主样本。

## 7 · 解引用缺口登记（前端设计要、后端没有的读端点）

v0 设计里有四处"拿着 id 想显内容"，但后端没有对应的解引用端点。**处置一律是：只显引用本身 +
写明端点未建，NEVER 前端编内容**。这四条不是 v0 臆想出来的字段（id 都在冻结件里），而是产品
少一层读端点，故按你的规则登记待示下：

| 引用 | 出处（冻结件） | 缺什么 | 影响哪个屏 | 当前如实呈现 |
|---|---|---|---|---|
| `CitationMark.citation_id` | `contracts/models.py#CitationMark` | `GET /citations/{id}` → 标题/URL/quote_span | 报告 L0（正文引用角标、`citation_list` 块）、Gate（`key_citation_ids`） | 只显 id，不编标题 |
| `ChartContent.chart_id` | `#ChartContent` → `#ChartSpec.derived_from` | `GET /charts/{id}` → chart_type + `derived_from` 出处 | 报告 L0 图表块 | 占位框 + chart_id；`derived_from` 明写"接口未建" |
| `QualityCardContent.card_ref` | `#QualityCardContent` | `GET /quality-cards/{ref}` → 覆盖率/对齐率等 | 报告 L0 质量卡块 | 只显 card_ref，明写"NEVER 前端代算覆盖率/对齐率" |
