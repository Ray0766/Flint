## 2 owner 2026-08-08 的四条裁决（`DEC-035-038-LANDING` 逐字落地）

### DEC-035 · 地区面走迁移，不绕

`PLAZA-02` 停得对。规格 `#2.14` 白纸黑字写「`GET /plaza/hot?region=`【已建】」，而 `flint/api/views.py:66` 的签名只有 `day`——FastAPI 对未声明的 query **静默忽略**，带 `region=CN` 照样回全量 154 条。**一个静静地什么都不筛的筛选器比没有筛选器更坏**：用户会把「全国的热点」读成「这个区的热点」，并据此做判断。

**steward 已把代价核清楚**（`REGION-08` 卡面写死，省 worker 一次重查）：

```
clusters 表列 = cluster_id · canonical_name · category_id · centroid · status
              · first_seen · last_active · parent_cluster_ids · merged_into · aliases
              ← 没有 region
heat_points   ← 也没有
region 只在   trend_items_raw（0004 迁移）
              flint/region/bucketing.py 的 RegionCluster ← 模块内 dataclass，从没落过库
```

**所以要迁移**：`clusters` 加 region 列 + 回填 + 日更作业写入。三张卡（`REGION-08/09/10`）。

**回填有一条硬规矩**：`region` 随成员走、NEVER 靠簇去推断（`bucketing.py` 自己的原话）。回填时撞见成员跨区的簇 → **停下上报，NEVER 取众数**——那说明数据面已经破了 `PRINCIPLES#B5`。

### DEC-036 · 主题名称三元组：改规格，不动冻结件

冻结件 `Topic` 的全部字段是 `topic_id / seed_id / one_liner / target_user_tag / form_factor_tag / why_now / keyword_mapping / embedding`——**它本来就没有名称**。规格 `#2.4` 那句「名称三元组上屏」大概率是从热点簇那边抄过来的（**簇确实有**，`HotspotCard` 正在用）。

**改规格比动冻结件便宜得多，而且它才是对的。** `SPEC-01` 顺带建一条判据：**规格里凡提名称三元组的实体，冻结件里 MUST 真有那两个字段**——下一次抄错会被拦住。

### DEC-037 · 那条红：改取证样例，不改产品

`/jobs/m1004-j` 回 403 是第 4 批鉴权接上之后的**正确行为**：那条作业的发起人不是探针用的 `self`，屏上正确显示「无权查看」。**红的是取证样例**——样例 id 是鉴权之前从库里查的。

`D_insufficient → void`（证据不足 = 有形空缺，语义逐字相同），其余三类 → `verified`，**分类本身由标签文字承载**。理由是 worker 写的那句：**借一个已经有主的记号去说另一件事，比不给记号更坏**——`disputed` 是铁律级的事实状态，不能拿去表示「红海赛道」。

## 3 广场那张卡为什么是空的

`GET /plaza/hot` 每条 cluster 实际只回八个字段：

```
cluster_id · canonical_name · category_id · status
by_source · total_heat · hotness · hotness_components
```

**卡片六槽里五槽后端不返回**。逐槽的代价差别很大：

| 槽 | 缺在哪 | 本批怎么办 |
|---|---|---|
| **首见日期** | 列在 `clusters` 里、字段在冻结件 `Cluster` 里，**端点没回而已** | `SLOT-01`，**零迁移** |
| **陈旧标记** | 口径归 Revalidator，`HOTSPOT-06` 的适配器已建 | `SLOT-02`，接适配器 |
| **机翻译名** | `translate` 作业**至今没有消费者**（`dispatch.py` 的 `UnwiredKindReason` 三条之一） | `SLOT-03`，接消费者 |
| **地区** | `clusters` 表没有这一列 | `REGION-08`，要迁移 |
| **Gate 判定** | cluster→判定的对应关系没持久化（`DEC-012` 已说明，`GET /clusters/{id}/verdict` 不存在） | **本批不做**，见 §7 |

**这是同一种病的第三次变体**：能力建好了路由没挂（51 条）→ 组件建好了屏没用（`HotspotCard`）→ **卡槽建好了端点不返回**。`SLOT-01~03` 与 `REGION-08~10` 就是修它。
