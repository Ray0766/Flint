## 2. 先查清楚：三张表一张都不存在

`users` / `orgs` / `memberships` 在 `migrations/versions/` 里**一张都没有**

## 3. 越权在结构上不可达——所以 NEVER 写那个 404 分支

acceptance③ 是本批四张 BE 卡共用的一句「越权取他人资源返回 404 而非 403」。
本端点**没有 id 入参**，读到的恒是调用方自己，越权根本没有入口。

这时写一个 404 分支不是保险，是**给它留一条日后能被接通的路**：
有了那个分支，后来的人加一个 `/account/{who}` 只需要改一行路由。
所以判据钉的是「结构上不可达」本身：

- `test_the_route_has_no_path_parameter`：AST 取出全部路由字符串，
  断言恰好一条 `/account` 且不含 `{`；
- `test_the_principal_is_exactly_the_caller`：返回的 principal 逐字等于头。

变异⑭（路由改成 `/account/{who}` 并拿路径参数当身份）一次红 20 个。

## 5. 变异考逼出来的一处真隔离（本卡最重要的一条）

十七个变异体里 **⑨ 与 ⑬ 活了下来**。

### ⑨ 是真洞：别人的档案会被贴到你的账户屏上

变异体把 `principal` 改成「用档案里的 id」——**全绿**。
原因是所有用例里档案的 `user_id` 恰好等于头，**这条隔离当时根本没被判**。

想清楚之后发现不只是判据缺一条，实现也缺一道：
数据源若键错了、或按邮箱查串了行，拿回来的可能是**别人的 `User`**，
而本模块会把那个人的名字与邮箱原样显示。这正是 acceptance②
「NEVER 返回其它租户的任何信息」。

**改前**（`_profile` 只认 `checked` 与 `user is None` 两个条件）：

```python
def _profile(user: User | None, *, checked: bool) -> dict[str, Any]:
    if not checked: ...
    if user is None: ...
```

**改后**（多一道调用方过滤，与成员关系那一处同一条纪律）：

```python
def _profile(user: User | None, caller: str, *, checked: bool) -> dict[str, Any]:
    if not checked: ...
    if user is not None and user.user_id != caller:
        user = None          # 拿回来的不是你的档案 → 丢掉
    if user is None: ...
```

**为什么非改不可**：多租户隔离 NEVER 只靠调用方查对了。成员关系那一处
一开始就滤了（变异⑥当场红），档案这一处漏了——两处是同一件事，
一处滤一处不滤，就是隔离只做了一半。

补判据 `test_another_users_profile_is_dropped` + 变异⑱（把过滤改成 `if False`）当场红。

### ⑬ 是判据不够硬：词没出现，路已经通了

变异体加了一行 `import os` —— 我原来的判据扫的是「有没有 `environ` / `secret`
这类标识符」，`import os` 一个词都不占，于是全绿。

判据改判在 **import 白名单**上（`__future__` / `collections` / `dataclasses` /
`typing` / `fastapi` / `flint` 之外一律不许）。之后 ⑬ 当场红；
再加一个真读环境变量并塞进响应的 ⑬′，红 3 个。

**扫词判不住结构**——这条与 BE-03 那个「假变异」是一对：
一个是变异不真变，一个是判据判的不是那件事。

## 9. 登记未做

1. **没挂进任何 ASGI 应用**。BE-01/02/03/04/05 五张卡同一件待办——装配超出卡上 outputs。
2. **`load_user` / `load_memberships` 没有真实实现**，因为**三张表还不存在**。
   真接线要先有 users / orgs / memberships 迁移（属身份任务，本批无此卡）。
   未注入时本端点报 `not_checked`，**不会假装查过**。
3. **组织不报名字**。`Org.name` 要 orgs 表；这里只报 `{kind: "org", id}`。
   报一个 id 当名字，或拿 id 拼一个名字，都是造数据。前端 R1 屏当前显示 id。
4. **角色只解析一层**。冻结件 `Principal` docstring 的第二条分支是
   「经 `Membership.role` 解析」，本端点如实转出成员行；
   **组织层级嵌套（org 属于 org）冻结件里没有**，所以这里也没有。
5. **`RoleResolver`（既有 `Callable[[str, str], str | None]`）没用上**。
   它按 (user, org) 点查一个角色，本端点要的是**列出全部 scope**，
   点查凑不出列表。真接线时两者应共用同一张 memberships 表，
   NEVER 各查各的——否则同一个人的角色在两处会不一致。
6. **额度/套餐/用量一个都不报**（判据 `test_no_plan_or_tier_is_synthesised` 钉住）。
   那是 BE-06 `/billing` 的事，且它有自己的「计费未启用」如实态。
