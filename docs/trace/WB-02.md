## 一处刻意没照蓝本（`SHIP-14` 首节要列）

蓝本把证据卡列成一份**与热点无关的清单**——它是 demo，数据写死在 `state` 里。
本仓证据卡按簇取（端点签名就是 `/clusters/{id}/evidence-cards`），
凭空列一份「所有证据」要么多打 N 次请求，要么编一份出来。
改成「选了哪几条热点，就列那几条的证据」，一条都没选时如实说——
空清单与「你还没选」在屏上长得一样，而后者是用户该做点什么的信号。

## 三种空态 + 一处诚实性修正

`empty` / `out_of_scope` / `failed` 各有各的记号与文案，
判断顺序照广场**先判 `out_of_scope`**（不在范围内时结果必然为空，
先判空的话那一态永远走不到）。两句文案照搬广场既有的
（`plaza.empty.no_data_today` / `plaza.out_of_scope.line`）。

写到一半发现 `failed` **从来没被置起来过**：往回找日期那个循环把每一天的异常
都吞掉，走完窗口就 `setClusters([])`——后端整个不通时屏上会说
「该区当日无数据」，而我们根本没查成。补了一个 `answered` 标记：
一次都没答上来 = `failed`，问到了而答的是空 = `empty`。

## 两处判据自己是缺陷

1. 探针按记忆写了 `.hotspot-card__name` —— **那个类名不存在**（主行在 `NativeName` 的 `[data-testid=native-primary]`）。于是 `clickedNames` 恒是 `['', '']`，「chip 上印的是不是那两条」这条判据拿两个空串去比，**永远不可能对上**。
2. 空态判据把这一段里所有 `wb.cards.*` 文案都收进来判两两不同，而「正在取…」被热点栏与证据栏各引一次 → 当场红。收窄成**只比那三句**，另加一条判三个机器可读记号分得开。
