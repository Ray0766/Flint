## 3. 为什么不删这个常量（acceptance③）

0.90 治的是**旧模板 check_questions 结构考核面**（`check_answer_report`：规则派生、
合成 golddocs 上自证）。**生产**答作率的绝对 0.90 线已依 owner 裁决 @2026-07-30 作废，

`test_the_milestone_self_check_still_depends_on_it` 是这句话的机器版。

## 4. 注释挡不住复制（acceptance②）

`eval/doc_metrics.py` 已经写了十行范围界定注释，末尾还写着「NEVER 表述为生产口径
达标线、NEVER 顺手改 0.90 值」。**注释只能劝住读它的人**——下一个人在生产路径里写
`from eval.doc_metrics import CHECK_ANSWER_LINE`，今天没有任何东西会红。

本卡补的就是那一下红：全仓扫 `*.py`，**代码面**引用这个名字的文件必须在
`ALLOWED_CODE_REFS` 名单内（三条，逐条写明角色）；不在名单里就点名报出来。

**名单是闭集，且有反向断言**：`test_the_allowlist_has_no_dead_entries` 要求名单里
每一条今天仍真的引用它。只增不减的名单会慢慢变成一张许可证，而许可证不是判据。

## 5. 判断只看代码面，留痕不能被判据挤掉

同一个名字出现在 docstring 与注释里是**正当的**——那正是在说明为什么不能沿用它。
所以 `code_face()` 先用 AST 把 docstring 清空、再 `ast.unparse`（注释在 AST 里本来就没了）。

把注释也算成引用的后果很具体：它会逼着后人删掉解释才能让尺子闭嘴，
而那是本仓一路在守的反面（判据不该与留痕互相取消，本批第十次同型）。

**两个方向都钉住**：
`test_the_production_paths_never_touch_it_in_code`（代码面零引用）与
`test_the_production_paths_still_explain_why_not`（注释里那句话必须还在）。
删掉解释，下一个人只会看到「生产这边没有门」，然后顺手补一个 0.90。

**普通字符串仍算引用**：`getattr(dm, "CHECK_ANSWER_LINE")` 是真用法，
而从字符串本身看不出意图——docstring 是唯一例外，因为它按位置就能认出来。
