## 3. 判据：两类算、三类不算

| 算违规 | 例 |
|---|---|
| **分支假设**：与写死的地区字面量比较 | `lang == "zh"`、`source_id in ("weibo", …)` |
| **调用点写死**：给 `locale=` / `lang=` / `region=` / `source_id=` 传死值 | `run_gate1(…, locale="zh-CN")` |

| **不算** | 理由 |
|---|---|
| 默认值（`locale: str = "zh-CN"`、`.get("locale", "zh-CN")`） | 默认说的是「今天跑哪个地区」，不是「只有这一个地区」 |
| 类型标注 / 支持面声明（`Literal["zh","en"]`、`frozenset({"zh","en"})`） | 那是**声明支持面**，V2 加一个成员即可 |
| 数据表的键（术语表的 `"zh"` 列） | 表是数据，不是分支 |

三类「不算」各有一条正例用例守着——**判据窄下来，尺子才有人看**。
还有一条完整的正例 `test_a_correct_locale_dispatch_passes`：一段按 locale 查表 +
透传的正确写法必须放行（acceptance③）。

**注释与 docstring 天然不进 AST**，所以本卡不用另写剥注释那一步——
这是选 AST 而不是正则的直接收益。

## 5. 构造一个值 ≠ 替调用链定地区

判据按被调者是不是**类名**（首字母大写）区分：

- `UserProfile(locale="zh-CN")` —— **造值**：字段必填，不给就造不出来；
- `run_gate1(…, locale="zh-CN")` —— **传决定**：值本该从 profile / 请求 / 配置里来。

两条测试各守一边（`test_constructing_a_value_with_a_mandatory_locale_is_not_a_violation`
与 `test_passing_it_down_to_a_function_is_still_a_violation`），
且变异「构造判据放宽成全放行」→ **5 failed**。

## 6. 白名单：逐条列名 + 机制可注入（acceptance④）

`WHITELIST = {"flint/sources/weibo.py": "weibo 源本体就是中国特有的（V2-001 原话）"}`。
**逐条列名，不是整目录放行**——放一个目录，下一个人会把新代码写进那个目录。

豁免的命中**照样列出来**（进 `exempted`），只是不判红：藏起来的话，
「白名单里那些文件有多少地区假设」就没人知道了。

**现状登记**：`flint/sources/weibo.py` **今天一处命中都没有**，`exempted` 是空的。
白名单条目是**预留**的（卡面要求机制存在且只留给中国特有的源）。
`test_the_real_whitelist_exempts_nothing_today` 把这句话钉住——哪天 weibo 源真写了
地区分支，它会红，提醒那时的人来更新这段登记。
