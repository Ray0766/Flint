## 决策日志
- **Gate 集成 = 最小改法（owner #8）**：不动 gate 内核。chosen Topic → `topic_to_keywords` 派生 keywords → 照原样进 `run_gate1(keywords)`。`gate1.py` **零改动**（run_gate1 签名/判定单位不变，仍 keyword-unit）。
- **`topic_to_keywords`（gate_adapter.py）**：从 `Topic.keyword_mapping` 取「键 + 值」扁平、strip、去重保序；mapping 空 → 回退 `seed.keywords`；两者皆空 → `[]`。**hypothesis NEVER 参与**（owner #8：关联假设=人类判断，gate 只认证据、不判假设对错）。
- **/analysis 加可选 topic_id（owner #5，向后兼容）**：`AnalysisSubmitRequest` 加 `topic_id: str|None=None`，`keywords` 默认 `[]`（旧测显式传 keywords 不受影响）。端点：带 topic_id 且注入了 `topic_keywords_for` resolver → keywords = 派生；否则 = body.keywords（旧路径逐字不变）。**未开新端点**。
- **resolver 经 `AnalysisApiDeps.topic_keywords_for` 注入（默认 None）**：None = 端点不支持 topic_id 派生（旧部署零影响）。真实接线：resolver = `PgTopicStore.load(topic_id)` → `topic_to_keywords`。测试用记录型 resolver + 记录型 `enqueue` 钩子捕获喂 gate 的 payload keywords（payload 不落 jobs 表，故经 enqueue 钩子断言，非查库）。
- **build_project / choose_topic（owner #6）**：`build_project` 建容器（chosen_topic_id=None、deliverable_ids/change_log 空）；`choose_topic` 校验 `topic_id ∈ topic_ids`（越界 `ProjectValidationError`），写 chosen_topic_id + append change_log `{action:choose_topic, topic_id}`，返回**新 Project**（不原地改）。**verdict↔topic 经 Project.chosen_topic_id 链接**（该 project 的 analysis job → snap-{job}-verdict，既有链路）。持久化走 PgProjectStore（TS-001），往返保真。
