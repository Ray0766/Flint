## 4. 一个自己写出来又拆掉的设计

第一版把「当前批次的原文」放进模块级全局 `_ORIGINALS`，供「建议是否等于原文」
这条判断用。测试直接调 `parse_review` 时那个全局是空的，于是那条判断失效——
**测试当场把它照出来了**。

拆法：`parse_review(expected=...)` 收 `set` 或 `dict`，给 dict 时连原文一起给。
「建议与原文一样」这件事**只有知道原文才判得出来**，把它写进签名比藏在全局里诚实。
藏起来的那份状态还有个更远的害处：两次审校之间它会变成一份过期的影子目录。

## 5. 三条边界（acceptance②③）

1. **`en.json` 一个字节不动**：审校结果落旁挂文件。写回去等于「机器改的文案上线了」，
   而 `needs_review` 只在旁挂文件里——下一个人打开 `en.json` 看到的是一份
   **看起来已经定稿**的目录。改写以纯函数 `apply_suggestions()` 提供，
   `__main__` **不调它**；
2. **每条都带 `needs_review: true` + `reviewed_by: "machine"`**，连判 `ok` 的也带：
   机器说没问题不等于人看过。采纳建议之后**仍是待审**——改写本身也是机器做的；
3. **旁挂文件里不放译文本身**：放了就有了第二份目录，而两份里总有一份是旧的。
   有断言守着（`test_the_sidecar_never_becomes_a_second_catalog`）。

## 6. 变异考：十六个，三个先活了下来

| 变异 | 抽掉什么 | 结果 |
|---|---|---|
| ① 提示词不问机翻味 | acceptance① | **20 passed** ✗ → 补判后 **1 failed** ✓ |

| ⑤ 坏回复不报错 | S2-3 | **1 failed** ✓ |
| ⑥ 建议等于原文也留着 | 清单可用性 | **1 failed** ✓ |
| ⑦ 机审当成定稿 | acceptance② | **1 failed** ✓ |
| ⑧ 机审冒充人审 | acceptance② | **1 failed** ✓ |
| ⑨ 直接标成人已确认 | acceptance② | **1 failed** ✓ |
| ⑩ 采纳后不再标待审 | acceptance② | **1 failed** ✓ |
| ⑪ 花费恒记 0 | acceptance④ | **1 failed** ✓ |
| ⑫ `kind` 越界放行 | 分诊 | **20 passed** ✗ → 补判后 **1 failed** ✓ |
| ⑬ 没写理由也放行 | 分诊 | **20 passed** ✗ → 补判后 **1 failed** ✓ |
| ⑭ 不分批（一次全塞） | 上下文上限 | **1 failed** ✓ |

**① 为什么能活（本仓第十五次同型）**：判据是「提示词里有 `machine-translated`
这几个字」，而**回复格式那一行**里写着
`"ok|grammar|terminology|machine-translated"`——把断言喂饱了。
抽掉第 3 条指令，模型再也不会被问到机翻味，而判据毫无反应。
修法：判据**只看指令那一段**（`Entries:` 之前），且要求恰好三条编号指令，
每条各含一个角度。

**⑫⑬ 为什么能活**：`kind` 越界与 `note` 空缺，一条测试都没喂过。
两者都是**分诊**用的字段：`kind` 越界会让清单上出现没人知道怎么处置的类别；
`note` 空着则等于「这条有问题但不说哪里」，读的人只能重新自己审一遍——
那等于这次机审没发生。各补一条（`note` 那条测空串与纯空白两形）。

十六次变异后 `harness/i18n_review.py` 的 sha256 与变异前逐位相同。

## 8. 登记未做

1. **20 条改写建议一条都没采纳**：`apply_suggestions()` 在，但 `__main__` 不调。
   采纳是人的决定（acceptance② 的直接后果）。**`workbench.switch.unarchive`
   那条不一致是真的**，值得优先看（§3）。
2. **没有校验建议本身的质量**：模型给的改写没有第二个模型复核。
   要复核就是 JUDGE-03/04 那条判官路线的事。
3. **`ok` 的 116 条也标了待审**——这不是保守，是口径：机审没有人审的效力。
   但它的副作用是**待审清单等于全表**，人真要审时还是得从头看。
   要缩短清单，得先有「哪些条目值得人先看」的优先级口径，本卡没定。
4. **只审了 en**：zh 是源语言，没审。zh 的文案质量是另一条线（产品文案面）。
5. **命中率没记**：`reconcile()` 里有 `cache_hit_tokens`，但本卡的报告没把它单列出来。
   6 次调用共用长前缀，命中应当发生过——**下次值得把它打进报告**，
   那是判断「批大小选得对不对」的直接依据。
