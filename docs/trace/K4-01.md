## 3. 谷歌免费档的响应形状是**录出来的**

真发了一次请求（`translate.googleapis.com/translate_a/single?client=gtx`，免费无 key），
录进 `fixtures/translate/google_free_zh_to_en.json` + manifest。真实形状：

```
[[["Quantum computing is an emerging technology. ", "量子计算是一种新兴技术。", ...],
  ["It is developing rapidly.", "它正在快速发展。", ...]], null, "zh-CN", ...]
```

**两件事只有真录了才知道**：① 译文与原文是**同一个数组里的前两项**——
按位置取错一位就会把原文当译文返回；② 长文本被**切成多段**，
只取第一段就是半截译文（acceptance④ 明令禁止的那种）。
这两条现在各有一条断言守着。

录制件按 NET-02 的信封形状存（`[{url, body_text}]`），与四源的录制件同一个形状，
`verify_fixture` 才核得动——**换个形状就等于这份录制件没人核**。

**⑥ 为什么能活**：那条断言里的 429 响应体给的是 `{}`，**解析不了**——
于是抽掉状态码检查之后，报错照样从解析器抛出来，断言照样红。
**判的其实是解析器，不是状态码**。修法：把响应体换成录制件里那份**合法形状**，
这样只有状态码检查能救它。真实后果很具体：限流页若带一个能解析的体，
就会被当成译文写进缓存。

**⑫ 为什么能活**：一条断言都没盯「成功的译文要入缓存」——
`translator.py` 的幂等缓存是既有机制，我默认它还在。补了两条：
同一段翻两次只问模型一次（`test_a_successful_translation_is_cached`）、
换引擎不串译文（`test_the_cache_is_not_shared_across_engines`），
并顺手加了 ⑬ 的变异确认缓存键含版本。

十三次变异后 `flint/i18n/translate.py` 的 sha256 与变异前逐位相同。

## 7. 登记未做

1. **`select_translator` 还没有调用方**：既有的翻译使用点走
   `translator.py#translate_or_degrade`，本卡加的是 `translate_marked`
   （多带 provenance）。把使用点切过来要改 `flint/i18n/name_display_job.py`
   与卡片渲染，**超出卡上 outputs**。
2. **`TranslatorConfig` 没有从环境/配置文件读的装配代码**：现在靠调用方传入。
   接进 `flint/config.py` 的通道要定「provider 实例怎么从配置构造」，
   那是 BE 组接线的面。
3. **本地模型这条路没有跑过真模型**：测试用的是替身。真跑要起本机 Ollama
   （`harness/run_worker.py` 那条路），属编排面。
4. **谷歌免费端点没有官方契约**：`client=gtx` 是公开可用但非官方文档化的接口，
   随时可能变。所以解析器的结构漂移**必须报错**（有断言守着），
   而不是静默返回空串——这条设计正是为它准备的。
5. **只录了 zh→en 一份**：其它语向没录。多语向的形状应当一致（同一端点），
   但**没验证过**。
