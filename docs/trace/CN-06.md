## 1 用说真话的旗标

`--authorized-by=DEC-052`。**NEVER 冒用 `--owner-is-here`**——
那个旗标的语义是「owner 此刻在场」，而这一次是预授权、owner 不在场。
**旗标的名字就是它的诚实性**：冒用一次之后，盘上再也分不出「谁点的头」。
回执里 `authorized_by` 逐字记下来，两种授权 NEVER 混成一个。

## 2 三次实跑，前两次都不算数——而第二次「成功」了

| 跑 | 结果 |
|---|---|
| ① | 四源全败：`DecodingError: incorrect header check` |
| ② | 四源全 `ok`——**而 ghtrend 与 arxiv 录的是 gtrends 的响应** |
| ③ | 四源全 `ok`，各录各的 |

**第一次**：录制传输层 `read()` 拿到的是**已解码**的字节，却带着
`content-encoding: gzip` 重建响应，外层再解一次就炸。
在录制器侧要 `Accept-Encoding: identity`——**而不是去改 `flint/testing/replay.py`**
（那个文件不在本卡 outputs 里，且**录下来的夹具本来就该是明文**：
存一份压缩流进仓库，下一个人打开它看到的是一堆二进制）。

**第二次是本卡最值得记的一处**：录制器的适配器分派写的是
「weibo 用 `WeiboHotSource`，**其余一律 `GoogleTrendsSource`**」。
两源时代那是对的；扩到四源之后，`ghtrend` 与 `arxiv` 被**录成了 gtrends 的响应**，
而回执报的是 `ok`。

> **这比失败更坏**：失败会喊，而这一种安安静静地把三份一样的东西
> 存进三个不同的目录，且它们**有 manifest、有 sha256、看起来样样齐全**。

是核对 provenance 里的 URL 时发现的——判据因此逐源钉住「manifest 记的是它自己的端点」。
分派收进 `_ADAPTERS` 一处：散在 if/else 里时，**加一源忘改它不会报错，
只会把新源录成旧源**。
