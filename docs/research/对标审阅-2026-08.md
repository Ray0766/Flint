## §3 明确不抄的与为什么

1. **关键词/Jaccard/正则指纹聚类路线**（TrendRadar、agent-pulse、trend-pulse 三仓同路）：Flint 已锁 bge-m3 + pgvector + 凝聚聚类（S3，registry 校验 @2026-07-26）。启发式路线的代价这三仓都露出来了——agent-pulse 的模型家族指纹需人工维护且跨语言在它自己的待办里；trend-pulse 的 TF-IDF 是 O(n²) 靠截断活着。语义聚类是 Flint ②段少数真差异之一，NEVER 降级去省这笔算力。
2. **失败伪装成功的容错哲学**（TrendRadar json 修复第三级纯文本兜底标 success=True；agent-pulse stopCondition 兜底文案静默替换）：直接违反 S2-3「verdict 类失败 NEVER 猜测」。这两个仓证明该哲学的后果：产物不可作可复现引用源。修复链的前两级（本地确定性修复）可借（§2-4），第三级 NEVER。
3. **第三方聚合 API 单点路线**（TrendRadar 全靠 newsnow.busiyi.world 公共实例）：可用性与合规完全外置，与 Flint 的数据源合约单（K1-02）方向相反。四源直连更重但可控、可录制回放。
4. **多 agent 编排框架整仓引入**（CrewAI/LangGraph/CrewAI 脚手架）：三个证据——ccandelora 证明框架脚手架可以与真实链路零关联还挂在 README 上；kumar-sanchay 的 LangGraph 是固定拓扑（框架没带来自主性）；academic-commercialization 用 CrewAI 用得好但其全部价值在框架外的 guardrail 代码里。Flint 的编排已锁 arq + 自建 Job 状态机（D6），框架不带证据纪律，引入只多一层锁版负担。
5. **「多智能体分工」作为宣传面**（ccandelora 教训）：README 驱动开发的反面样本——宣称六 agent、实际是未改动脚手架。对 Flint 的镜像警示：vibe_pack 的宣称能力必须逐条有 verify_cmd 兜底（本仓 S7 已是此纪律，维持）。
6. **计划书内嵌视觉 mockup**（ccandelora 的产品点子）：V1 不做——五套人类模板范围已冻结（S1），视觉稿生成是新能力面、新依赖族。若 V2 重开，接缝在 compose 模板的资产位（无需现在留代码）。
7. **LLM 主观分代替确定性检查**（LaunchPad 的 node-importance-ai、TrendRadar 的 ai_filter 作为唯一过滤面）：Flint 双尺评分里客观尺必须保持确定性可复现，LLM 尺只能是第二把（判 C 对称、D9 语义）。
8. **同文档受众分节冒充受众分叉**（agent-pulse decisionCards、TrendRadar 三角色段）：这是全网现状的天花板，恰是反例——同一份产物里给四类人各写一段，证据深度与结构不变。Flint 的分叉是交付物级（模板族 + vibe_pack 章节族），NEVER 退化成分节。
