## 2. 承重墙：三层判据钉住「生产渲染 NEVER 收 html」

异见 B5 已判**维持**。这堵墙塌了，两阶段模型（探索期自由 / 固化闸门）
就只剩一个说法——固化时拦下的示例数字、来源残留、水印，全都能从 html 口子绕过去。

| 层 | 判据 | 变异 |
|---|---|---|
| 请求模型里**没有** html 字段 | `ProductionRenderRequest.model_fields` 恰好两项 | ① |
| 递进来一个也不收（`extra="forbid"`） | 带 html 的请求 422 | ② |
| `ExploreRenderer` **够不着**生产那条路 | AST 上取生产处理函数 + 它调到的本模块辅助函数的名字闭包 | ③ |

第三层第一版只看处理函数本身，而渲染器是经 `_renderer()` 拿的——
判据当场红得没道理。改成**一层调用闭包**后既不误伤也不放水。

## 3. 变异② 揭出的一条：判据绿了，但绿的是别的原因

变异② 把 `extra="forbid"` 改成 `"ignore"`——**全绿**。

原因：那条判据发的请求 `slot_values` 是空的。html 被悄悄丢掉之后，
请求因为**缺插槽**而 422——判据看到 422 就满意了，
而它本来要判的是「html 被拒」。

修法是先证明这份请求**本来会成功**（插槽全填对 → 断言 200），
再加 html 断言 422。这样 422 就只可能来自 html 那一层。

**「测试绿了」与「测试判到了它要判的东西」是两件事**——
这是本轮第一次遇到「判据因错误原因通过」，比假变异更隐蔽：
假变异是变异没生效，这个是判据判错了地方。

## 5. 写测试时被真件教了两次

| 我写的 | 真件 |
|---|---|
| `Block(parent_id=..., block_type=...)` | 真字段是 `section_id` / `type`，还有必填的 `claim_ids` / `fact_ids` / `revision` |
| 脏内容塞在 `data-slot` 标记区里 | 标记区会**先**被换成 `{{slot}}`，里面的东西到不了残留检查——那是对的，那块本来就是要填内容的 |

第二条同时解释了「版本序列」用例：第二版必须改**插槽之外**的内容，
否则两版 html 逐字相同 → 同内容去重 → 根本不产生第二版。

（第一条是 BE-03 那条「按记忆造字段名」的第五次。修法恒是：读真件。）

## 6. 陈旧提示：「不 stale」的形态是**不出通知**

变异⑳（把 `notice.stale` 写死成 True）**全绿**——读源码才看清它是**假变异**：
`notices_for_change` 出的每一条通知本来就恒 `stale=True`，
结构性判定归 `derive_stale`，非结构性变更**根本不出通知**。

所以补的是另一条真判据：`node_moved` → **一条通知都没有**。
把布局变动也算成陈旧，会让「陈旧」这个信号迅速失去意义——
每天挪几下图，满屏都是黄标，然后没人再看它。
补的变异⑳′（绕开 `derive_stale` 给所有变更都出通知）当场红。
