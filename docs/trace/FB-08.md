## 4. acceptance② 的正题：不确定 NEVER 伪装成确定

冻结件 `GapHint` docstring 原话：

> expand 拒绝注水的出口 [D13]。**missing_permission 绝不伪装成缺资料 [审8]**：
> missing_data → 「补充以下任一即可」+ 一键注入；
> missing_permission → 「需 {required_scope}, 你当前无权访问」→ 请 owner 授权。

**两种缺口修法完全不同**：一个去补资料，一个去要权限。把后者说成前者，
用户会一直找一份根本不存在于他手里的材料。落地三条：

1. **话术取自 docstring**（`_gap_why` 运行时从 `GapHint.__doc__` 里核那两句，
   取不到就抛「口径变了，本处要跟着改」）——与 FB-06 的 `share_note` 同一条纪律：
   **抄一份出来的，和正本迟早不是同一句**；
2. **权限缺口 NEVER 带 `suggested_sources`**（那是「去补资料」的话术），
   且它的 `why` 里不许出现「补充」；配正例：缺资料那条**要**给出处建议，
   否则前一条可以靠「一律不给建议」满足；
3. **每条自报 `is_conclusion: false`**——缺口是缺口，不是一句已经站住的结论。

### 4.1 取不到时回 404 而不是空列表

**空列表读起来是「这一节没有缺口」——那是一句结论**，而真相是「没人存过它」。
这正是 acceptance② 要防的那种伪装，所以默认缝返回 `None` → 端点 404。
