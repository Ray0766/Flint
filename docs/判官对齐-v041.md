## 从这张表里看出来的三件事

1. **`budget/q2`（支出在时间上如何分布）两次都翻**：两份不同组稿产物上，
   Claude 录制时判「未答」、复判判「答」，DeepSeek 一直判「答」。
   这条题面问的是**时间分布**，而正文给的是分项金额加一句「分阶段拨付」——
   判准没写清「一句概括性的阶段说明算不算回答了分布」。**这是判准要补的第一条**。
2. **分歧集中在 `timeline` / `budget` / `evaluation_plan` / `resources` 这几节**
   （21 条里 9 条）：它们的共同点是题面问的都是**结构化清单**（谁在什么时候做什么、
   多少钱花在哪），而正文常常是叙述体。**判准需要说明：叙述体里能推出清单，
   算不算作答。**
3. **DeepSeek 更宽松**：21 条分歧里 DeepSeek 判「答」的占压倒多数。
   这不必然是错——复判有 9 条站在它那边。但**用它替代 Claude 之前，
   得先把上面两条判准写清**，否则宽松会被当成「作答率提高了」。

## 一致率不达标怎么办（owner 2026-08-04 的口径）

**NEVER 停机**。降级链在 `harness/judge_alignment.py#resolve_votes` 里：

| 情形 | 处置 |
|---|---|
| 两家一致 | 采纳，`calibrated=True` |
| 三家里两家一致 | 采纳那两家 |
| 打平 / 都不一致 | `answered=None` + `needs_owner_review=True`，**进清单、继续跑** |
| 只剩一家可用 | 用它，但 `calibrated=False`——**照实标注未校准** |
| 一家都没有 | `needs_owner_review=True`，仍然返回一份结果 |

该模块**一个 `raise` 都没有**（有 AST 断言守着）：判官吵架、判词坏掉、
一条都没比成，全部表达成返回值。
