## 3. 线画在 0.95：一半权威、一半实测

**权威那一半**：DORA 2024 报告 elite 档的变更失败率 **≤5%** → 一次成功率 **≥0.95**。
搬得过来的理由：DORA 的「变更失败」= 这个变更没能一次做对、要回头补救，
与本仓 oneshot 口径（首个 verify 即绿，返工不计）问的是同一件事。
**没采用制造业 FPY**：它的良率线随工艺而定，没有跨行业可搬的数——理由写进文档，
免得下一个人以为漏了。

**实测那一半**：M4 19 卡 rate=1.0 · v0.4 台账 122 卡零 `review_failed` ·
v0.4.1 第 2 批 56 卡（本卡写时）零 `review_failed`、1 张有跨轮重入痕迹按未一次通过计。
合计 n≈197。

**误差**：三法则——n 次 0 失败时失败率 95% 上界 ≈ 3/n = 3/197 ≈ 1.5%，
即通过率 95% 下界 ≈ **0.985**。0.95 落在下界之下，所以「本项目超过这条线」
是样本量撑得住的结论，不是运气。

**为什么不画 1.0**（实测确实是 1.0）：1.0 是没有余量的线，20 张卡返工一次就判 fail；
而返工在本仓是被鼓励的（S7 的返工环，同一原因连续 2 次才升级）。
画 1.0 等于把「返工」定义成「不合格」，与那条纪律自相矛盾。

**实测那份数据的两个已知弱点照实写进了文档**：① 台账记的是事件不是 verify 次数，
用 `review_failed` 当代理会**低估**失败率；② 样本不是随机抽的，全是本仓的卡、
同一个 worker 执行，跨项目可比性未知。

## 5. 变异考：十一个，三个先活了下来

| 变异 | 抽掉什么 | 结果 |
|---|---|---|
| ① 线偷偷放低到 0.80 | 初值 | **2 failed** ✓ |
| ② 回落值另抄一份（`return 0.95`） | 单一真相 | **19 passed** ✗ → 补判后 **1 failed** ✓ |
| ③ 写错的值静默回落 | acceptance② | **1 failed** ✓ |
| ④ 越界值放行 | 配置校验 | **2 failed** ✓ |
| ⑤ 来由说明抹平 | acceptance④ | **1 failed** ✓ |
| ⑥ 权威那节删掉一行的出处 | acceptance① | **19 passed** ✗ → 补判后 **2 failed** ✓（首行与末行各验一次） |
| ⑦ 误差只留结论、删掉算式 | acceptance④ | **19 passed** ✗ → 补判后 **2 failed** ✓ |
| ⑧ 不写为什么不画 1.0 | §3 | **1 failed** ✓ |

**② 为什么能活，以及为什么它比看起来危险**：把回落分支从 `return Z_LINE_INITIAL`
改成 `return 0.95` —— **当下行为一模一样**，所以没有任何行为判据能红。
但它埋的是「第二个真相」：owner 哪天把初值调到 0.98，回落分支还是 0.95，
而那时它开始改行为。**正是这种改动最容易活到它开始改行为的那天**。
判据改成结构的：数 `config.py` **AST 里的 0.95 字面量**恰好一次。
数 AST 而不是数文本——`Z_LINE_BASIS` 那句来由说明里也写着这个数（它该写），
按文本数会把说明算成第二份。

**⑥ 为什么能活**：判据是「这一节里有 http」，删一行的链接时**别的行把它喂饱了**。
改成「每一行都有」，表头与数据行的分界**按分隔行定位**不按行数偏移
（K3-01 刚踩过这个偏移的坑）。首行与末行各验一次。

**⑦ 为什么能活**：判的是「文中出现 0.985」，而变异只改了标题，正文里 0.985 还在。
重做成**删掉整段算式只留结论**——这才是真正要防的：一个没有算式的置信下界
与拍出来的数没有区别。补判 `"3/197" in doc`。

十一次变异后两个产物文件的 sha256 与变异前逐位相同。

## 7. owner_review：三件要 owner 拍板的

1. **0.95 这个数认不认**。它不是本项目拟合出来的，是 DORA elite 档的换算值。
   实测（0.985 下界）比它高，所以画在这里是**有余量**的。
   owner 若想要更严（0.98），三法则的下界撑得住，但返工余量会从 5% 压到 2%。
2. **返工算不算失败**。本卡按「`review_failed` 出现过 = 未一次通过」计。
   K1-01 那张卡是**跨轮重入**（上下文耗尽后接着做），不是质量返工——
   我按未一次通过计（保守侧），但这两件事在台账上目前分不开。
   要分开得给台账加一个事件类型，那是另一张卡。
3. **M4 出口报告那一行要不要改**。它现在还写着「⚠️ 待 owner …… report_only」。
   线画上之后那行可以出真判定了，但改出口报告属**里程碑文书**，
   本卡没动（超出 outputs）。
