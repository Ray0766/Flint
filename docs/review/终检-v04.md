### 本批新发现

#### F-05（**实现缺陷 · 中危 · 留卡不打补丁**）GRAPH-06 的并发断言抽掉临界区后照样绿——它没有守住自己那条 acceptance

**卡号** GRAPH-06 · **acceptance②** 原话：「服务端并发双写下 primary ≤1 仍成立」
**被测对象** `flint/graph/roles.py` · **断言所在** `tests/v04/graph/test_primary_unique_runtime.py:83` `test_primary_stays_unique_under_concurrent_writes`

**复现命令**（tier ②，零源码改动；探针脚本在会话 scratchpad，未进仓库）
```python
# 把 roles._lock_for 换成 nullcontext（临界区消失，其余逻辑一字不动），打同样的并发压力
R._lock_for = lambda store: contextlib.nullcontext()
```
**真实输出**
```
加锁版（正式实现）   25 次: counts=[1] 违反(≠1)=0
抽掉临界区           25 次: counts=[1] 违反(≠1)=0      ← 坏实现照样全绿
还原后加锁版          5 次: counts=[1] 违反(≠1)=0
```
**monkeypatch 自证生效**（否则上面这个结论是假的，故单独验）
```
[1] _lock_for 被调用 320 次（期望 8 线程 × 40 轮 = 320）→ monkeypatch 生效
[2] 临界区内并发峰值 max_inside=1
```
`max_inside=1` 是本条的**直接物证**：用一把带计数的假锁量了全部 320 次写入，**从头到尾没有任何两个线程同时处在临界区内**。acceptance 里那个「并发双写」在这个测试的压力下**根本没有发生过**。

**那把锁不是没用，是这个测试打不到它**：把 `sys.setswitchinterval` 调到 1e-6 后，无锁版 20 次里有 1 次真的跑出了 2 个 primary（`counts=[1, 2]`）。竞态是真的、可达的；**默认调度下 8 个节点的清主循环几乎总能在一个时间片里跑完**，所以撞不上。

**常驻反例探针为什么没兜住**：`roles.py:84` `naive_set_primary_unsafe` 只把自己那一个置 `True`、**从不清旧主**，因此它必然留下 8 个 primary——**串行跑也一样红**。它证明的是「`primary_count` 这把尺子认得出多主」，**不证明「线程真撞上了」**。而它的 docstring 自述要挡的恰恰是后者（`test_...can_actually_fail:96` 原话「否则上一条的绿可能只是因为线程没撞上」）。**这一句目前不成立。**

**影响面**（三层，逐层都查过，不是推测）
1. 断言只看**终态**，不看过程——运行中途出现过的双主窗口，即使发生也看不见；
2. `threading.Lock` 是**进程内**的。uvicorn 多 worker 进程下它一开始就不构成保证；
3. 模块 docstring 说 SQL 等价物是 `graph_nodes` 上的部分唯一索引 `UNIQUE (graph_id) WHERE primary`——**`migrations/` 全目录 grep `graph_nodes` 零命中**，该索引不存在；`GraphStore` 自述「内存实现；SQL 实现随 E2 接入」；`flint/graph/roles.py` **无任何生产调用方**（全仓只有自己的测试 import 它）。
   → 也就是说 acceptance② 里的「**服务端**」三个字，**目前后面没有服务端**。

**为什么判中危而不是高危**：正式实现本身是对的（单进程内它确实守得住，`test_...demotes_the_first` 等四条行为断言都真实有效），产品当前也还没有并发写这条路径。危的是**这条 acceptance 目前处在「看起来验过了」的状态**——它连穿了 GRAPH-06 的 verify 与 self_review。这与 `test_m4_023` 计数哨兵藏住 `orphans` 是同一种病：**绿的原因和它声称的原因不是同一个**。

**建议修法（v0.4.1，留卡，本轮 NEVER 改）** 三选一，我推荐第 1 条：
1. **把探针换成真竞态写法**——`naive_*` 改成「读全图 → 无锁清旧主 → 立新主」，并在探针里把 `switchinterval` 调小；再加一条**元测试**断言「抽掉临界区后 `test_primary_stays_unique_under_concurrent_writes` 必红」。这才是那条 docstring 声称的东西。
2. 把断言从终态改成**全程观察**（写入过程中采样 `primary_count`，出现 >1 即红）。
3. 承认单进程锁不构成「服务端」保证，把 acceptance② 措辞收窄为「单进程并发写下 primary ≤1」，并把真正的服务端保证**挂到 E2 建 `graph_nodes` 表那张卡**（部分唯一索引）。
**三条可叠加；若只做一条，做第 1 条**——因为它修的是「尺子量不出东西」这个根因，另两条修的是表述与将来。
