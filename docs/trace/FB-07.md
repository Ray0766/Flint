## 4. 零计算（acceptance② 的正题）

每个数据点的 `value` **就是账本里那条的 value**，端点没有动过任何一个数字。
三条断言从三个角度守：

1. **逐值相等**：把响应里每个点的 value 与库里那条对比（`test_the_values_are_exactly_what_the_ledger_stores`）；
2. **字段面**：响应里 NEVER 出现 total/sum/avg/growth/pct/ratio/delta/trend 这类键，
   并要求 `computed: false` 自报家门；
3. **源码面**：扫 `chart_json` 那一段，不许对 `["value"]` 做算术、不许出现 `sum(`。
   字段名可以起得人畜无害，**算术却藏不住**——两个角度互补。

理由写进代码：**图表是报告里最容易偷偷造数的地方**。一个「合计 732.5」看起来天经地义，
而它没有出处——它是端点算的，端点不进账本、不留痕。所以这条端点连一个加号都不写。

## 5. 取不到的点照实说

`derived_from` 里取不到的 fact（不存在 / 不属于调用者）进 `unresolved`，
并给 `complete: false`。**NEVER 静默丢掉**：
**少一个点的折线图看起来完全正常**，没人看得出它少了一段。

越权调用者拿到的是 `points: []` + 三个 id 全在 `unresolved`——
**一张空图，而不是一张看起来正常的图**。
