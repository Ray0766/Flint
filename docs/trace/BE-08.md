## 2. 本卡的全部难点：四处「接线处才漏」

`flint/fav` 的四个模块**各自都是对的**，口径也都写在自己的 docstring 里。
但把它们直接接成 HTTP 端点，会漏四个洞——而每一个洞在既有测试里都看不见，
因为既有测试测的是函数，函数拿到的 owner 是调用方给对了的。

| 既有函数 | 单独看 | 直接接成端点会怎样 |
|---|---|---|
| `remove_favorite(store, favorite_id=...)` | 幂等、不抛错（对） | **不判归属**：任何人都能删别人的收藏 |
| `add_favorite(...)` 同 id 返回既有那条 | 幂等（对） | 拿别人的 favorite_id 一发请求，**读到别人的快照内容** |
| `evaluate_snapshot_stale(...)` | 判定落库（对） | 挂 GET 就是**藏起来的写**，列表页每刷一次写一次库 |
| `SnapshotPins.unpin(...)` | 取消钉住（对） | 删收藏时顺手解钉，**另一条收藏还引用着**那个快照 |

四道补丁全在端点这一层，判据也全钉在端点上（变异①②③④ 各钉一条）。

### 2.1 「删别人的收藏」是本卡最贵的一个

变异① 把归属判定去掉后，`test_removing_someone_elses_favorite_is_404_and_leaves_it_alone`
红——判据里那句 `assert len(store.all()) == 1` 是关键：
**光看状态码是 404 不够**，得断言那条收藏还在。
只判状态码的话，「先删掉再回 404」也能过。

### 2.2 陈旧判定挂 POST 不挂 GET

`evaluate_snapshot_stale` 会 `store.put`。所以：

- **列表 GET** 报的是**库里存着的** `snapshot_stale`（冻结件字段，默认 False）；
- **重算**是显式的 `POST /favorites/{id}/staleness`。

变异③（把重算塞进列表）红。判据 `test_reading_the_list_never_evaluates_staleness`
断言列一次表之后库里的标记**没变**——哪怕账本确实变了。

这与 BE-04 那条「陈旧不隐藏内容、只加标记」是一对：读路径 NEVER 有副作用。

### 2.3 pin 是补充，不是前提

`pin.py` 原话：「pin 依赖有人记得钉。忘了钉，快照到期照样没。所以它是**补充**」。
所以快照里没有 `snapshot_id` 时**照样收藏成功**（变异⑦ 把它变成前提 → 红）；
删除与刷新时**都不解钉**（变异④⑤ → 红）——
「查看当时版本」要的正是那份旧快照，解钉等于给它判了个缓刑。

## 3. 一处冻结件读法被教了

`get_args(Favorite.__annotations__["target_kind"])` 返回 **空元组**。
冻结件开了 `from __future__ import annotations`，`__annotations__` 里存的是
**字符串** `'Literal["cluster", ...]'`。

后果不是报错，是**「四种之内」悄悄变成「一种都不许」**——第一次跑时
每个 POST 都 422，`allowed: []`。改用 `get_type_hints` 后正常。
测试里也加了 `assert allowed == ["card", "cluster", "deliverable", "topic"]`，
把空元组这条路堵死（否则两边一起空，判据自洽地全绿）。

另一处：`DiffChannel` 是**可调用对象**（`(project_id, since, until) -> FactDiff`），
不是带 `.diff()` 方法的东西。我按记忆写了 `.diff()`，照 `analysis_stale`
的调用点改正。

## 4. 越权与不存在同一行

`flint/fav/stale.py#_owned` 把两者分成 `KeyError` 与 `PermissionError`——
那是**模块内诊断用**。到 HTTP 边界合成一句 404 一个码
（变异⑨ 改 403 红 5 个，变异⑩ 让两种 404 走不同路径也红）。

## 7. 登记未做与两处判断

1. **没挂进任何 ASGI 应用**。BE-01~08 八张卡同一件待办。
2. **响应里不回 `owner`**。调用方就是 owner，回给他自己没有信息量；
   而一旦回了，就多了一条「把别人的 id 带出去」的路（变异⑱ 钉住）。
   判据比对冻结件字段集时显式减去 `owner`。
3. **「查看当时版本」没做端点**。`original_snapshot` 已经在 `stale.py` 里，
   卡面五个动作里**没有它**（列/加/删/看陈旧/更新到最新）。
   接一个 `GET /favorites/{id}/original-snapshot` 是一行的事，但那是卡外的第六个动作，
   按 §六.1 不顺手加——登记在此，UI 卡若要「查看当时版本」按钮，需补一张卡。
4. **DELETE 幂等到 HTTP 层变成 404**。`remove_favorite` 本身仍是幂等的（返回 False 不抛），
   端点先判归属，不存在 → 404（acceptance⑤「只有真正未知的 id 才 404」）。
   连删两次时第二次是 404，这与「不存在的 id」是同一句话，符合 404 不泄露存在性那条。
5. **`project_id_for` 是注入点**。判陈旧要 project_id，而冻结件 `Favorite`
   **没有这个字段**（它只有 target_kind/target_id）。真接线要从 target 反查所属项目——
   `cluster`/`topic`/`deliverable`/`card` 四种目标各有各的查法，属另一张卡。
   **NEVER 在这里猜一个 project_id**。
6. **批量动作（`flint/fav/batch.py`）没接**。卡面五个动作里没有批量；
   `batch_add_to_workbench` / `batch_remove_favorites` 仍零出口，登记。
