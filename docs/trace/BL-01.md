## 4. 两种写法，判据只有一条

| 写法 | 例 | 值 |
|---|---|---|
| 算术式（含位字 十/百/千/万/亿） | 二十六 / 一百零五 / 一亿二千万 | 26 / 105 / 120000000 |
| 数位串式（不含位字） | 二〇二六 / 一九九八 | 2026 / 1998 |

按哪一种读，只看串里**有没有位字**。混起来的后果很具体：把「二〇二六」按算术式读
会得到 **6**（2+0+2+6 相加更离谱），拿这个数去卡原文里找，找不到就报「疑编造」。

「零」在算术式里是**占位**：一百零五 = 105，不是 1005。

## 5. 解析器与扫描器分开

**解析器**（`parse_cjk_numeral`）只管读：给它「千万」它就读成 10^7，因为那确实是一种读法。
**扫描器**（`find_cjk_numerals`）判「这一串在正文里到底是不是个数」，两条判据：

| 判据 | 挡掉的 | 为什么 |
|---|---|---|
| 首字必须是数位字或「十」 | 万一 / 千万 | 位字开头的是词。「一万」是数、「万一」是词，差别只在顺序 |
| 孤零零一个字要带量词 | 这**一**趋势 / **三**者之中 | 代价是「三者」这种真数字被放过；收益是不会把遍地都是的「一」变成检查项 |

首版把「必须含数位字」写进了**解析器**，于是 `parse_cjk_numeral("十")` 返回 None——
而「十」就是 10。**读得出与该不该算，是两个问题**；混在一处的结果是解析器替扫描器
做了决定。拆开后两边各自可测，也各自可改。

## 6. 解不出 NEVER 猜（acceptance②）

「两 / 俩 / 廿 / 卅」本器读不出：「两千三」这类省略式读法不唯一，猜就是替作者决定。
读不出返回 `None`，但**它们照样进检查面**——`raw` 是原文，上层只能靠原文比对。
静默跳过 = 正文里一个没出处的数字溜过去（卡面原话）。

`test_an_unreadable_chinese_numeral_reaches_the_checker_with_no_value` 守着这条：
`extract_numbers("增长廿六%")` 交出 `("廿六", "quantity", None)`。

## 7. 撞上一个既有缺陷：`"" in "%％"` 是 True

写 acceptance③ 的阴性对照时，`("1998 与 2026", 两个都是 year)` 这一条红了——
实测第二个是 `quantity` 且 `is_percent=True`。

根因在既有代码：`tail = text[m.end():m.end()+1]` 在**正文以数字结尾**时是空串，
而 **Python 里空串是任何字符串的子串**——`has_unit` 与 `is_percent` 一起变成 True。
后果两条，都是**放松**：年份落进 quantity 后 `_check_date` 收不到它；
`is_percent` 让 `_number_present` 多试一个 `value/100` 的比对形。

**没有顺手改**：acceptance③ 原话是「既有阿拉伯数字路径**逐字不变**」。
改这一行会翻转「正文以数字结尾」的所有既有判定，影响面要重跑接地校验全部用例
与金标集才说得清。登记在 `docs/blocked/GROUNDING-EMPTY-TAIL.md`（含复现与一行修法）。

**新写的中文那条路没有照抄这个写法**（照抄最省事，两处逻辑长得一模一样），
两条测试各守一边：`test_a_number_at_the_very_end_is_still_misread_as_a_percent_quantity`
钉住现状（修好那天它会红，提醒删它）、`test_the_new_chinese_path_does_not_inherit_that_bug`
钉住新路没继承。

## 11. 登记未做

1. **小数点（「二点五」）不支持**：`点` 不在数字串字符集里，所以「二点五」会被切成
   两段，而两段都是孤零零一个字 → 都不进面。卡面要求的是十/百/千/万/亿位与混排，
   小数属另一形。**这是一个静默漏**，与 acceptance② 的精神相抵，如实登记。
2. **「三成」「两成」不支持**：`成`（十分之一）是量词也是位，本器不认。
   「两」本来就解不出，「三成」会被判成孤字+量词？——`成` 不在 `_QTY_TAIL` 里，
   所以「三成」整个不进面。同 §11-1，是漏不是错判。
3. **序数与编号不区分**：「第二十六条」里的「二十六」会被当成数量去查出处。
   要分清得看「第」字前缀，本卡未做。
4. **`_corpus_numbers` 只扫阿拉伯**：卡原文里若写的是中文数字，容差比对那一路
   找不到它（字面比对仍然有效）。补它要动既有函数，超出「只加不改」。
