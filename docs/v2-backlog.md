## V2-001 · 全球版：多地区 / 多语言 / 分地区数据源

- **登记**：2026-07-30，owner 明确指示（本条由监管 agent 按 owner 侧输入写入，非执行 AI 产出）。
- **状态**：V2 backlog（NOT V1 scope；不进 tasks.json 关键路径）。

### 愿景
把 Flint 从"中文单市场"扩成**可推广到世界各地的版本**:按**每个具体地区**分析**该地区的**热点,受众/语言分叉——
- 中文 → 分析中国市场;
- 英文 → 分析澳洲 / 美国 等英语市场;
- 结构上可继续扩到任意地区(每地区一套口径)。

### 为什么"等 V1 结束再扩"是安全的(架构已留缝,非重写)
监管 agent @2026-07-30 核过冻结件,确认多地区维度**在契约层已是一等公民**:
- `contracts/models.py`:多个实体带 `locale` / `region` / `lang` 字段(第 58/278/289/296/602/684/883/898 行等);
- 第 602 行设计注释:**"规则表按 locale 分别维护,非翻译"**——一开始就是"每地区一套规则"的设计,不是把中文翻成英文;
- `contracts/protocols.py:68`:协议方法带 `locale` 参数;
- `flint/sources/registry.py`:热点源为**可插拔注册表**(source_id → 工厂,`source_{id}_enabled` feature flag 启停)——**加地区专属源 = 注册一个新源,不动主干**。

结论:最贵、最难回头的"架构留缝"已完成。V2 是**往已留插槽里加东西**,不是推倒重来。故推迟到 V1 之后**零架构惩罚**。

### V2 scope 草图(全部为扩展,非重写)
1. **分地区数据源**(owner 明确要求):不同地区/语言用**不同数据源**。现 4 源中 `weibo` 为中国特有;V2 按 locale/region 注册地区专属源(例:美/澳的地区趋势与本地社媒源),复用现有 `SourceRegistry` + feature flag,按 locale/region 参数化启停。**每地区一套源清单**。
2. **分 locale 规则表**:relevance / competitor / gate 等规则按 locale 分别维护(契约注释已预留),V2 填充各 locale 规则表。
3. **分语言生成 + 模板变体**:英文计划书模板等(受众分叉机制已在);内容由 LLM 按目标语言生成。
4. **分 locale 模型路由**:接入多提供商选择器(见 V2-002),按语言/地区选模型(如中文用 Qwen/Kimi、英文用 GPT/Claude)——与全球版天然互补。
5. **前端 i18n**。

### V1 实现层护栏(便宜保险,不新增 V1 工作量)
V1 写 prompt / 模板 / 相关性判断时,**在数据模型已给 locale 字段的地方 NEVER 硬编码 "中文/zh/微博" 假设**——尊重契约已留的 locale 缝,保证 V2 是干净扩展。

### V2 启动前待 owner 裁决的开放问题
- 首批扩哪些地区(澳/美优先级)?
- 各地区数据源清单 + 当地数据/合规约束?
- 分 locale 的模型映射(哪语言用哪模型)?
- 定价/额度是否按地区分层?
