## 二、逮到两条真缺陷，各开一单（都不是本批引入的）

**① 重写作业不写事件、也不推状态**（`REGENERATE-JOB-WRITES-NO-EVENTS.md`）
作业跑完了而 `jobs.state` 仍是 `queued`、`job_events` **0 行**。
既有的 `InstructionRegenerateBox` 正是靠订阅事件流收尾的——照着用，屏上会一直转。
这就是本仓点名要防的那一族病（「失败不写事件、屏上一直转圈」），这一条更进一步：**成功也不写**。

**② 项目总览列不出它自己的产出**（`PROJECT-DOES-NOT-LIST-ITS-OWN-DELIVERABLES.md`）
我为①写的绕行是「轮项目的交付物清单，新出现的那一份就是产物」。
**实测那条路也不通**：`projects.deliverable_ids` 是建项时写死的一列，
组稿与重写落库都不回写它——库里四份，那一列一条。取证里那一格
（`projectListChanged: False`）就是证据。

于是今天从「我提交了重写」到「产物是哪一份」**三条路全断**：
作业不写状态与事件 · 端点不回产物 id · 项目总览列不出新产出。

## 三、落盘的那一版：只说到「已提交」为止

屏上写清**改的是哪一块**与**批注是什么**，作业 id 留在 `data-*` 上，
「好了没有」一个字都不说——说不出来的事 NEVER 编一句像样的话糊过去。
`onNewVersion` 那条缝留着并写明今天没有调用点：解阻那天接回来的就是它。

**NEVER 由 `{原id}-r-{作业id}` 拼一个出来**：那个形状在库里确实成立，
但它是实现细节。**取证可以这么做**（它是在核实一件刚拿到的事实），
产品不行（它那时候是在猜一个不知道的 id）——这条分界写在探针注释里。

## 四、三处刻意与既有件/蓝本不同

| 处 | 本仓 | 为什么 |
|---|---|---|
| 没直接用 `InstructionRegenerateBox` | 只复用它复用的那两样（保护门 `availableBlockInterventions` + 端点客户端 `regenerateBlockWithGuidance`） | 它靠事件流收尾，而这一族作业不写事件 |
| 蓝本每块旁边一个批注按钮 | 点选一块 + 一个面板 | 块由 `BlockTree`/`BlockView` 渲染，那是 v0.4 封版件（`DEC-021`），往里塞控件要停下报 owner |
| 蓝本模板下拉旁的模型/档位选择器 | **不做** | 一律免费本地档；摆一个能选中付费档的下拉等于把 `S2-10` 那道人审节点交给用户点 |
