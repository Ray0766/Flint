## 3. 三处泄漏（acceptance①）

终检实测的三个 key 在两份词条里**都不存在**，`t()` 按 DEC-009 返回 key 本身，于是：

| 位置 | 用户实际看到 | 本卡补的文案（zh / en） |
|---|---|---|
| `QuoteSlot` 展开按钮 | `quote.expand_original` | 展开原文 / Show original |
| `RegionSwitch` 选择器标签 | `settings.region.label` | 地区 / Region |
| `NativeName` 机翻标记 | `card.name.translated_mark` | 机翻 / MT |

**前两处是该元素里唯一的文字**——按钮和标签整个显示成了变量名。

补法：两侧同时补，键集从 130 → **133 且仍逐个对称**。文案口吻照既有条目
（`block.action.dispute` = 争议/Dispute 这一档：短、动宾、无标点）。
三条断言分别挡三种「补了等于没补」：补空串、把 key 当文案、把中文抄进 `en.json`

**组件源码一个字节未改**：它们引用的 key 名本来就是对的，缺的一直是定义。

## 4. 尺子（acceptance②）：`tools/i18n_key_defined.mjs`

扫全部 `t("…")` 调用，逐个比对 `zh.json` 与 `en.json`，**缺任一侧即红并点名 key + 文件行号**。
只说「有 key 缺定义」等于把定位活退回给人，所以报告逐行给位置。

四条判据边界，每条都有理由：

1. **两侧都要有**——只在 zh 里有，英文用户照样看到变量名；
2. **测试文件不算**——`t()` 的缺键路径本来就要拿一个不存在的 key 当夹具（`nope.key`）。
   把夹具算成缺陷，等于逼测试删掉自己的反例，而那条反例守的正是 DEC-009。
   （与 `no_hardcoded_models.mjs` 的「测试文件不算」同一条口径。）
3. **定义了却没被引用的键只报不判红**（13 个）——F-10 原话「不是缺陷，是清理线索」。
   判红会逼人删掉将来要用的文案，或者反过来给不用的键硬造一个引用；
4. **动态 key 按前缀判**——见 §5。

## 5. 实测逼出来的第四档：动态 key

第一版扫出 **5 处**缺定义，除终检点名的三处外多了两处：

```
✗ web/components/graph-roles/GraphRoles.tsx:63     graph.role.${role}
✗ web/views/workbench-tabs/WorkbenchTabs.tsx:55    workbench.tab.${tab}
```

回源一看是**模板字面量拼出来的 key**，而它们的候选都在：
`graph.role.` 下有 5 个（primary/secondary/auxiliary/demoted/failed）、
`workbench.tab.` 下有 2 个（graph/tree）。**这两处是合法的，报成缺失是我的假红。**

修法不是「跳过含 `${` 的 key」——**跳过等于给自己开一个盲区，而盲区正是这把尺子要治的病**。
改成按**静态前缀**判：`graph.role.` 下两侧各要至少一个定义；一个候选都没有 = 真泄漏，判红。
两个方向都配了测试：仓库里那两处必须被认成 `dynamic` 而不是 `missing`（正向），
构造一个 `nothing.here.${x}` 必须红（反向）——**没有反向那条，正向那条就等价于「动态 key 一律放行」**。

顺带修了「未引用键」的口径：动态前缀下的键（`graph.role.*` 那 5 个）**算被引用**，
否则它们会被报成「定义了没人用」，而删掉它们界面当场就坏。未引用键因此从 18 → 13。

## 6. DEC-009 不许被改掉（acceptance③）

`web/lib/i18n/t.ts:36-37` 缺键时 `console.warn` + `return key`。终检原话：
「这条设计救了这次——正因为它显眼，才被我一眼抓到」。
空串会变成界面上一块**无声的空白**，没人会发现。
本卡把这条行为钉成断言（返回 key、有 warn、**无任何返回空串的路径**），
防止将来有人为了「把界面弄干净」顺手改成空串。**`t.ts` 一个字节未改。**
