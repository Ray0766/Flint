## 三类是什么意思

| 类 | 含义 | 处置 |
|---|---|---|
| **还能用** | 口径自洽、判官一致，**或根本没有判官** | 照用 |
| **需重判** | 判官不同或口径已变，但被判的东西还在 | 用 DeepSeek 重判，新值另存 |
| **只能作历史** | 口径已变、或被判的东西已不在 | 留作历史，**说清为什么不可比** |

**「没有判官」也是一种自洽**：`goldcases.json` / `golddocs.json` 是 fixture 脚本
构造出来的**期望值**，不是谁判出来的。把它们当判定结论去重判，
重判出来的东西会顶掉本来当基准用的那份——这是本卡最容易做错的地方。

**本卡 NEVER 改任何阈值**：只对齐口径、产出对照。调线是 CAL-02 与 Z-01 的事。
四个现存阈值（`CHECK_ANSWER_LINE` / `THETA_REL` / `Z_LINE_INITIAL` / `EXIT_LINE`）

## 三件从这张总账里看出来的事

1. **「判官判出来的数」比看上去少得多**。31 项里真正有判官参与的只有 12 项，

2. **有两份产物是逐字节重复的**：`qwen3_30b.v3-backup.json` 与
   `v3_no_spec/qwen3_30b.json` 的组稿产物与 `qwen3_30b.json` 完全相同。
   先按内容指纹去重再重判，**省下的是两次 258 条的钱**。
3. **有一份永远补不回来**：`gemma4_26b.json` 里没有 compositions——
   被判的东西已经不在盘上。它的数只能作历史，**任何重判都做不到**。
