## 2. 它与报告**必须长得明显不同**（清单第 31 条）

> 「它是给 AI 执行的包，排版上是否与给人读的报告明显不同？」

报告是给人读的散文；vibe_pack 是**喂给执行者的材料**。两者长得一样的话，
用户会把包当报告读（读不下去），或把报告当包喂（喂进去的是散文）。

所以这一屏的形态是**清单不是文章**：

- 九章走 `<ol>` 逐条列，**正文一律 `<pre>`**——这些字是要被逐字复制走的，
  排版上的每一次「美化」都会改到它；
- 任务清单走 `<table>` 逐行列；
- 冻结件逐个带 sha256（包里那份与仓里那份对不对得上，靠的就是它）；
- 屏上明说「这份材料是给 AI 执行者的」。

判据除了看这些结构，还判**两屏不共用呈现组件**
（`test_the_pack_viewer_shares_no_component_with_the_report`）——
共用的那天它们就会长得一样。

**NEVER 合成「完整度 8/9 章」**：BE-02 的原话——章节数是**计数**不是分值，
少一章是内容问题，不是「完成度 89%」。

## 3. Human Digest 带着「不进 AI 上下文」的标记

BE-02 的响应里 `human_digest.for_ai_context === false`
（`pack_assemble` 原话「NEVER 并入 markdown」）。它是**监工视图**，与九章不是一回事。

前端把这条标记**显示出来**，且在结构上把 digest 放在九章那个 `<ol>` **之外**——
不显示、不分开的话，用户会把它和九章一起复制走喂进上下文。

## 4. 三种「没有」

| 状态 | 屏上 |
|---|---|
| 没查过（端点未装配） | 执行包接口未提供 |
| 查过了、还没生成（BE-02 的 `not_generated`，**不是 404**） | 这份交付物还没有生成执行包 |
| 生成了 | 九章 + digest + 任务表 + 冻结件 |

判据钉住「还没生成时**不画九章骨架**」——画了就等于冒充生成过。
