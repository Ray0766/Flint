## 1 为什么这张卡压在那一次点头之前

**录制不可逆、灌库可重来。** 灌库那一步失败时，人最可能做的事就是**再抓一次**——
而再抓一次就是再一次真实外网抓取。

而完成态报告那句「跑完广场上那些 `热搜话题NN` 就换成真热点了」**多说了一链**：
抓成了、灌成了、**屏上还是合成词面**——这三件事今天在屏上长得一模一样。
owner 抓到的正是这一层。

## 2 灌库命令：三处，逐条

改前（文件头第 33~37 行）：

```
python -c "import asyncio;from datetime import date;from pathlib import Path; \
from flint.jobs.ingest import build_replay_deps,run_daily_ingest; \
asyncio.run(run_daily_ingest('cn-01-real', {'day': DAY.isoformat()}, \
  build_replay_deps('postgresql://flint:flint@localhost:55432/flint', Path('fixtures'), DAY)))"
```

| # | 毛病 | 后果 |
|---|---|---|
| 1 | **`DAY` 没有定义** | 贴上去当场 `NameError` |
| 2 | **第二参传成字典** | `run_daily_ingest(job_id, day: date, deps)` 要 `date`。仓里另外三个调用点（`replay30.py:139` · `drill7.py:90` · `worker_main.py:196`）**全传 `date`**，只有这条文档里的例外 |
| 3 | **反斜杠续行** | POSIX shell 的写法，**在 PowerShell 里当场断句**——前半行先跑，后半行变成一条新命令，而报错读起来像 Python 语法错 |

改后**两条**（都是一整行，内层全单引号、外层双引号，PowerShell 整行粘贴）：

```
python -c "import asyncio; from datetime import UTC, datetime; from pathlib import Path; from flint.jobs.ingest import build_replay_deps, run_daily_ingest; d = datetime.now(UTC).date(); print(asyncio.run(run_daily_ingest('cn-01-real', d, build_replay_deps('postgresql://flint:flint@localhost:55432/flint', Path('fixtures'), d))))"
```

```
python -c "import asyncio; from datetime import date; from pathlib import Path; from flint.jobs.ingest import build_replay_deps, run_daily_ingest; d = date.fromisoformat('2026-06-24'); print(asyncio.run(run_daily_ingest('cn-01-real-20260624', d, build_replay_deps('postgresql://flint:flint@localhost:55432/flint', Path('fixtures'), d))))"
```

`d` 取 `datetime.now(UTC).date()` 而不是 `date.today()`：**与录制器 `--day` 的默认值同源**。
两处各取各的话，跨日的那几个小时里**录进去的文件名与灌库要的那一天对不上**，
而那时屏上只会说「这一天没有数据」。

## 3 广场默认日：落在库里最新有数据的那一天

改前 `web/app/plaza/page.tsx`：`params.get("day") ?? "2026-07-04"`。
**实测 demo 库里已经有 `2026-07-05`（107 条）**——那个写死的默认**今天就已经在显示旧的一天**。

### 3.1 为什么是「往回走」而不是问一条端点

今天**没有任何端点回「最新有数据的那一天」**（逐条看过 `flint/api/views.py` 的
八条 GET：`/plaza/hot` 必须带 `day`，`/plaza/topics` 与日期无关）。
加一条那样的端点要动 `flint/api/`，**而那不在本卡 outputs 里**。

所以从今天往回一天一天问，**第一天问到东西就停**：

- **上限 41 天**（`fixtures/` 现有回放窗口 34 天 + 一周余量）——
  **NEVER 无上限**：库真的空着时那会变成一个看不见尽头的请求串，而屏上什么都不说；
- **单独一天问不到就往前再问一天**：一次网络抖动 NEVER 变成「库里没有数据」；
- **代价说清楚**：库里最新数据离今天越远，首屏多发的请求就越多。
  `CN-01` 点头、真实抓取跑起来之后**今天就有数据**，这里恒是 1 次。
  想把它变成 1 次常量，就给 `/plaza/hot` 的响应加一格「最新有数据的那一天」——
  留给某张 outputs 含 `flint/api/` 的卡（§7）。

### 3.2 三种来源，屏上说得出口

| `data-day-origin` | 什么意思 |
|---|---|
| `url` | 用户自己指定的（`?day=`，`REGION-10`：URL 是当前视图的真相） |
| `resolved` | 库里最新有数据的那一天 |
| `fallback` | **一天都没问到**，落到兜底——屏上明说「它**不是**今天的热点」 |

acceptance⑤ 的「明说」不是一句形容：安静地显示另一天的数据，
用户会把兜底那天的热点**当成今天的**去做判断。

### 3.3 acceptance⑦ 的阴性对照：打真库 + 真浏览器

```
库里 max(day) = 2026-07-05          （> 写死的 2026-07-04，阴性对照的地基）
屏上 data-day-origin = resolved      （不是 fallback、不是 url）
屏上 meta 日期      = 2026-07-05
屏上文案            = 正在看 2026-07-05 的热点
```

**NEVER 只断言「代码里没有那个字面量」**——换成另一个字面量之后那句话也成立。
所以先有一条判据钉住「库里确实有比 `2026-07-04` 更新的一天」（阴性对照的地基），
再由真浏览器判首屏落在**那一天**。
