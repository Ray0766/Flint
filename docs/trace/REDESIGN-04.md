# REDESIGN-04 · 补暗色四屏（@2026-11-14）

`REDESIGN-03` §七欠着的一项：演示串屏、模板工具、干预页、导出页在暗色下没看。
owner 在那一卡收尾时点的下一步就是这一项。

## 一、装载清单

`docs/trace/REDESIGN-03.md` §四、§七 · `web/app/redesign.css` · `tests/v041/test_redesign_layer.py`。
真栈（`localhost:3000`），浏览器暗色模拟（`prefers-color-scheme: dark`），1920×1080。

## 二、怎么看的

每屏两步：先截图看，再在页面里跑一段脚本——遍历正文区每个文字节点，取它的文字颜色与
往上找到的第一个不透明底色，算对比度，报最低的几项。提示语不是文字节点，另用
`getComputedStyle(el, "::placeholder")` 量。

## 四、量到的一处问题（修了）

**模板工具输入框的提示语是 `rgb(117, 117, 117)`**——Chrome 的默认值，不是本仓的 token。

| | 修前 | 修后 |
|---|---|---|
| 暗色，底 `rgb(19, 20, 24)` | 3.99（不到 4.5） | 6.35 |
| 亮色，底 `rgb(255, 255, 255)` | 4.61 | 5.76 |

修前那两个数是拿量到的颜色算出来的；修后是在浏览器里重新量的。
默认灰不随主题变，所以它在一个主题里勉强够、在另一个里不够。

修法：设计层加一条通用的 `::placeholder { color: var(--ink-3); opacity: 1; }`。
工作台的假设输入框（`.wb-composer__input`）修后量到的也是 6.35 / 5.76；
**它修前是多少没有量**——我是先加了规则才想到去量它的。它没有自己的提示语规则，
按理与模板工具那个框同病，但这句是推断。

干预页那个框在 `REDESIGN-03` 里已经单独写过提示语颜色，暗色下量到 `rgb(145, 152, 166)`，本来就是对的。

## 五、判据

`tests/v041/test_redesign_layer.py::test_placeholder_text_takes_its_colour_from_the_palette`，先写。

- 第一版写错了：借用了文件里现成的 `_block`，而它只认 `--token` 声明，并且会匹配到干预页那条
  `…textarea::placeholder`。那一版是红的，但加了规则之后仍会是红的——红的原因不对；
- 改成只认整行就是 `::placeholder` 的那条规则。改后：没有规则时 `1 failed`
  （「设计层没有通用的 ::placeholder 规则」），加了规则 `12 passed`。

`--ink-3` 对三种底色的对比度由同一份文件里的 `test_text_on_its_background_is_readable` 在两个主题下守着，
所以这条哨兵只需要守「提示语用的是它」。
