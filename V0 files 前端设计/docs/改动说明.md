# 我改了哪些文件，为什么

范围：只动「V0 files 前端设计」内的文件 + `harness/demo_server.py` 的挂载胶水 + 一个新的
harness 夹具脚本。**`contracts/` 与任何 flint 端点的响应形状一个字没动**；`web/` 一个字没动。

---

## 一、后端侧（只碰第 2 层胶水，共 2 个文件）

### 1. `harness/demo_server.py` — 挂上 deliverables app
**改了什么**：`import` + `create_deliverables_app(DeliverableApiDeps(dsn=DSN))` + 加进
`include_router` 循环；改了文件头注释。
**为什么**：报告 L0 屏的读契约是 `GET /deliverables/{id}/blocks`（M3-058），端点在
`flint/api/deliverables.py` 里**本来就存在**，只是 demo 后端没挂 → 前端只能拿 404。挂载属于
你划的第 2 层（胶水/静态挂载），**不改任何端点的响应形状**。
**顺带说明**：`flint/api/compose.py`（report/proposal 提交）**故意没挂**——demo 没有 report
worker，挂了只会造出永远 `queued` 的 job，那是假连通。
**CORS**：原来就是 `allow_origins=["*"]`，:3001 天然放行，**没改**（已用预检实测确认）。

### 2. `harness/demo_seed_report.py` — 新增，报告夹具（opt-in）
见「待你定夺 ①」。不跑它，前端就如实显 404。

## 三、三条铁律怎么落到代码里

1. **不造假数据**：前端没有任何兜底常量。`lib/mock/*` 与业务屏彻底断开；后端 404/空数组/
   缺字段一律走各自的诚实态文案。验证脚本里专门有 `unseen()` 反向断言——错误态时**不许**出现
   空态文案，未生成时**不许**出现 mock 正文。
2. **不压诚实态**：`speculative / needs_review / D_insufficient / gap_notice / degraded /
   disputed / EXPORT_BLOCKED / 5xx` 逐个有屏、逐个有断言（`degraded` 因无屏而如实登记为待办）。
   保护块是**不渲染控件**而不是 disabled。
3. **前端零判定**：档位、门禁、热度排序、缺口清单全部直取后端。`ReportShell` 不再自己判"能不能
   导出"，`GateLive` 不自己推进度。
