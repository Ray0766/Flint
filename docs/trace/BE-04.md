## 2. 本卡只做三件事：转调、拼装、如实报

acceptance② 原话「陈旧判定**委托既有 Revalidator**，NEVER 在端点里再写一份
（同一件事两个真相是本项目的老病）」。`stale_adapter` 自己的 docstring 把后果写死了：

> 再写一套的后果不是重复劳动，而是同一份分析在两个地方被判成不同的新旧：
> 收藏页说它陈旧、分析页说它是最新的，用户不知道该信哪个。

于是三条线全部转调：

| 要答的 | 转调 |
|---|---|
| 陈旧不陈旧、多严重、哪几条事实 | `flint/analysis/stale_adapter.py#analysis_stale` |
| 下次该重核的日子 | `flint/revalidate/schedule.py#next_due_on` |
| 有没有事件触发（含 14 天去重窗口） | `flint/revalidate/events.py#derive_event_triggers` |

**判据不止查「函数在不在」**——那太容易骗过（照抄一遍再顺手调一次也能过）。
判据同时断言模块里**没有严重度字面量**（`"blocking"` / `"advisory"` 一个都不出现）、
**没有年龄阶梯的天数**。抄一份最坏的形态不是抄错，是**日后只改了一处**：
阈值改了 `schedule.py`，端点还按旧天数报到期。

## 3. 三个语义分界（都是本轮反复出现的同一条）

### 3.1 陈旧不隐藏内容，也 NEVER 出「已隐藏」开关

acceptance③ = DESIGN-12 既有纪律（失锚仍可见）。在本端点上的形态是：
**陈旧的交付物与新鲜的交付物，响应形状逐字相同**——只有标记值不同。
少给一个键，就是「因为旧了所以不给你看」。

本端点根本不返回正文，所以更进一步：**连一个 `content_hidden` 之类的开关都不给**。
有那个开关，就迟早有人照它把内容藏起来。变异⑩（陈旧时少给 `fact_ids`）
与变异⑪（加一个 `content_hidden: false`）分别钉这两头。

### 3.2 「没判过」与「判过、不陈旧」分得开

版本信息缺失时**不报 fresh**——报 fresh 等于告诉用户「这份是最新的」，
而我们根本没能力知道（`flint/fav/stale.py#StaleNotEvaluated` 就是这条）。
`status: "not_checked"` 时**连 `stale` 这个键都不给**（给一个 `false` 它就还是个答案）。

这是本轮第四次出现同一形状：DOC-01 的 `content=None`、PAY-02 的「配成 0 与没配」、
PAY-01 的「实读与未读到」、BE-03 的「没解引用器时不报 0」。

### 3.3 不可重核要说**为什么**

只给一个 `can: false`，用户不知道该怎么办。两种不可重核给两句不同的话：
没记版本那句说的是「重核跑出来的东西无从与旧结果对比」，
没到期那句说的是「还没到期，也没有事件触发」。变异⑫（把 reason 清空）钉住它。

## 4. 一次冻结件教训

`_diff()` 辅助函数第一版按记忆写了 `added=[...]`——**`FactDiff` 只有三项：
`changed` / `removed` / `disputed`，没有 `added`**。读真件后改掉，
并在辅助函数上留了一行注释写明这件事，免得下一张卡的人再犯。

（BE-03 记了三处同类，本卡一处。形状一样：**按记忆造字段名**。）

## 7. 登记未做

1. **没挂进任何 ASGI 应用**。与 BE-01/02/03 同——装配超出本卡 outputs，
   **前端那条「陈旧/重核横幅位」现在仍拿不到数据**。四张卡的装配是同一件待办。
2. **`load_staleness` 没有真实实现**。真接线要一次查齐：`deliverables`（owner / project_id /
   `analysed_at_version` / 建档日）· 账本当前版本 · 该交付物引用过的 fact_id ·
   簇的 flags 与动量 · 新增强驳文档 · `revalidation_triggers` 近 14 天记录。
   **NEVER 拆成多次查询**——两次查询之间账本会前进，那时算出来的判定
   对应两个不同时刻的库，而它看起来像一次判定（`DeliverableStaleness` docstring 记了这条）。
3. **只报「该不该重核」，不发起重核**。真正的重核是写操作 + 长任务，
   要走 job 状态机，属另一张卡；本端点 acceptance④ 明写只读。
4. **去重窗口传的 deliverable_id 是空串**。`derive_event_triggers` 去重比的是
   `(id, kind)`，本端点只处理单个交付物，两边统一传空串等价于「只按 kind 去重」。
   真接线时若要跨交付物去重，这里得改成传真 id。
5. **`recent_triggers` 的第一项（doc_id）本端点没用**。保留在类型里是为了真实现
   直接把库里那行塞进来，不必在调用方先削一遍。
