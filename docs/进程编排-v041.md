# 进程编排 · 本机（SHIP-02 @2026-08-04）

**本文只管本机。生产部署需 owner 人工确认**（S2-10 红线）——本文**不写**任何
可照做的生产部署步骤：那份文档一旦存在，就会有人照着做，而那一刻红线已经被越过了。

## 改之前是什么

demo 此前用的是 `harness/demo_server.py` 里 `asyncio.create_task(_run())` 的**临时钩子**：

- 作业在 **API 进程里**跑，队列形同虚设；
- 关掉 API 窗口，正在跑的作业就没了，而 `jobs` 表里它还写着 running；
- **cron 一次都没触发过**——日更批与复核扫描的时刻定义在
  （`flint/jobs/sched.py#CRON_BATCHES` / `flint/jobs/revalidation.py#SCAN_HOUR`），
  但没有任何进程按它走。

本卡把 `flint/jobs/worker_main.py#build_worker` 与 `flint/jobs/cron.py#build_cron_jobs`
接成一个可独立起停的进程（`harness/run_worker.py`），并让起停脚本带上它。

**那条临时钩子没有删**：demo_server 仍能单独跑（不起 worker 时它照旧工作）。
两条路并存是有意的——先有一条能跑的，再有一条对的。

## 四个进程

| 进程 | 职责 | 端口 | 谁起的 |
|---|---|---|---|
| **postgres** | 所有持久状态（簇/卡/作业/账本/交付物） | **55432** | `docker compose up -d` |
| **redis** | arq 队列 + 分布式锁（`lock:daily_ingest:*` / `lock:revalidation:*`） | **56379** | 同上 |
| **api** | 读端点 + 提交端点（`harness/demo_server.py`） | **8000** | `start-demo.ps1` 起独立窗口 |
| **worker**（含 cron） | 消费作业 + 定时批（`harness/run_worker.py`） | 无监听端口 | `start-demo.ps1` 起独立窗口 |

前端（Next dev，**3000**）不算后端进程，但起停脚本一并管。

## 起停顺序，以及**为什么**是这个顺序

**起**：`postgres` → `redis` → `api` / `worker`（后两个无先后）→ 前端。

- postgres 最先：api 与 worker 启动时都要连它，连不上就直接退；
- redis 在 api 之前：api 的提交端点要把作业推进队列（`build_enqueue_hook`），
  队列不在时提交会失败，而失败发生在**用户点了按钮之后**；
- worker 与 api 无先后：worker 消费的是队列里的东西，晚起只是晚跑，不会丢
  （**这正是把作业从 API 进程里搬出来的收益**）。

**停**：前端 → api → worker → redis → postgres（起的逆序）。

- worker 在 redis 之前停：先停 redis 的话，worker 会开始刷连接错误日志；
- postgres 最后停：worker 收尾时可能还要写一次作业状态。

`stop-demo.ps1` 用 `docker compose stop`（**不是** `down -v`）：容器停下、端口释放，
数据卷 `pgdata` 完整保留。

## 失败征兆 → 是谁没起来

| 症状 | 多半是 | 怎么确认 |
|---|---|---|
| 任何页面 500，日志里 `connection refused ... 55432` | **postgres** 没起 | `docker compose ps` |
| 提交按钮点了报错，或作业永远停在 `queued` | **redis** 没起 / **worker** 没起 | `docker compose ps`；查有没有 `harness.run_worker` 进程 |
| 前端整屏空白、控制台 `Failed to fetch` | **api** 没起（:8000） | 浏览器直开 `http://127.0.0.1:8000/plaza/hot?day=…` |
| 作业状态一直 `queued`，队列里却有它 | **worker** 没起（只有它会取） | 任务管理器里找 `harness.run_worker` 的窗口 |
| 日更批/复核扫描到点没动静 | **worker** 没起（cron 挂在 worker 上） | worker 窗口里应有 `[flint cron]` 行 |
| 页面中文变成乱码 | 脚本掉了 UTF-8 **BOM** | `tests/v041/test_orchestration_doc.py` 会红 |

## 幂等

- **api**：先探 `:8000`，通了就复用；
- **前端**：先探 `:3000`，通了就复用；
- **worker**：没有端口可探，按**命令行标记** `harness.run_worker` 查重——
  查到就复用，**NEVER 起第二份**（同一队列两个 worker 不会出错，但 demo 面不需要，
  而两个窗口会让「哪个在跑」这件事变得没法回答）。

停脚本按**同一个标记**认人：两边用不同标记，就会关不掉自己起的那个。
**按标记停而不是按进程名停**——按 `python.exe` 停会连别人的 python 一起杀。
