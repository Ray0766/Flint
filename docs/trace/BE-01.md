## 2. 补的是蓝本自己标出来的那个洞

## 3. 四条不肯含糊的地方

1. **越权返回 404 而不是 403**。403 等于告诉对方「这个 id 存在，只是不给你看」——
   **状态码本身就泄露了存在性**，还能被用来枚举 id。
   实现上不是「查到了再判归属」，而是把归属**写进那条 SQL 的 WHERE**：
   owner 不符与不存在**得到同一个结果**（`row is None`），走同一条出口、
   连错误码都一样（与 `deref.py` 同一条口径）。
2. **空态与错误态分清**。项目在、但一个 topic 都没有 → 返回**空数组**，不是 404。
   空数组说的是「查过了，没有」；404 说的是「没这个东西」。混在一起时，
   用户看到 404 会以为自己的项目丢了。三个列表**恒存在**——
   没有内容时是 `[]`，不是缺这个键。
3. **只读**。模块里只有 `SELECT`。判据在 **AST 去掉 docstring 之后**扫写库动词——
   注释里解释「本端点只读」不算写库（本轮反复撞到的那个形状，这次一开始就避开）。
4. **NEVER 造字段**。判据把返回的每个键与 `information_schema.columns` 对一遍；
   另有一条专门挡「完成度 60%」这类**前端最想要、后端算不出**的合成值
   （没有总量、没有权重口径，给一个就是编）。

**作业另带一层 owner 过滤**：项目归你，**不代表它下面每条作业都归你**。
判据构造了一条别人的作业挂在同一个项目下，断言它不出现在结果里。

## 4. 判据先红，然后被库的真类型教了六次

本卡没有改既有文件，但**播种数据踩了六层**，每一层都是「库没备齐」而不是断言不过：

| 撞到的 | 真相 |
|---|---|
| `expected str, got list` | `topic_ids` / `deliverable_ids` / `stale_reasons` 是 **jsonb**，不是 `text[]` |
| `invalid input syntax for type json` | `topics.why_now` 也是 jsonb（不是 text） |
| `null value in column "embedding"` | `topics.embedding` 是 **NOT NULL 的 vector(1024)** |
| `fk_topics_seed` | `topics.seed_id` → `topic_seeds` |
| `fk_topic_seeds_origin` | `topic_seeds.origin_id` → `origins`（外键链三层） |
| `ck_jobs_state` | 合法状态里**没有 `succeeded`**，是 `done` |
| `progress is of type double precision` | `jobs.progress/budget/cost_accum` 是浮点，不是 jsonb |
| `generation_record_id` NOT NULL | `deliverables` 那一列必填（但没有外键） |

**每一条都写进了播种代码的注释**，与 `tests/conftest.py` 里那句
「空库缺 12 行 categories，用例会以 ForeignKeyViolationError 失败——
那不是断言不过，是库没备齐」是同一种坑。下一个写 BE 系列的人不必再踩一遍。

## 7. 登记未做

1. **这个端点还没被挂进任何 ASGI 应用**。`create_project_overview_app` 是独立的
   FastAPI 实例，装配（挂进 `harness/demo_server.py` 或生产入口）属另一处改动，
   超出本卡 outputs。**前端因此还调不到它**——UI 那边要用，得先装配。
2. **前端没改**。UI-02 的主链路没有项目总览屏；蓝本 P14 那一屏属 UI-03~11。
3. **没有分页**。一个项目的 jobs / deliverables 多起来时会一次全返。
   现在没有分页参数，也没有上限——真数据量上来之前不好定口径，登记在此。
4. **`topics` 按 `projects.topic_ids` 取**：那一列是 jsonb 数组。
   如果某个 topic_id 在 `topics` 表里已经不在了，它会**静默消失**在结果里
   （而不是报一条「引用了不存在的 topic」）。要不要报，得先有产品口径。
5. **org 归属没测**：`owner.kind` 现在只判 `user`（与 `deref.py` 同）。
   `org` 那条路要等 Membership 解析接上。
