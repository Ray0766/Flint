# 上线前合规手续清单

**这是上线（商用）前抓取手续的唯一清单。**
`docs/blocked/K2-COMPLIANCE-BEFORE-LAUNCH.md` 只留指针，不再自带第二份——
两处各写一份，迟早各说各的，而读的人分不出哪份是真的。

## 触发条件

本产品从非商业转为**商用上线**的那一刻。在那之前，现行裁决兜着。

## 失效条件（现行裁决什么时候不再覆盖）

现行裁决是 `flint/region/legal_policy.py#RECORD_ONLY`：合规状态照实记录、不拿它拦抓取。
它的范围写死在记录里——`scope="non_commercial"`，做出日期 2026-08-04。

**范围一变，裁决就不再覆盖**：商用上线那一刻，`scope="non_commercial"` 与实际用途
不再相符，这张清单上的每一行都要有结论。裁决不是被推翻，是它从头就没管这段。

## 三件要一起看的事

### 一、`robots` 放行不等于条款放行

`assets/source_legal_status.yaml` 里的 `tos_url` **只记地址不记结论**：robots.txt 是
机器可判的，服务条款是人读的。八条 ToS 至今一条都还没读——机器判不了的东西
NEVER 由机器给个结论顶上。清单上「手续」那一列，多数就是这件事。

`weibo` 是最需要人读的一条：robots 放行（那份文件只针对具名爬虫），
而它的 ToS 明确限制自动化取数。**只看派生合规态会得到「没问题」的错觉。**

### 二、三个 `restricted` 源的处置是三选一

`arxiv` · `naver_datalab` · `reddit_data_api` 实测为 `disallowed` → 派生 `restricted`。
上线前每一条必须落到下面三种之一，NEVER 靠现行裁决兜着：

1. **签约取数**：拿到授权，回执按上表「判据」列存档，并重跑探测让数据带上新结论；
2. **换源**：该区改用别的源，种子表里换掉；
3. **走 E6 缺数据行**：该区照实缺数据，产物上出现「今日缺 {源} 数据」。

### 三、切档是最后一步，且它本身有判据

商用上线时把 `flint/region/legal_policy.py` 里的

```python
OWNER_DECISION: Final[LegalDecision] = RECORD_ONLY
```

改成 `BLOCK`。改完立刻回到 REGION-07 的原行为：只放行 `allowed`，其余落降级行 +
抛 `FetchDenied`。`flint/region/fetch_gate.py` 一个字没改过——门一直在，
只是这一层此前没让它拦人。

**切档的判据**：`OWNER_DECISION is BLOCK`，且
`tests/v041/test_legal_status_recorded.py#test_flipping_the_switch_back_blocks_again`
全绿，且届时确认合规的源在种子表里已填成 `allowed`。

## 这张清单自己怎么不漂

| 会漂的地方 | 谁挡着 |
|---|---|
| 新增一个源而清单没跟上 | `build_table` 抛 `KeyError`，判据跟着红 |
| 手改表里的实测态或派生态 | `test_the_table_is_exactly_what_the_data_produces` 逐字比 |
| 代码里改了裁决范围而文档没跟上 | `test_the_scope_string_is_the_one_in_the_code` 从代码读 `scope` |
| 问题单那边又长出第二份清单 | `test_the_blocked_doc_no_longer_carries_its_own_per_source_list` |
| 判据一列写成「确认合规」这种空话 | `test_every_row_names_a_place_to_look` 要求给出可以去看的地方 |

## owner 上线前要给的三样

1. **八条 ToS 的人读结论**（尤其 `weibo` / `arxiv` / `reddit_data_api` 三条）；
2. **三个 `restricted` 源的处置**：上面三选一，逐条落文；
3. **切档确认**：把 `OWNER_DECISION` 切到 `BLOCK`，并把届时确认合规的源在种子表里
   填成 `allowed`。
