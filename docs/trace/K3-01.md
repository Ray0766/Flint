## 3. 调研（A 档只读，五条方法论，逐条留链接）

| 方法论 | 取到什么 |
|---|---|
| Google E-E-A-T（质量评估指南） | 权威度是**分主题**的相对量，不是网站的绝对属性 |
| Wikipedia WP:RS | 「学术同行评议 > 有事实核查的报刊 > 自出版」，判据是**有没有独立核查**，不是名气 |
| NewsGuard 九项评级 | **唯一公开了具体分值与分档边界的体系**：100 / 75–99 / 60–74 / 40–59 / 0–39 |
| 证据金字塔 + GRADE | 印证同一条次序；降级理由是**偏倚风险** |
| Moz 域名权重 DA | **明确不采用**：衡量的是外链影响力不是可信度，且对数刻度直接当乘数会压扁差距 |

**数怎么来的**：取 NewsGuard 分档中点（100 / 87 / 67 / 49.5），**以主流档为分母归一** →
1.15 / 1.00 / 0.77 / 0.57；`unknown` 取已知最弱档的值。
逐档推导写在 `docs/authority权重-v041.md`。

**为什么锚在主流档**：锚在 `mainstream = 1.00` 意味着改的是**相对分量**，
不是整体分数水位。五档若全 >1，接轴会让所有分数一起涨——
此前所有金标结论都要重跑，而那些结论跟权威度本来毫无关系。

**`unknown` 为什么不是 0 也不是 1.0**：0 是判定门的活（`tier_gate` 已经在做，
门是布尔的、轴是连续的，用轴去做门的事等于一个权重值悄悄改掉判定门槛）；
1.0 是主流媒体档的分量，「没查到来路」自动获得那个分量是这条轴最不该有的行为。

## 4. 改既有文件：三处，逐处交代

### 4.1 `flint/region/authority_axis.py`（卡上 outputs 未列，但这是本卡的实现落点）

- **改前**：`AUTHORITY_AXIS_WEIGHT = 1.0` 单常数 + `AUTHORITY_REVISIT`（`revisit(K3)` 标记）；
  `apply_authority_axis` 恒 `round(strength * 1.0)`。
- **改后**：`AuthorityWeights` 五档 dataclass（初值只有这一处）+ `AUTHORITY_BASIS`
  （来源说明，替掉 revisit 标记）+ `weight_for()`（**认不出的档位按最低权重**，
  NEVER 按 1.0）+ 幂等守卫（同档原样返回，换档抛错）+ 0~100 截断。
- **为什么非改不可**：这就是卡面 acceptance②「`revisit(K3)` 标记随之移除」
  与「替掉 1.0 中性占位」本身。

**两处新增的防护，理由分别是**：
- **截上界**：`official` 是 >1 的乘数，满分证据会被顶到 115；
- **幂等守卫**：权重不再是 1.0 之后，**叠乘是真的会发生的事**——
  同一份证据会因为多走一遍流水线而变强。换档再接一次直接抛错，
  因为第二次乘的是已经加过权的分，不是底分。

### 4.2 `flint/config.py`

- **改前**：`TUNING_KEYS` 十二个键；`TuningProfile` 无 authority 字段。
- **改后**：加五个 `authority.*` 键 + `TuningProfile.authority` 字段 +
  `replace(AuthorityWeights(), **group("authority"))`。
- **为什么非改不可**：acceptance②「写进配置，NEVER 硬编码进代码」。
  走既有通道而不另开一套——另开一套的后果是 owner 要在两个地方调参，
  而两处里总有一处会被忘掉。**初值仍只有一处**（`AuthorityWeights` 的默认值），
  这是那条通道自己的规矩（「这里 NEVER 再抄一份数」），有断言守着。

### 4.3 `tests/v04/region/test_scorer_axis.py`（REGION-06 的既有守护断言）

- **改前**：`test_authority_weight_is_neutral_one`（断言 == 1.0）、
  `test_weight_carries_a_k3_revisit_marker`、
  `test_gold_scores_do_not_drift_for_any_tier`（**任何档**都不漂移）。
- **改后**：分别换成锚点档恒 1.00、来源标注、
  `test_gold_scores_do_not_drift_at_the_anchor_tier` + **新增阴性对照**
  `test_gold_scores_do_move_at_the_other_tiers`。
- **为什么非改不可**：「全档不漂移」在定值之后是**自相矛盾**的——
  它要求的正是「权重不起作用」。但守护点不能丢：`mainstream` 那一档一旦漂移，
  说明改的不只是权重，而是打分本身。所以是**收窄 + 补阴性对照**，不是删掉。

### 4.4 `tests/v041/test_tuning_channel.py`（BL-05）

- **改前**：`assert TUNING_KEYS == (十二个键)`（相等）。
- **改后**：`assert set(TUNING_KEYS) >= {十二个键}`（包含），
  并把逐个旋钮生效的参数化改成**直接遍历 `TUNING_KEYS`**。
- **为什么非改不可**：那条通道本来就是给后续参数报到用的

  参数化改成遍历之后，新加的旋钮**跑不掉**——不生效就红。

**⑩ 第一次打偏了**：我把「（E-E-A-T）」改成「（据了解）」，改的是**名字**不是出处，
那一行的链接还在——判据当然不该红。重做成真删链接（⑩''）才发现真洞。
**变异要对准判据盯的那件事**，否则测出来的是另一个问题的答案。

**⑩'' 为什么能活（真洞）**：判据先取本节所有以 `"| "` 开头的行、再 `[2:]` 跳过
表头与分隔行。但 markdown 分隔行写的是 `|---|---|`，**不以 `"| "` 开头**——
于是 `[2:]` 实际跳掉的是表头 + **第一条数据行**，第一行方法论从此没人判。
修法：分界**按分隔行定位**（找 `set(ln) <= set("| -:")` 的那一行），
不按行数偏移；另加「至少四行，卡面点了四个角度」的下界。
两端各验一次（⑩'' 第一行、⑫ 最后一行）都红。

**顺手补的**：`test_the_document_uses_no_hearsay_wording`——⑩ 那次打偏的变异
把「据了解」写进了文档而**没有任何判据拦下**。沿用 K1-01 的判法（先剥「」引号）。

十二次变异后三个产物文件的 sha256 与变异前逐位相同。

## 7. owner_review：三件要 owner 拍板的

1. **这五个数认不认**。它们不是本项目实测出来的，是从 NewsGuard 的公开分档
   换算的。换算这一步是我做的判断：把「档」映射到「NewsGuard 分档中点」。
   owner 若认为 `industry` 该更高（比如厂商白皮书在本产品的语境里比一般媒体更有用），
   改配置即可，**不用改代码**。
2. **`unknown` 与 `community` 同值对不对**。现在两者都是 0.57。
   理由是「不知道来路 NEVER 比已知最弱的更强」，但也没有理由更低——
   更低就成了「未知即扣分」，那是门的活。若 owner 要区分，需要给出理由，
   否则就是拍一个数。
3. **要不要分主题**。E-E-A-T 明说权威度是分主题的（医学问题上的权威源与
   金融问题上的不是同一批），本表是全局的。分主题要主题分类先到位，
   是另一张卡的量。
