## 3. 缝的形状：参数早在，接线没有

`generate_topic(..., cards_context: str = "")` 的参数早就在，`{cards}` 占位也在 @2/@3 里。
缺的是**谁来拼、谁来传**：`orchestrate_combo` 一路走默认值，于是生产路径上
`{cards}` 被替换成空串。

**空串与没接线在结果上长得一模一样**：模型照常生成、校验器照常判，只是它手上
从来没有卡的真实内容。harness（`topic_caliber.py`）自己拼上下文，一直是绿的——
**两条路分叉时，绿的那条不是生产那条**。

## 4. 三个落点

| 落点 | 做了什么 |
|---|---|
| `flint/topic/cards_context.py`（新） | 纯函数：`CardFacts` / `build_cards_context` / `card_day_from_id` / `NoUsableEvidenceCards` |
| `flint/topic/create.py#PgCardCatalog.contents_of`（新方法） | 从真表读**每张卡各自**的关键词 |
| `flint/topic/orchestrate.py` / `flint/api/combo.py` | 两个旋钮露出来 + 路由真的拼串并处置「接不到卡」 |

**为什么不复用 `keywords_of`**：它给的是全批**去重后的一份**清单。`{cards}` 要的是
「哪张卡里有什么」——混成一份之后模型无从知道某个词属于哪张卡，而 why_now 的
每条证据 MUST 指到具体一张卡。

**日期从 card_id 里读**：`evidence_cards` 表**没有 day 列**（见 0001 迁移），
日期编码在 `card-YYYYMMDD-{cluster}` 上（`flint/jobs/ingest.py:569`）。
解不出返回 `None` 且那一行显示空日期——**NEVER 拿今天顶上**，那会让模型
把今天写成事件发生日，而日期幻觉正是接地校验第一条要挡的。

## 5. 接不到卡不静默（acceptance③）

`build_cards_context([])` 抛 `NoUsableEvidenceCards`，路由捕获后 `422 VALIDATION_FAILED`
并**当场返回**。静默继续等于把「没有证据」写成「有证据但模型没引」——
两者的处置完全不同：前者该拒绝生成，后者该看模型。

**一张空壳卡不整批拒**：`CardFacts(texts=[])` 那一行写「（内容缺失——未读到卡内容，
NEVER 据此编造）」。留一个只有 id 的空壳会让模型以为那张卡内容就是空的，
进而放开手编，而真相是这一侧没读到。

## 6. 变异考：五个，第五个先活了下来

| 变异 | 抽掉什么 | 结果 |

| ① 空卡集不报错 | acceptance③ | **1 failed** ✓ |

| ⑤ 路由把上下文换成 `cards_context = ""` | **本卡正题** | **22 条全绿地活了下来** ✗ |

**变异⑤ 是最该被抓住的那一个，却漏了**：路由那条源码面断言写的是
`"build_cards_context" in code` 与 `"cards_context=" in code`——
**导入行里有前者，orchestrate 调用处有后者**，两个词把断言喂饱了，
而赋值那一行早就换成了空串。

改成判**赋值形状**：`re.search(r"cards_context\s*=\s*build_cards_context\(")`
加一条反向断言（不许出现 `cards_context = ""`）。重考变异⑤ → **1 failed**。

这是本批第三次同型（DEF-01 的 `RETENTION_DAYS`、DEF-03 的 ⌘A 快照，本条）：
**判据查的是「有没有这个词」，而要守的是「它有没有真的接上」**。

五次变异后三个文件的 sha256 与变异前逐位相同。

1. **生产默认提示词仍是 `topic_gen@1`，它没有 `{cards}` 占位**。所以「生产路径强接地」
   有两半：本卡接的是**上下文**这一半；另一半是把默认换成 @2，那要动
   `prompts.lock.json` 与口径实测结论，属 owner 面。
   `test_production_still_defaults_to_the_prompt_without_the_placeholder` 把现状钉住——
   默认改成 @2 的那天它会红，提醒来更新这条登记。
2. **`ComboApiDeps` 没有 `prompt_name` 字段**：编排器那一层的旋钮露出来了，
   API 那一层还没有。加它属上一条的同一件事（谁来决定用哪版提示词）。
3. **`contents_of` 只读关键词**：卡上的 `top_links`（真证据 title/quote_span）没进串。
   `enriched_cards_context` 那条路（B-5）读的是富化后的证据行，比这条厚。
   两条并存，本卡按 catalog 现成的数据接——把 top_links 也拼进去要先定「引哪一条链接」，
   属另一张卡。
4. **没有端到端 API 用例**：`POST /projects/combo` 的行为面要 origins/seeds/topics/
   projects/generation_records 一整套表 + 假 provider 注入，而 `PgCardCatalog` 在路由里
   是**写死构造**的（不可注入）。本卡用源码面两条断言守接线，登记这条现状。
