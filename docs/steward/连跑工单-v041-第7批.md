## 2 owner 2026-08-08 的三条裁决（`DEC-039-041-LANDING` 逐字落地）

### DEC-039 · 热点卡的陈旧槽恒不显示

`SLOT-02` 停得对，而且它的理由比「做不了」强得多：

> **热点簇不是一份分析——它不引用事实，它是事实的来源之一。**

Revalidator 判的是「一份分析引用过的事实变没变」，需要 `project_id` / 账本版本 / 引用的事实三样，而 `clusters` 表一样都没有。全库带 stale 的只有 `deliverables.stale_reasons` 与 `pricebook.stale_after_months`，**没有第三处**。

唯一能挂到簇上的是 `Favorite.snapshot_stale`，它说的是「**你收藏的那份快照旧了**」——印在广场卡上会被读成「**这个热点旧了**」。两句话不是一回事（与 `DEC-038` 同一形状）。而且今天也借不到：`fav/store.py:35` 自述是内存实现，`favorites` 表不存在，标记每次重起就消失。

**`STALE-01` 的产品不是那个隐藏动作，是那条判据**：全仓禁止用 `last_active` / `first_seen` 做算术得出「陈旧」。否则迟早有人写 `now - last_active > 7 天`——那是新写一套比对，而且**它说的是系统不知道的事**。

### DEC-040 · `global` 与 `NULL` 归入显式的「未归区」

**steward 实查的分布**（省 worker 一次重查）：

```
global = 103    CN = 89    NULL = 1
```

`global` 是 `ghtrend` 写死的常量，**不是地理事实**。

- 把它当第九区 → 用户会在地理列表里选到一个不存在的地方；
- 让它从筛选面消失 → 那 104 条在默认视图之外**再也看不见**。

**「未归区」是唯一诚实的说法。** 库里 `NULL` 与 `global` **保持可分辨**，本卡只在呈现层合并——NEVER 把 `NULL` 回填成 `global`，那会抹掉「这条簇从来没归过区」这个事实。

走 `DEMO-TOPIC` 单的甲。它让主题两屏第一次有真数据可看，而且与「广场数据是合成的」同族——那一族你已经接受了，本条不新增性质。

## 3 steward 复核第 6 批发现的一处（`LOCK-01`）

`ENTRY-02` 把 `PgProjectStore.save` 从纯 `INSERT` 改成全行 upsert——**改动本身对**（`save` 只能建不能更是真缺陷，`created_at` 排除在更新列外也对）。

**但它没有乐观锁，而 `change_log` 在被覆盖的列里。** `projects` 九列里没有版本列：

```
project_id · owner · origin_id · topic_ids · chosen_topic_id
· deliverable_ids · change_log · status · created_at
```

并发下：A 读（`change_log=[e1]`）→ B 读 → A 写 `[e1,e2]` → B 写 `[e1,e3]`，**e2 无声消失**。

**改前是「第二次写大声失败（500）」，改后是「并发下静默丢失」——它把一个响亮的错换成了一个安静的错。** 现在只有一条写路径，风险是潜伏的，而「潜伏」正是它形容原缺陷时用的词。

`LOCK-01` 把响亮的错找回来：加版本列 + 条件更新，版本不符抛 409。**阴性对照 MUST 断言「先写者的 `change_log` 条目还在」**——只断言抛异常不够。
