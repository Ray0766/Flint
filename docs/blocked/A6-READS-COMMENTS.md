## 实况

A6 的取数信号是

```js
if (!has(/useScreenData|useEffect|fetch[A-Z]\w*\s*\(/)) return [];
```

`has` 判的是**原文**（`re.test(code)`），注释在内。

`WB-01` 的工作台骨架**一个请求都不发**，却被报「缺加载态、错误态」——
命中的是它注释里那句解释「为什么这里不该用副作用钩子同步宽度」。
**说明问题的那句话又被当成问题本身。**

同一个坑本仓已经踩过一次：`declarationsStripped` 的文件头写着
「一段解释『这里为什么不需要 return』的注释里带着 `return` 二字，
会让一个纯类型文件被当成有运行时」——那次是 A3 踩的，
于是 A3 用了剥注释的那份，**而 A6 没有**。

## 直觉上的修法有一个坑，所以本单不在 `WB-01` 里修

把 A6 也改成判 `declarationsStripped(code)`，一改就红出**四屏**：

| 屏 | 报的是 |
|---|---|
| `app/gate/[id]/page.tsx` | 缺空态 |
| `app/demo/page.tsx` | 缺空态 |
| `app/account/page.tsx` | 缺错误态 |
| `app/settings/locale/page.tsx` | 缺空态 |

这四条**有可能全是真的**——三态只写在注释里、屏上并没有，
正是这条规则该抓的东西；也**有可能**是那一态住在更深一层的组件里
（A6 只跟一层本仓 import）。两种情况修法完全不同。

`WB-01` 是一张搭骨架的卡。在它里面顺手改一条**全仓共用**的规则、
再顺手判四屏该不该改——那是把一次骨架改动变成一次静默的批量改数
（`DEC-058` 的边界原话：「回填只处理今天这一条，NEVER 顺手重算全库」，
同一条纪律）。所以本单只把证据留下。

## `WB-01` 当下怎么绕开的

把注释里那个钩子的名字换成中文说法（「副作用钩子」）。
**这是绕开，不是修好**：下一个人写一句带 `useScreenData` 的注释，
同样会中招，而他会以为是自己的屏缺三态。

## 建议的下一张卡

1. 先**逐屏核**上表四条：那一态是在注释里，还是在第二层组件里；
2. 真缺的补上（各自有自己的判据）；
3. 再把 A6 换成判剥过注释的那一份；
4. 阴性对照要补一条：**注释里写满三态而代码里一个都没有的屏 MUST 报红**——
   没有这一条，第 3 步等于没做。
