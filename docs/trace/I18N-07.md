# I18N-07 trace — 正交性 18 组合 harness @2026-08-02

## 1 SELFCHECK-V1 里点名的风险，这张卡正面处理
V1 出口时我写过：「正交性 harness 与 i18n 扫描器是两件全新工具，
**它们本身的可靠性要先自证**（否则「18 组合全绿」可能只是工具什么都没测）」。

所以本工具**先自证再干活**：`main()` 里 `self_test()` 是前置步骤，自证不过直接非零退出、
**不进入正式 18 组**。

## 2 自证怎么做的
四条断言各注入一个**对应的反例探针**，断言那条断言确实会红：

| 断言 | 注入的反例 | 出处 |
|---|---|---|
| ① UI locale == lang | region=JP 时 locale 变 `ja` | A3 反例第一条「切 region=JP 时把界面变日文」 |
| ② 源集 == SourceRegistry[region] | 源集变成 `s-{lang}` | 「本国隔离」的形态之一 |
| ③ 热点集合 hash 与 lang 无关 | payload 掺进 lang | A3 反例第二条「lang=en 时把 CN 热点集合过滤成英文源」 |
| ④ Deliverable.lang == lang | 产物语言取自 region | 由 region 反向派生语言 |

外加**阴性对照**：正确接线下不得报红——否则就是「一把见谁都报警的尺子」。

## 3 空表期间断言②仍然有效
K1 未决 → `SourceRegistry` 是空表种子，每区期望都是空元组。
这不是「没测」：正交性要的是**源集只由 region 决定**，空集同样能证伪——
只要有一组因 lang 不同而拿到不同的源集，②就红（反例探针正是这么触发的）。

## 4 探针面 = 未来的接线点
四个观测点用注入的 `Probe` 表示。真实接线落地时把探针换成真实读取即可，
**断言一字不改**——NEVER 让 harness 自己去猜系统内部结构。

## 5 一处自纠
首轮 `ModuleNotFoundError: No module named 'flint'`——`python tools/x.py` 只把 `tools/`
放进 `sys.path`，仓库根不在其中。已显式补 `sys.path`，原因写在代码注释里。

## 6 验收
`python tools/orthogonality_check.py --combos all` → **exit 0**：
自证通过（4 条注入反例各自变红 + 阴性对照不报红）→ 18 组 × 4 断言全过。
