## 2. 卡面一处措辞与仓里对不上（不阻塞，照实办）

卡面 acceptance② 写「既有 **orthogonality_check** 守着 18 组合」。
仓里**没有叫这个名字的函数**（全仓 grep 只在 `.venv` 里命中数学库的同名词）。

真实存在的是两样：

- `flint/profile/prefs.py#set_prefs`——「只改传进来的那一项」，A3 正交的实现；
- `tests/v04/i18n/test_profile_prefs.py`——两条正交断言（改语言不动地区、反之）。

18 = 2 语言 × 9 地区，出处是 `contracts_v04` 的两个 Literal。
卡面说的那件事**在**，只是不叫那个名字。所以照办不停：
本卡把 18 组合**逐个走了一遍**（`test_all_eighteen_combinations_round_trip`），
比原来的两条抽查更硬。

## 3. 转调，不重写

| 要做的 | 转调 |
|---|---|
| 合并（只改传进来那项） | `prefs.set_prefs` |
| 读（未设置 → 声明过的默认值） | `prefs.get_prefs` |
| 可选值清单 | `contracts_v04.SystemLanguage` / `Region` 的 `get_args` |

**可选值 NEVER 在本模块抄一份**：抄一份就是第二个真相，它会在加第十个地区那天
悄悄少一项。变异⑥（抄一份且少一个地区）红 4 个。

判据还多钉一层：端点列出的可选值与 `prefs.py` 实际收的那一套**逐字相同**
（`test_the_options_agree_with_what_the_store_accepts`）。两处不一致时，
端点会把一个 prefs 根本不收的值列成「可选」——用户照着选，然后被拒。
这条判据故意读了 `prefs` 的私有名 `_LANGS`/`_REGIONS`：
要钉的正是「另一处的真相」，换成公开别名就等于把两处抹成一处，判据也就不判了。

## 4. A3 的三条形态

### 4.1 两轴分别接受

`lang` 与 `region` 各自可省，省掉的不动（变异⑩⑪ 各钉一头：
改语言时把地区一并重置 / 反之）。

### 4.2 NEVER 合成 `zh-CN`

合成串把两轴绑死：切地区必然连语言一起切。判据用正则扫全响应，
`[a-z]{2}-[A-Z]{2}` 一处都不许有（变异⑨）。

冻结件 `AnalysisContext.locale` 是 v0.4 前的兼容字段，注释写着「由 lang 派生填充」——
**它是派生值，不是这里的真相**，所以本端点根本不返回它。

### 4.3 读不写

`get_prefs` 未设置时返回声明过的默认值而**不落库**。落了的话，
日后默认值一改，这个人还留在旧默认上——而他从没设置过。
变异⑧（读时顺手落库）当场红。

## 5. 无效值：整次拒绝，一个字不写

acceptance③「NEVER 静默回落」。三条判据：

1. 422 + `code=VALIDATION_FAILED` + `detail.allowed` 列出可选值（变异③④）；
2. 库里**一个字都不许变**（变异①「静默回落到默认」红 3 个）；
3. **一项对一项错时整次拒绝**（变异② 只写对的那项）——写了一半的设置比全不写更难查。

外加：拼错的字段名（`{"language": "en"}`）走 pydantic 的 `extra="forbid"` → 422。
静默忽略的话，用户以为改了，其实什么都没发生（变异⑬）。

## 6. 变异考逼出来的一把新尺（本卡最重要的一条）

二十个变异体里 **⑫ 与 ⑳ 活了下来**。

### ⑳ 是真洞：既有那把尺子不认九区代码

变异体往模块里插了一行 `patch.region == "CN"` ——`scan_source` 返回空、全绿。
读 `tools/check_locale_seam.py` 才看清：

```python
LOCALE_LITERALS = frozenset({"zh", "zh-CN", "zh_CN", "zh-Hans", "中文", "weibo", "微博"})
```

**九区代码一个都不在里面**。A3 是两条轴，这把尺子只守住了语言那条。

加宽它要动全仓门禁（`"CN"` 这类字符串在数据表键与类型声明里到处都是，
得连带扩豁免规则），**改动面远大于本卡 outputs** → 按 §六.1 停下登记：
`docs/blocked/LOCALE-SEAM-RULER-MISSES-REGION-CODES.md`（给 owner 三个选择）。

本卡就地补一把**只管 `flint/api/settings.py`** 的窄尺：从冻结件取全部 11 个值，
断言它们一个都不作为字符串字面量出现在模块里（docstring 除外）。⑳ 当场红。

### ⑫ 是本轮第四个假变异

变异体把「回库里那份」改成 `Prefs(lang=patch.lang or updated.lang, ...)` ——
**行为一个字没变**：`patch.lang` 有值时它就等于 `updated.lang`，没值时走的也是 `updated`。
（DOC-02 ⑧、DOC-03 ⑤、BE-03 ⑧ 是前三个，都是 `x or y` 这一族。）

改成真变异 ⑫′（回请求那份且**根本不看库**）后红 3 个——
`test_changing_the_language_leaves_the_region_alone` 第一个抓住它。

## 9. 登记未做

1. **没挂进任何 ASGI 应用**。BE-01~07 七张卡同一件待办。
2. **`PrefsStore` 仍是内存实现**（`prefs.py` 自己写着「SQL 实现随 profiles 表接入」）。
   本端点收的是 `PrefsStore` 这个既有座子，换成 SQL 实现时端点一行不用改。
3. **不报「设过没设过」**。`prefs.py` 已决：未设置 = 声明过的默认值 zh/CN，
   「而不是『空』或『猜』」。要区分「他选了 zh」与「他没选过」，
   得先在 store 上开一个存在性查询——那是重开一条已决口径（S4），本卡不动。
4. **前端 `web/components/region-switch/RegionSwitch.tsx` 自带一份地区清单**——
   与本端点的 `options` 是两个真相。本卡属后端，UI 卡（UI-03~11）接线时
   应改成读 `options`，**本批不顺手改**（§六.1）。
5. **`docs/blocked/LOCALE-SEAM-RULER-MISSES-REGION-CODES.md`**：
   BL-09 那把全仓尺不认九区代码，已登记 + 给 owner 三个选择；
   本卡用一把只管自己模块的窄尺兜住（§6）。
6. **不做地区自动探测**。IP 猜地区是「假值」的典型（变异⑱ 钉的就是
   `detected_from_ip`）：猜错时用户看到的是一个他没选过、也不知道从哪来的地区。
