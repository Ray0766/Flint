## 3. 实测：真去取了八个源的 robots.txt（A 档）

`harness/probe_robots.py`（**唯一真发请求的地方**，`flint/` 里零网络）。
只取 `robots.txt` 一个路径，**没碰任何数据端点**——那属首次真实抓取，是红线。
八个响应全落 `fixtures/robots/*.txt` + manifest（NET-02 三件套：URL / 时间 / sha256）。

| source_id | 实测态 | 证据 |
|---|---|---|
| `gtrends` / `google_trends_api` | allowed | 该 agent 有 2 条规则，没有一条命中 `/trends/api/dailytrends` |
| `weibo` | allowed | **该文件里没有适用于通用 agent 的规则组**（9152 字节，只针对具名爬虫） |
| `ghtrend` | allowed | HTTP 404：`api.github.com` 没有 robots.txt，RFC 9309 §2.3.1.4 全放行 |
| `yahoo_jp_realtime` | allowed | 15 条规则未命中 `/realtime` |
| `arxiv` | **disallowed** | `Disallow: /`（`export.arxiv.org`） |
| `naver_datalab` | **disallowed** | `Disallow: /`（`openapi.naver.com`） |
| `reddit_data_api` | **disallowed** | `Disallow: /`（robots 里还写着「非商业使用见 r/reddit4researchers」） |

**判的是我们真会请求的那个主机**：K1-01 记 `naver_datalab` 的首页是
`datalab.naver.com`，而 API 在 `openapi.naver.com`——判错主机等于判了一份
与我们无关的 robots。改了探测目标。

**4xx 不记 `unreachable`**：RFC 9309 §2.3.1.4 说 4xx = 该主机没有 robots.txt，
协议本身给的结论就是全放行。记成「不知道」是另一种蒙混。
5xx / 超时 / 域名不解析才记 `unreachable`（临时结论，**NEVER 固化成 restricted**）。

**ToS 一条都没读**：`tos_url` 只记地址不记结论。robots 是机器可判的，
**服务条款是人读的**——机器判不了的东西 NEVER 由机器给个结论顶上。

## 5. 变异考：十三个，三个先活了下来

| 变异 | 抽掉什么 | 结果 |
|---|---|---|
| ① 开关切到 `BLOCK` | 现行裁决 | **6 failed** ✓ |
| ② block 档不再委托门 | acceptance④ | **1 failed** ✓ |
| ③ 戳一律改写成 allowed | acceptance② | **2 failed** ✓ |
| ④ 脚注给每条都加 | 阴性对照 | **1 failed** ✓ |
| ⑤ 脚注不说上线前要补手续 | acceptance③ | **1 failed** ✓ |
| ⑥ 入表口不跟裁决走 | §4.1 | **1 failed** ✓ |
| ⑦ 派生一律回 unknown | acceptance① | **3 failed** ✓ |
| ⑧ disallowed 派生成 allowed | acceptance① | **1 failed** ✓ |
| ⑨ 路径匹配退回纯前缀 | `$` / `*` 语义 | **38 passed** ✗ → 补判后 **2 failed** ✓ |
| ⑩ 空 `Disallow` 守卫抽掉 | robots 原义 | **38 passed** ✗ → **是惰性变异**，见下 |
| ⑪ 入表口写回硬编码 allowed | §4.1 | **38 passed** ✗ → 补判后 **1 failed** ✓ |
| ⑫ 「没有适用规则组」与「没命中」并成一句 | 证据可读性 | **1 failed** ✓ |
| ⑬ 别的爬虫的规则也照单全收 | agent 分组 | **2 failed** ✓ |

**⑨ 为什么能活**：`$` 行尾锚与 `*` 通配一条测试都没有。而这不是纸面问题——
`openapi.naver.com` 的 robots 就是 `Allow: /$` + `Disallow: /`：照前缀判的话
`/$` 命中每条路径，**整站被判成 allowed**。判宽比判严更危险：一个本该
`restricted` 的源会被记成 `allowed`，而这张表要拿去做上线前的合规清单。
补了 `$` 锚（2 例）、`*` 通配（2 例）、最长者赢、agent 分组、无适用组 五组判据。

**⑩ 是惰性变异，不是测试有洞**：抽掉 `if not value: continue` 之后行为一个字不变——
空串长度为 0，永远输给「同长则 Allow 赢」的定序，自动落到 `allowed`。
那道守卫**本来就不担事**。处置：**删掉它**（留着会让下一个人以为它在担事），
把这件事写进代码注释，改用定序那一行重考 → 2 failed ✓。
本批第三次撞上「惰性变异 ≠ 测试有洞」（K1-02 ⑥、BL-04 同型）。

**⑪ 为什么能活**：判据是 `"admits(" in code`，而**模块自己的 docstring 里就写着**
`legal_policy.py#admits()`——把断言喂饱了。改成钉在 AST 上：
找 `ast.Call` 且 `func.id == "admits"`，另判「没有与字面量 `"allowed"` 的
`ast.Compare`」。**本仓第十四次同型**（判据被自己的解释文字喂饱）。

十三次变异后三个实现文件的 sha256 与变异前逐位相同。
