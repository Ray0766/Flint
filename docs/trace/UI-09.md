## 2. R3：覆盖率给**两个数**，NEVER 给一个比例

技术约束清单第 1 条 + BE-03 的原话：

> 「6 个块里 1 个有证据引用」前端能列出来；「引用覆盖率 17%」前端会拿它画进度条——
> **而那条进度条没有出处**。给了商，也就没人再去想它是怎么算出来的。

所以本组件把分子与分母**分别渲染**，中间那个「/」是排版，不是除法。判据三层：

1. 组件里**一处除法都没有**（剥掉字符串后扫 `\w / \w`——见 §5 那处返工）；
2. 屏上**没有 `%`**，且**每个数都是整数**（出现小数就意味着有人算了商）；
3. 没有 `<progress` / `aria-valuenow` / `width:`（进度条的三种画法）。

**被排除的用户块数一并报出**——否则「分母为什么比总块数小」说不清（BE-03 §3.1）。

## 3. 两处「没查过」

| 处 | 后端 | 屏上 |
|---|---|---|
| 未解引用 | BE-03 的 `status: "not_checked"`，**连 `count` 键都不给** | 「还没查过引用解不解得开」，NEVER 显示 0 |
| 陈旧态 | BE-04 的 `status: "not_checked"`，**连 `stale` 键都不给** | 「还没判过新旧」，标记是 `unknown` 而不是 `false` |

0 的意思是「查过了，一个都没有」；`false` 的意思是「查过了，是最新的」。
两句话都是我们此刻没有资格说的。

## 4. R4：陈旧不隐藏内容（DESIGN-12）

BE-04 那侧的形态是「陈旧的交付物与新鲜的交付物，响应形状逐字相同」。
前端这侧对应的是：**横幅只是加在内容上面的一条**。

判据钉在**类型**上而不是行为上：组件的 props 里**没有 children、没有正文**——
够不着正文，也就藏不了。行为判据只能证明「这次没藏」，类型判据证明「藏不了」。

两条附带纪律：

- **不可重核要说为什么**（BE-04 的 `revalidatable.reason` 原样转出）：
  只给一个灰按钮，用户不知道该怎么办；
- **没查过陈旧态时不挂横幅**：横幅位是常驻的，常驻位上不该有一条恒久的「未知」噪音。
  （这与质量卡屏的「接口未提供」不同——那是用户主动点开时该看到的。）

## 5. 一处判据见谁咬谁（返工）

第一版的「不许有除法」写成 `re.search(r"\w\s*/\s*\w", code)`，

**每一行 import 都会被报成除法**。

修法：先剥掉字符串再判。一把见谁咬谁的尺子，用不了几天就没人看它
（与 AUDIT-01 窄化那三次、BE-09 的 `DELETE` 误伤同一类）。
