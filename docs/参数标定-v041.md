**今天一个参数都标定不了。** 四个参数各有各的理由，四条都有实测撑着——
所以本卡**没有改任何参数值**，改的是**标定状态**（`flint/config.py#CALIBRATION_STATUS`）。

## δ：分数本身没有区分力（实测）

拿 `same_topic` 的 60 对标注去扫余弦距离阈值：

```
same  距离: n=14  min=0.9581  中位=1.0319  max=1.0659
diff  距离: n=46  min=0.9368  中位=0.9943  max=1.0638
扫遍所有阈值的最优：δ=0.961  acc=0.7667  F1=0.2222
                     （TP=2 FP=2 FN=12 TN=44）
```

两件事一起说明问题：

1. **`same` 对的距离比 `different` 对还远**（中位 1.0319 vs 0.9943）——序关系是**反的**；
2. 扫遍所有阈值，最优 F1 只有 **0.22**（口径要求 ≥0.80）。

根因查到了：**demo 库的关键词嵌入是随机向量**。任取 40 个词两两算距离：

```
n=780  均值=1.0001  标准差=0.0314  min=0.8974  max=1.0938
```

1024 维随机向量两两近似正交，余弦距离恰好聚在 1.0 附近——这就是它的特征。
**在这种分数上定出来的 δ 是噪声**，不是标定值。

## θ_rel：金标形状不对，不是数量不够

`flint/retrieval/relevance.py` 里 θ_rel 判的是 `hit_rate`——
**一个查询的 top-k 里被判相关的比例**。而 CAL-01 的 `relevance` 金标是**逐对**的
（这个候选与这个簇相关吗）。

要标定 θ_rel，需要的是「每个查询的 hit_rate + 这次检索该不该被接受」的成对真值；
逐对标注**再多也换不出**那个真值——它回答的是另一个问题。
这一条**不是靠加样本能解决的**，要么换标注面（按查询标），要么承认它是产品决策
（「top-k 里多少算够」本来就带策略成分）。

## hotness：没有真值就没有「最优」

`harness/tune_hotness.py` 一直是 report_only，CAL-01 也没采热度面的标注。
**没有金标序列时，任何「调优」都只是换一组数看排序变没变。**

## 血缘：对照 S4 的 ≥90%/50 簇

CAL-01 实测 **60/60 簇 correct（=1.00）**，簇数 60 ≥ 50。数字上过线。

**但这个 100% 不能拿去对线**：那批语料里**一次簇漂移都没有**
（每条 `continued` 事件两天挂的关键词逐字相同），
所以标注**判不出错**——判不出错不等于没错。
